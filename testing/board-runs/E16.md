# Board run: E16 GPU kernel ops on V3D

Status: partly run on CM5 2026-11-10 (every kernel op matches its reference on V3D; timings not taken).

## Check

Build from NVMe, never from the HDD.

- `DAEDALUS_GPU_REQUIRED=1 cargo test -p daedalus-wgpu --test kernels -- --nocapture`. Every op
  has to match the reference there too: a mismatch on V3D is a finding, record the op and the
  first differing offset.
- Each op at 4 MiB of input, timed from `Kernels::run` to its ticket done (`Ticket::gpu_time`
  where the device writes timestamps), against the CPU kernel of the same name from
  `daedalus-kernels-sys` on the same bytes: f32 from LE, f16 to f32, f32 to unorm8, copy (the
  shader and `copy_with_engine`), hex, base64 encode, base64 decode, CRC-32. `dev` recorded
  0.005 to 0.2 ms on an RTX against 0.2 to 10 ms on its CPU. There are no CM5 figures: record
  them fresh, with which side wins for each op.
- The chain `HALF_TO_F32` then `F32_TO_UNORM8` through `merge::chain_shader` at 1 M values,
  against the two ops run one after the other.

## Result


Run on 2026-11-10 on the CM5 (raze2): OS image 2026.2.0-dev.993+e1097ec7, kernel 7.2.9-v8-16k, aarch64, 4 cores, 4 GB RAM. V3D 7.1.10.2 through the Broadcom ICD (Vulkan 1.3.354, driver 26.1.8), `/dev/dri/renderD128`. Tested commit: `next` at bdbfe947.

Method: the test binaries were built with `cargo test --release --no-run --target aarch64-unknown-linux-gnu -p <crate>` on NVMe, copied to `/tmp/daedalus-next/bin` on the board, and run as `DAEDALUS_GPU_REQUIRED=1 flock /run/lock/raze-gpu.lock ./<binary> --nocapture --test-threads=1`, with `DAEDALUS_DMA_HEAP_REQUIRED=1` where the variable is named below. Logs are on the board under `/tmp/daedalus-next/logs`.

- `wgpu-kernels` (`DAEDALUS_GPU_REQUIRED=1`): 7 of 7 pass: `a_chain_of_two_per_pixel_kernels_is_one_shader`, `copy_and_codec_kernels_match_the_references`, `copy_engine_copies_gpu_resident_bytes`, `float_kernels_match_the_references`, `gpu_base64_decode_reports_length_and_errors`, `gpu_crc32_matches_the_reference`, `two_ops_in_one_encoder_each_see_their_own_counts`. No op mismatched its reference on V3D.
- Not run: each op at 4 MiB timed from `Kernels::run` to its ticket, against the CPU kernel on the same bytes, and the `HALF_TO_F32` then `F32_TO_UNORM8` chain at 1 M values through `merge::chain_shader` against the two ops run one after the other. This branch has no harness for these timings, and there is no CM5 figure in this run. Writing one is new code, so it was not written.

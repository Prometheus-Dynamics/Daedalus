# Board run: E11 real device loss on V3D

Status: re-run 2026-11-11 on CM5 (raze2) at `next` 6245c925: the loss test passes on V3D. The real timeout (the `grind` shader past the 5 s bound) was not induced: no harness on `next` runs it.

## Check

Build from NVMe, never from the HDD.

- `DAEDALUS_GPU_REQUIRED=1 cargo test -p daedalus-wgpu --test region`: the loss test, which marks
  a live device lost, has to pass on V3D as it does elsewhere.
- Induce a real timeout: run a region whose shader loops long enough to pass the 5 s wait bound
  (the `grind` shader of `fence_tests.rs` with a large `rounds`), and wait on its ticket.
  Expect: the wait fails as a timeout, the device is marked lost, the region's next run faults,
  the backend opens a new device, and the run after that is correct.
- Record what the driver does: whether its own lost callback fires, what message it gives,
  whether the old device's work ever finishes, and how long the reopen takes.

## Result


Run on 2026-11-10 on the CM5 (raze2): OS image 2026.2.0-dev.993+e1097ec7, kernel 7.2.9-v8-16k, aarch64, 4 cores, 4 GB RAM. V3D 7.1.10.2 through the Broadcom ICD (Vulkan 1.3.354, driver 26.1.8), `/dev/dri/renderD128`. Tested commit: `next` at bdbfe947.

Method: the test binaries were built with `cargo test --release --no-run --target aarch64-unknown-linux-gnu -p <crate>` on NVMe, copied to `/tmp/daedalus-next/bin` on the board, and run as `DAEDALUS_GPU_REQUIRED=1 flock /run/lock/raze-gpu.lock ./<binary> --nocapture --test-threads=1`, with `DAEDALUS_DMA_HEAP_REQUIRED=1` where the variable is named below. Logs are on the board under `/tmp/daedalus-next/logs`.

- `wgpu-region`, `a_lost_device_faults_the_region_then_is_reopened_and_the_region_runs_again`: pass on V3D. The loss test, which marks a live device lost, passes here as it does elsewhere.
- `wgpu-lib`, `fence_tests::a_wait_that_outlives_its_bound_fails_and_marks_the_device_lost`: pass. This test drives the timeout directly through `context.timed_out`, as its own comment says. It waits on no long shader, so it is not the real timeout the procedure asks for.
- Not run: the induced real timeout (a region whose shader runs past the 5 s wait bound, waited on through its ticket, then the next run faulting and the backend reopening the device). The `grind` shader lives in `backends/wgpu/src/fence_tests.rs`, private to that module, and no runnable test drives it through a region. Writing that driver is new code, so it was not written. For that reason the driver's lost callback, its message, whether the old device's work finishes, and the reopen time are not recorded.

## Result, 2026-11-11

Commit `6245c925`, raze2 (CM5, V3D 7.1.10.2). `DAEDALUS_GPU_REQUIRED=1 ./region --nocapture a_lost_device_faults_the_region_then_is_reopened_and_the_region_runs_again`: 1 passed.

Not run: the induced timeout, which would need the `grind` shader of `fence_tests.rs` with a large `rounds`, waited on by a driver. Nothing on `next` makes that run, so the driver's own lost callback, its message, and the reopen time were not recorded.

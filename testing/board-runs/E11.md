# Board run: E11 real device loss on V3D

Status: untested on board. Run by a local session on the CM5 (Raze, V3D), only on the maintainer's
word. Nobody has verified real device loss on hardware, on `dev` or on `next`.

## Check

Build from NVMe, never from the HDD.

- `DAEDALUS_GPU_REQUIRED=1 cargo test -p daedalus-wgpu --test region`: the loss test, which marks
  a live device lost, has to pass on V3D as it does elsewhere.
- Induce a real timeout: run a region whose shader loops long enough to pass the 5 s wait bound
  (the `grind` shader of `fence_tests.rs` with a large `rounds`), and wait on its ticket.
  Expect: the wait fails as a timeout, the device is marked lost, the region's next run faults,
  the backend opens a new device, and the run after that is correct.
- Record what the driver does: whether its own lost callback fires, what message it gives,
  whether the old device's work ever finishes, and how long the reopen takes.

# Board run: G4 process backend (one-node round trip through the fixture worker)

Status: run on CM5 2026-11-11 with the driver `testing/crates/process-timings` (added on next, PR #212). Tested commit: `next` at 6245c925. The dev half is not run: dev's `ffi_overhead` bench is not built on next.

## Check

- Build the driver and the worker from NVMe, with `CARGO_TARGET_DIR` on `/mnt/nvme-wd`, in release:
  `cargo build --release --target aarch64-unknown-linux-gnu -p daedalus-process-timings -p daedalus-worker-fixture`.
- Copy `target/aarch64-unknown-linux-gnu/release/daedalus-process-timings` and `daedalus-worker-fixture`
  to a directory of your own on the board, and run
  `flock /run/lock/raze-gpu.lock ./daedalus-process-timings ./daedalus-worker-fixture 101`.
  It compiles `fixture.scalar_add` (two `i64` inputs, one output) as a one-node region on
  `ProcessBackend`, warms up, times 101 batches of 1,000 round trips, and counts the allocations of
  200 more runs on its thread.
- Compare with dev's `crates/ffi/host/benches/ffi_overhead.rs` on `origin/dev`, on the same board and payload size.

## Record

- Median one-node round trip, CM5, next and dev, in ns.
- Steady-state allocations on the host thread (must be zero: `backends/process/tests/alloc.rs`).
- Any regression needs a reason in the PR.

## Build

Build on NVMe only, never on the Github HDD. Use `CARGO_TARGET_DIR` on `/mnt/nvme-wd`.

# Board run: D16 CRC-32 NEON32 folding against slice-by-8

Status: not run: needs a Luckfox Pico Pro (RV1106, Cortex-A7 with NEON).

## Check

- Build the benchmark on the board from NVMe, never from the HDD. Use a release build with
  `RUSTFLAGS="-C target-feature=+neon"` for the `armv7-unknown-linux-gnueabihf` target.
- Time `crc32::run(Isa::Neon32, buf)` (the `vmull.p8` folding) against `crc32::run(Isa::Scalar,
  buf)` (slice-by-8) on a 64 KiB buffer. Repeat each path until the total exceeds one second,
  and report the median per call.
- Check each result against `reference::crc32` on the same buffer before timing.

## Decision

- Change the ARMv7 default in `crc32()` (backends/kernels-sys/src/crc.rs) to the NEON path only if
  its median is faster than slice-by-8 on the same buffer.
- Until this run is recorded here, the ARMv7 default stays slice-by-8.

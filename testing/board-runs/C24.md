# Board run: C24 tick-path overhead

Status: run on CM5 2026-11-10 (probe off and on, and the window overhead, taken with `cpu-timings`).

## Check

- The tick-path overhead of a 16-stage chain with `TickProbe` off and on, against `dev`'s tick overhead numbers.
- With the probe off the run path adds one `None` check per step, so the overhead with it off must match C1's per-stage figures.
- Record the per-tick `overhead_ns` from `TickOverheadWindow::report` next to the probe-off time per tick.

## Result


Run on 2026-11-10 on the CM5 (raze2): OS image 2026.2.0-dev.993+e1097ec7, kernel 7.2.9-v8-16k, aarch64. Tested commit: `next` at bdbfe947.

## Timings (cpu-timings, 2026-11-10)

Board: CM5 (raze2), kernel 7.2.9-v8-16k, aarch64, 4 cores, CPU governor `performance`. Built on
NVMe with `CARGO_TARGET_AARCH64_UNKNOWN_LINUX_GNU_LINKER` and `CC_aarch64_unknown_linux_gnu` set to
`/mnt/nvme-wd/scratch/zigcc/aarch64-cc`, as `cargo build --release --target aarch64-unknown-linux-gnu -p
daedalus-cpu-timings`. Copied to a directory of mine under `/tmp` on the board, run there, and removed
afterwards. Each section prints the median of 101 batches of 1,000 calls, after 20 warm batches; the
times are per call, in ns.

Commands: `daedalus-cpu-timings probe_off` and `daedalus-cpu-timings probe_on`, three runs each. The
workload is C1's 16-stage unfused chain (`budget_harness::chain(16, Stage::Plain, false)`, one feed
and one take a tick). The probe is attached to the host's runner with `set_probe`. The window
(`TickOverheadWindow`, 1,000 ticks) records every tick, and its figures are for the last batch.

| Row | run 1 | run 2 | run 3 | median of runs |
|---|---|---|---|---|
| Tick, probe off, ns | 1,868.9 | 1,866.6 | 1,866.0 | 1,866.6 |
| Tick, probe off, per stage, ns | 116.8 | 116.7 | 116.6 | 116.7 |
| Tick, probe on, ns (includes recording the window) | 3,478.8 | 3,518.8 | 3,499.7 | 3,499.7 |
| Window p50 tick, ns | 3,148 | 3,167 | 3,185 | 3,167 |
| Window mean `overhead_ns` (tick outside the bodies), ns | 2,238.4 | 2,245.3 | 2,320.4 | 2,245.3 |

Reference, C1: the unfused chain measured 1,842.8 ns a tick and 115.2 ns per stage on this board
(`testing/board-runs/C1.md`). The probe-off figure matches it to within 2%, so the run path with
the probe off costs what C1 measured.

The probe on adds about 1.6 µs a tick to this chain, which is about 100 ns per stage. The window's
`overhead_ns` is about 140 ns a stage. Most of it is the two clock reads a step takes when a probe
is attached. There is no dev figure for probe overhead to set beside it: `docs/benchmarks-log.md`
has whole-graph `graph_overhead` figures, and they include the host's own work, not the probe's.
So the probe-on figures are recorded and not compared with dev.

# Board run: E15 images into storage and sampled textures on V3D

Status: untested on board. Run by a local session on the CM5 (Raze, V3D), only on the maintainer's
word.

## Check

Build from NVMe, never from the HDD.

- `DAEDALUS_GPU_REQUIRED=1 DAEDALUS_DMA_HEAP_REQUIRED=1 cargo test -p daedalus-wgpu --test image
  --test import --test region -- --nocapture`, and `cargo test -p daedalus-wgpu-author --test
  pixel`. Record any refusal with its message.
- The cost of an import that is found in the cache (`import_storage` on a buffer already
  imported). `dev` measured 16 to 29 µs per image. Record it, and `storage_import_stats`.
- The direct copy (`ImageCopy`, plan `Direct`) at 640x480 XRGB and at 1280x720. `dev` measured
  0.49 ms and 0.71 ms with the TFU, against 2.9 ms and 8.6 ms for a shader copy. A time near the
  shader's means the TFU wasn't taken: record which.
- GREY at 640x480: the folded copy with a 640-byte stride (plan `Folded { rows: 2 }`, `dev`
  0.43 ms) and the direct copy with a 768-byte stride (`dev` 0.27 ms). Then a stride nothing
  folds, row by row (`dev` 21 ms).
- A buffer allocated with no slack past its last plane is refused with the size it needs.
- A pixel chain of four fed an imported camera texture: one render pass, and its time against
  the same chain fed a buffer (the compute form). `dev` found compute much the slower on V3D.

## Check

Command: `cargo run --release -p daedalus-gpu-budgets -- raw-submit fragment-pass`. `raw-submit` prints the record and submit of one dispatch on the wgpu path and on a raw Vulkan chain, each as the median of 200 after 20. `fragment-pass` prints one tap pass on r8 at 1280x800, as the median of 200 after 20. The box 3x3 and box 5x5 timings and the hand-written comparator below are not in the tool: Daedalus has no pixel code, so they are not measured here.

Build from NVMe, never from the HDD.

- `DAEDALUS_GPU_REQUIRED=1 cargo test -p daedalus-wgpu --test fragment --test region` and
  `cargo test -p daedalus-vk-sys`: all have to pass, and `a_raw_kernel_reads_8_bit_storage` has to
  run its body on V3D, which has the feature (it skips a device without it).
- Time, as the median of 200 after 20 warm-up runs, on r8 at 1280x800: a `FragmentPass` box 3x3
  (`dev` 2.83 ms, against 2.84 ms hand-written) and a box 5x5 (`dev` 7.05 ms).
- Time a raw submitter's record and submit of one dispatch (`dev` 23.3 µs).
- With the Vulkan validation layer and synchronization validation on, record every message the
  fragment and raw tests produce.

## Result


Run on 2026-11-10 on the CM5 (raze2): OS image 2026.2.0-dev.993+e1097ec7, kernel 7.2.9-v8-16k, aarch64, 4 cores, 4 GB RAM. V3D 7.1.10.2 through the Broadcom ICD (Vulkan 1.3.354, driver 26.1.8), `/dev/dri/renderD128`. Tested commit: `next` at bdbfe947.

Method: the test binaries were built with `cargo test --release --no-run --target aarch64-unknown-linux-gnu -p <crate>` on NVMe, copied to `/tmp/daedalus-next/bin` on the board, and run as `DAEDALUS_GPU_REQUIRED=1 flock /run/lock/raze-gpu.lock ./<binary> --nocapture --test-threads=1`, with `DAEDALUS_DMA_HEAP_REQUIRED=1` where the variable is named below. Logs are on the board under `/tmp/daedalus-next/logs`.

- `wgpu-fragment`: 5 of 5 pass.
- `vk-sys-lib` (the `daedalus-vk-sys` unit tests): 11 of 11 pass, including `a_raw_kernel_reads_8_bit_storage`. The device reports `storageBuffer8BitAccess` and `uniformAndStorageBuffer8BitAccess` as true (`vulkaninfo`). The test skips only when that feature is missing, so its body ran.
- `wgpu-region`: see E5 (one failure there, not a fragment result).
- Not run: the timings of the 3x3 box and 5x5 box `FragmentPass` on r8 at 1280x800, the hand-written 3x3, and the raw submitter's record and submit of one dispatch (median of 200 after 20 warm-up runs). This branch has no harness for them; writing one is new code, so it was not written. dev's 2.83 ms, 7.05 ms and 23.3 us were not compared.
- Not run: the Vulkan validation layer, with synchronization validation. The board has no validation layer: `vulkaninfo` lists no instance layers, and the procedure's messages cannot be produced here.

## Result, 2026-11-16 (batched session)

Run at `next` 748ef3cc on the CM5. Each timing is the median of three rounds, each the median of 200 after
20 warm-up runs.

- Fragment tests (`DAEDALUS_GPU_REQUIRED=1`, one run): 5 of 5 pass.
- Raw Vulkan tests (`vk-sys` unit tests, one run): 16 of 16 pass, including `a_raw_kernel_reads_8_bit_storage`.
  The test passes. The files do not show whether its body ran, because the device's feature list is not in
  this session's output.
- `fragment-pass`, one tap pass on r8 at 1280x800: 0.836 ms (rounds 0.836, 0.834 and 0.839 ms).
- `raw-submit`, one dispatch, record and submit, no wait: 30.2 µs on the wgpu path; 12.7 µs on the raw
  Vulkan chain (rounds 12.5, 13.5 and 12.7 µs). The reference's raw submitter is 23.3 µs, so the raw path
  is below it.
- Subject gone: the box 3x3 and 5x5 timings and the hand-written comparator. The pixel vocabulary was removed in f6513089 (#226), and no box pass is in the tree. They will not be taken.

Validation (the Khronos validation layer from the bundle, with synchronization validation requested through
its environment variables). The layer printed messages, so it was loaded. The run is not clean.

- Fragment tests: 14 validation errors, all `VUID-StandaloneSpirv-None-10684` from `vkCreateShaderModule`
  (spirv-val: "Invalid explicit layout decorations on type" for a function-local array of `v2uint`). By test:
  `every_target_format_renders_and_reads_back` 9, `invalid_passes_are_reported` 2,
  `a_binding_is_reused_across_encodes` 1, `pass_reads_inputs_at_its_own_texel` 1 and
  `rects_draw_only_their_texels` 1. All five tests still pass.
- `fragment-pass` step: 1 of the same error.
- No validation warnings, performance messages or synchronization messages in any validation file. The
  files show the variables were set. They do not show whether synchronization validation took effect, so
  neither active nor inactive is shown.
- `vk-sys` and `region` validation runs printed no messages.
- Cause, as traced (not re-run here): all 14 are on the vertex stage of every fragment pass, in `backends/wgpu/src/fragment.rs`, where a function-local `array<vec2<u32>, 6>` holds the corners. The newer validation layer on the board rejects that form (VUID-StandaloneSpirv-None-10684). The shader was changed in the same PR as this record: the corners are now computed from the vertex index, with no local array. That change was checked on lavapipe. It has not been re-run on V3D under the layer.
- The timings in the validation run (fragment pass 1.016 ms; raw submit 0.102 ms on the wgpu path and
  0.065 ms on the raw path) are with the layer on. They are not performance figures.

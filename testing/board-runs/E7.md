# Board run: E7 fragment passes and raw submits on V3D

Status: partly run on CM5 2026-11-10 (fragment and raw tests pass; timings and validation not run).

## Check

Build from NVMe, never from the HDD.

- `DAEDALUS_GPU_REQUIRED=1 cargo test -p daedalus-wgpu --test fragment --test region` and
  `cargo test -p daedalus-vk-sys`: all have to pass, and `a_raw_kernel_reads_8_bit_storage` has to
  run its body on V3D, which has the feature (it skips a device without it).
- Time, as the median of 200 after 20 warm-up runs, on r8 at 1280x800: a `FragmentPass` box 3x3
  (`dev` 2.83 ms, against 2.84 ms hand-written) and a box 5x5 (`dev` 7.05 ms).
- Time a raw submitter's record and submit of one dispatch (`dev` 23.3 µs).
- With the Vulkan validation layer and synchronization validation on, record every message the
  fragment and raw tests produce.

## Result


Run on 2026-11-10 on the CM5 (raze2): OS image 2026.2.0-dev.993+e1097ec7, kernel 7.2.9-v8-16k, aarch64, 4 cores, 4 GB RAM. V3D 7.1.10.2 through the Broadcom ICD (Vulkan 1.3.354, driver 26.1.8), `/dev/dri/renderD128`. Tested commit: `next` at bdbfe947.

Method: the test binaries were built with `cargo test --release --no-run --target aarch64-unknown-linux-gnu -p <crate>` on NVMe, copied to `/tmp/daedalus-next/bin` on the board, and run as `DAEDALUS_GPU_REQUIRED=1 flock /run/lock/raze-gpu.lock ./<binary> --nocapture --test-threads=1`, with `DAEDALUS_DMA_HEAP_REQUIRED=1` where the variable is named below. Logs are on the board under `/tmp/daedalus-next/logs`.

- `wgpu-fragment`: 5 of 5 pass.
- `vk-sys-lib` (the `daedalus-vk-sys` unit tests): 11 of 11 pass, including `a_raw_kernel_reads_8_bit_storage`. The device reports `storageBuffer8BitAccess` and `uniformAndStorageBuffer8BitAccess` as true (`vulkaninfo`). The test skips only when that feature is missing, so its body ran.
- `wgpu-region`: see E5 (one failure there, not a fragment result).
- Not run: the timings of the 3x3 box and 5x5 box `FragmentPass` on r8 at 1280x800, the hand-written 3x3, and the raw submitter's record and submit of one dispatch (median of 200 after 20 warm-up runs). This branch has no harness for them; writing one is new code, so it was not written. dev's 2.83 ms, 7.05 ms and 23.3 us were not compared.
- Not run: the Vulkan validation layer, with synchronization validation. The board has no validation layer: `vulkaninfo` lists no instance layers, and the procedure's messages cannot be produced here.

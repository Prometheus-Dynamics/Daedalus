# Board run: E8 fence polls on V3D

Status: partly run on CM5 2026-11-10 (fence tests pass; poll and busy timings not taken).

## Check

Build from NVMe, never from the HDD.

- `DAEDALUS_GPU_REQUIRED=1 cargo test -p daedalus-wgpu --lib fence_tests`: all five have to pass.
  Record which time source `timers_report_gpu_time_per_pass` reports on V3D.
- Time `Ticket::is_done` on a submission that has finished, as the median of 10,000 calls. `dev`
  measured about 0.3 µs for the same poll.
- Time a `Run::Busy` answer, which is what a step pays when the device is full.

## Result


Run on 2026-11-10 on the CM5 (raze2): OS image 2026.2.0-dev.993+e1097ec7, kernel 7.2.9-v8-16k, aarch64, 4 cores, 4 GB RAM. V3D 7.1.10.2 through the Broadcom ICD (Vulkan 1.3.354, driver 26.1.8), `/dev/dri/renderD128`. Tested commit: `next` at bdbfe947.

Method: the test binaries were built with `cargo test --release --no-run --target aarch64-unknown-linux-gnu -p <crate>` on NVMe, copied to `/tmp/daedalus-next/bin` on the board, and run as `DAEDALUS_GPU_REQUIRED=1 flock /run/lock/raze-gpu.lock ./<binary> --nocapture --test-threads=1`, with `DAEDALUS_DMA_HEAP_REQUIRED=1` where the variable is named below. Logs are on the board under `/tmp/daedalus-next/logs`.

- `wgpu-lib` with the filter `fence_tests` (`DAEDALUS_GPU_REQUIRED=1`): 5 of 5 pass: `a_fence_resolves_once_and_is_then_forgotten`, `a_wait_that_outlives_its_bound_fails_and_marks_the_device_lost`, `tickets_complete_without_waiting_and_in_flight_is_bounded`, `timers_report_gpu_time_per_pass`, `uncaptured_errors_fail_the_next_run_once`.
- Which time source `timers_report_gpu_time_per_pass` reports is not printed by the test. The device supports timestamps (`timestamps: true` in the limits from E1), so the timestamp source is the one available here.
- Not run: the median of 10,000 calls to `Ticket::is_done` on a finished submission (dev about 0.3 us), and the time of a `Run::Busy` answer. This branch has no harness for them; writing one is new code, so it was not written.

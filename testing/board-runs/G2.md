# Board run: G2 dylib loader (one node tick, fixture against dev)

Status: untested on board. Run by a local session on the CM5 after G2 merges.

## Check

- Build `testing/fixtures/dylib` as a cdylib with `CARGO_TARGET_DIR` on NVMe only, with
  `cargo build --release --manifest-path testing/fixtures/dylib/Cargo.toml`.
- Open it through `daedalus_loader::Loader::open`, compile the `fixture.pass` node with the
  `fixture.cpu` backend, and run its step in a loop with one `u32` payload in the input cell.
- Compare with dev's stable tick on the same board: `crates/daedalus/examples/plugins/stable_abi`
  and the `dev` stable bench, on the same payload size.

## Record

- Median tick time for the `fixture.pass` step, CM5, next and dev, in ns.
- Whether the warm tick allocates (it must not: `core/loader/tests/alloc.rs` proves it on the host).
- Any regression needs a reason in the PR.

## Build

Build on NVMe only, never on the Github HDD. Use `CARGO_TARGET_DIR` on `/mnt/nvme-wd`.

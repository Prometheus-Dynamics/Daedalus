# Board run: G2 dylib loader (one node tick, fixture against dev)

Status: partly run on CM5 2026-11-10 (warm ticks and allocations taken through the budget harness; the dev run on this board was not done).

## Check

- Build `testing/fixtures/dylib` as a cdylib with `CARGO_TARGET_DIR` on NVMe only, with
  `cargo build --release --manifest-path testing/fixtures/dylib/Cargo.toml`.
- Open it through `daedalus_loader::Loader::open`, compile the `fixture.pass` node with the
  `fixture.cpu` backend, and run its step in a loop with one `u32` payload in the input cell.
- Compare with dev's stable tick on the same board: `crates/daedalus/examples/plugins/stable_abi`
  and the `dev` stable bench, on the same payload size.

## Record

- Median tick time for the `fixture.pass` step, CM5, next and dev, in ns.
- Whether the warm tick allocates (it must not: `core/loader/tests/alloc.rs` proves it on the host).
- Any regression needs a reason in the PR.

## Build

Build on NVMe only, never on the Github HDD. Use `CARGO_TARGET_DIR` on `/mnt/nvme-wd`.

## Result


Run on 2026-11-10 on the CM5 (raze2): OS image 2026.2.0-dev.993+e1097ec7, kernel 7.2.9-v8-16k, aarch64, 4 cores, CPU governor `performance` at 2.4 GHz. Tested commit: `next` at bdbfe947.

- Built the fixture with `cargo build --release --target aarch64-unknown-linux-gnu --manifest-path testing/fixtures/dylib/Cargo.toml` on NVMe (cdylib `libdaedalus_dylib_fixture.so`), copied it to the board.
- Run as `ex-daedalus-budget-harness plugin 2000000 ./libdaedalus_dylib_fixture.so`. The harness opens the library with `daedalus_loader::Loader::open` and ticks the `fixture.pass` node once per tick with one value in its input. Output: `plugin: 2000000 ticks, sum 1999999000000`, which is the sum of 0 to 1999999, so each value came back through the node.
- Wall time for those 2,000,000 ticks: 0.76 s from `/proc/uptime`, which has 10 ms resolution and includes starting the process. That is about 0.38 us per tick. It is an average over the run, not the median the procedure asks for.
- Allocations: `ex-daedalus-budget-harness plugin 1000 ./libdaedalus_dylib_fixture.so allocations` printed `alloc_plugin_node_tick 0`: a warm tick allocates nothing.
- Not run: the median tick time of `fixture.pass` from a criterion bench (this branch has no bench on the plugin path), and the `dev` stable bench on this board (`crates/daedalus/examples/plugins/stable_abi`), which was not built or run here. There is therefore no next-against-dev comparison on this board. The design's figure of about 3,100 instructions per tick is an x86 instruction count and is not comparable.

# I2: budget timings

Status: partly run on CM5 2026-11-10 (ticks, allocation rows and the V3D batching taken; the callgrind rows and the RX 6800 XT row not run).

The counted budgets are checked in CI (`testing/budgets/budgets.toml`). These are the timings
that go with them. Each result is one row: the board, the commit, the value, and the `dev` value.

The `dev` column is from `origin/dev`. Build on the board's NVMe, never on the HDD, in release:

```sh
cargo bench -p daedalus-budget-harness --bench ticks
```

## CM5

| Measure | How | `dev` |
|---|---|---|
| Per-stage overhead, unfused | `unfused_chain_16_tick` divided by 16 | 655 ns |
| Per-stage overhead, fused | `fused_chain_16_tick` divided by 16 | 498 ns |
| 16-stage idle tick, wall time | `idle_tick_16` | not recorded on `dev` |

Both chain figures include one feed and one take a tick, which `dev`'s per-stage figure does
not. Record the figure as measured, and beside it the same figure with the 1-stage chain's time
subtracted (`budget-harness chain` takes the stage count).

## Results


Run on 2026-11-10 on the CM5 (raze2): OS image 2026.2.0-dev.993+e1097ec7, kernel 7.2.9-v8-16k, aarch64, 4 cores, CPU governor `performance` at 2.4 GHz. Tested commit: `next` at bdbfe947.

Commands: `cargo bench --no-run --target aarch64-unknown-linux-gnu -p daedalus-budget-harness`, run on the board as `./ticks-bench --bench`; `ex-daedalus-budget-harness allocations`; `ex-daedalus-gpu-budgets batching` (three runs).

Each row below is one result. The per-stage rows are the C1 record's, with one feed and one take per tick included.

| Board | Commit | Measure | Value | `dev` |
|---|---|---|---|---|
| CM5 | bdbfe947 | Per-stage overhead, unfused: `unfused_chain_16_tick` / 16 | 115.2 ns | 655 ns |
| CM5 | bdbfe947 | Per-stage overhead, fused: `fused_chain_16_tick` / 16 | 67.1 ns | 498 ns |
| CM5 | bdbfe947 | Per-stage, unfused, 1-stage chain subtracted (wall time, 20,000,000 ticks, (t16 - t1) / 15) | 98.9 ns | not recorded |
| CM5 | bdbfe947 | 16-stage idle tick, wall time: `idle_tick_16` | 33.42 ns | not recorded on `dev` |
| CM5 | bdbfe947 | Detector mirror graph, per frame: `detector_frame` | 1.181 us | about 7 us |
| CM5 | bdbfe947 | 8 GPU ops, 8 submits (`daedalus-gpu-budgets batching`, V3D) | 3.128 ms | 1.30 ms |
| CM5 | bdbfe947 | 8 GPU ops, 1 submit (`daedalus-gpu-budgets batching`, V3D) | 2.890 ms | 1.32 ms |
| RX 6800 XT | not run | 8 ops, 8 submits and 1 submit | not run: not this board | 0.37 ms and 0.15 ms |

The two V3D rows miss `dev`: the one-submit figure is 2.2 times `dev`'s and the eight-submit figure is 2.4 times. Three runs agree within 2 percent, so the miss is not noise. It is not diagnosed.

Not run:

- The callgrind instruction rows, including the 16-stage idle tick in instructions (27,064 on `dev`). valgrind is not on the board.
- The RX 6800 XT rows: that is a different machine.
- `scripts/ci.sh budgets` on the CM5: the board has no cargo, and the script builds on the host.

Allocation rows, from `ex-daedalus-budget-harness allocations` (warm, per tick): `alloc_fused_tick` 0; `alloc_large_handle_tick` 0; `alloc_large_handle_moved_tick` 1; `alloc_detector_frame` 6; `alloc_handoff_handle_read_tick` 0; `alloc_handoff_handle_chain_tick` 8; `alloc_handoff_shared_read_tick` 0; `alloc_handoff_shared_chain_tick` 8; `alloc_handoff_vec_read_tick` 0; `alloc_handoff_vec_chain_tick` 16. The procedure does not give expected values for these, so none is judged here.

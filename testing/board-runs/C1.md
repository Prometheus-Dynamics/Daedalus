# Board run: C1 serial runner

Status: partly run on CM5 2026-11-10 (per-stage and idle timings taken; the dev run on this board was not done).

## Check

- Form: `Steps`. Plan: an unfused 16-stage chain of trivial bodies (each body copies its input
  slot to its output slot, as `core/runner/tests/support/mod.rs` `Link` does).
- Measure the per-stage cost: one tick that runs the whole chain, divided by 16, with the chain
  fed once per tick.
- Measure the idle-tick cost: a tick on the same plan with nothing fed.
- Compare with `dev`: 655 ns per stage unfused (`docs/benchmarks-log.md`), 27,064 instructions
  for an idle 16-step tick on x86.

## Record

- Per-stage ns, CM5, unfused, next and dev.
- Idle-tick cost, CM5, next and dev. Instruction counts are not in CI, so the x86 count belongs
  to I2.
- Any regression needs a reason in the PR.

## Build

Build on NVMe only, never on the Github HDD. Use `CARGO_TARGET_DIR` on `/mnt/nvme-wd`.

## Result


Run on 2026-11-10 on the CM5 (raze2): OS image 2026.2.0-dev.993+e1097ec7, kernel 7.2.9-v8-16k, aarch64, 4 cores, CPU governor `performance` at 2.4 GHz. Tested commit: `next` at bdbfe947.

Commands: `cargo bench --no-run --target aarch64-unknown-linux-gnu -p daedalus-budget-harness` for the release-profile bench, copied to the board and run as `./ticks-bench --bench` (criterion, default settings). The rows are the budget harness's, which I2 names for these figures. `unfused_chain_16_tick` is `chain(16, Plain, merge = false)`; each tick includes one feed and one take.

| Row | CM5, `next` | Per stage | `dev` |
|---|---|---|---|
| `unfused_chain_16_tick` | 1.8428 µs (range 1.8394 to 1.8461 µs) | 115.2 ns | 655 ns per stage |
| `idle_tick_16` | 33.42 ns (range 33.33 to 33.52 ns) | n/a | not recorded in ns on `dev` |

Per-stage from wall time (I2's subtraction): 20,000,000 ticks of the 16-stage unfused chain took 37.13 s and 37.14 s; 20,000,000 ticks of the 1-stage chain took 7.46 s and 7.47 s (`ex-daedalus-budget-harness chain 20000000 <stages> unfused`, timed with /proc/uptime). (t16 - t1) / 15 = 98.9 ns per stage.

Result: the unfused per-stage figure is 5.7 times below the 655 ns `dev` recorded on the CM5. `dev` was not re-run on this board, and the bench bodies here may not be the ones `dev` timed, so this is recorded, not read as a speedup. No regression against `dev` in the numbers measured. The instruction count (27,064 on x86) is not in this run: see I2 for why.

Not run: the `dev` side of this comparison on this board.

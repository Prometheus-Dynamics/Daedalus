# Board run: E6 merged pixel chains on V3D

Status: partly run on CM5 2026-11-10 (two pixel tests fail on V3D; timings not taken).

## Check

Build from NVMe, never from the HDD.

- `DAEDALUS_GPU_REQUIRED=1 cargo test -p daedalus-wgpu-author --test pixel`: all eight have to
  pass.
- Eight pixel nodes on 1280x800, as one merged fragment pass (`merge::fragment_pass`): time it as
  the median of 200 after 20 warm-up runs. It must be one submit and one pass, and cost no more
  than the single box 3x3 fragment pass (`dev` 2.83 ms) plus the arithmetic of the extra nodes.
- The same eight nodes as the merged compute form through a region, and as eight unmerged
  regions. Record all three numbers: `dev` measured storage-buffer compute at 36.4 ms against
  2.83 ms for the fragment pass on a box 3x3, which is why V3D is meant to get the fragment form.

## Result


Run on 2026-11-10 on the CM5 (raze2): OS image 2026.2.0-dev.993+e1097ec7, kernel 7.2.9-v8-16k, aarch64, 4 cores, 4 GB RAM. V3D 7.1.10.2 through the Broadcom ICD (Vulkan 1.3.354, driver 26.1.8), `/dev/dri/renderD128`. Tested commit: `next` at bdbfe947.

Method: the test binaries were built with `cargo test --release --no-run --target aarch64-unknown-linux-gnu -p <crate>` on NVMe, copied to `/tmp/daedalus-next/bin` on the board, and run as `DAEDALUS_GPU_REQUIRED=1 flock /run/lock/raze-gpu.lock ./<binary> --nocapture --test-threads=1`, with `DAEDALUS_DMA_HEAP_REQUIRED=1` where the variable is named below. Logs are on the board under `/tmp/daedalus-next/logs`.

- `author-pixel` (`cargo test -p daedalus-wgpu-author --test pixel`): 7 of 9 pass. The procedure names eight tests; this branch has nine.
  - Pass: `a_chain_of_four_is_one_pass_and_equals_the_nodes_run_one_at_a_time`, `a_long_chain_is_cut_into_pieces_that_each_fit_any_device`, `a_node_that_reads_its_neighbour_cuts_the_chain_around_it`, `a_second_consumer_ends_the_chain`, `the_chain_key_is_pinned`, `the_fragment_form_gives_what_the_compute_form_gives`, `the_record_holds_the_function_and_what_it_takes`.

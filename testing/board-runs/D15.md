## Result


Run on 2026-11-10 on the CM5 (raze2): OS image 2026.2.0-dev.993+e1097ec7, kernel 7.2.9-v8-16k, aarch64, V3D through the Broadcom ICD. Tested commit: `next` at bdbfe947. Records carry `rev` bdbfe947, the commit tested, not the D15 PR's own commit.

Commands, on the board from `/tmp/daedalus-next/bin` with `ACCEL_RESULTS_DIR` set to a fresh directory, `ACCEL_TARGET=aarch64-unknown-linux-gnu`, `ACCEL_RUNNER=raze-cm5-v3d`, `ACCEL_REV=bdbfe947`: `kernels-conformance`, `kernels-crc` and `kernels-lib` (the test binaries of `daedalus-kernels-sys`), each with `--nocapture --test-threads=1`. `ACCEL_DUMP=<file> inventory-registry registry_dump` wrote the CPU registry dump.

Results: `kernels-conformance` 5 of 5 pass; `kernels-crc` 4 of 4 pass; `kernels-lib` 1 of 1 pass. `inventory-registry`: `registry_dump` passes; `registry_rows_point_at_existing_files_and_tests` fails on the board with `missing source backends/kernels-sys/src/reference.rs`. That test checks source paths in the repository tree, which the board does not have, so it cannot run on the board as written. That is not a kernel result.

neon64 records, now in `testing/board-runs/accel/raze-cm5-neon64.jsonl` (8 rows, all `pass`):

- `daedalus.copy.bytes`, `daedalus.codec.hex_lower`, `daedalus.codec.base64_encode`, `daedalus.codec.base64_decode`, `daedalus.float.f32_from_le`, `daedalus.float.f16_to_f32`, `daedalus.float.f32_to_unorm8`: pass.
- `daedalus.codec.crc32` with extension `crc`: pass.

The file held 12 neon64 rows from `dev` (rev 6a0c73f). Four of them are `daedalus.pixel.gray_to_rgba`, `rgba_red`, `rgba_to_rgb` and `rgb_to_rgba`. Those ops are not in `next`'s kernels, so they could not be re-recorded and are not in the new file. Every neon64 cell that `docs/backend-matrix.csv` marks pass has a passing record here: the eight ops listed above.

Matrix re-render: `scripts/accel.sh render --registry <the board's CPU dump> --results testing/board-runs/accel --baseline docs/backend-matrix.csv --scan . --out <scratch>` exits 1 with 31 regression errors, all in scalar, portable_simd and x86 cells (for example `daedalus.float.f32_from_le on scalar: pass -> untested`). No neon64 cell regressed. The render needs the full CI evidence set and every target's registry dump, which this run does not have, so `docs/backend-matrix.csv` was not regenerated and is unchanged in this PR. The re-render belongs to the CI accel lane.

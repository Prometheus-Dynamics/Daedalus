# Board run: E9 dma-heap buffers on V3D

Status: partly run on CM5 2026-11-10 (dma-buf tests pass; the dma-heap storage test fails on V3D; timings not taken).

## Check

Build from NVMe, never from the HDD.

- `cargo test -p daedalus-dma-sys -- --nocapture`: nothing may print `skipped`.
- `DAEDALUS_GPU_REQUIRED=1 DAEDALUS_DMA_HEAP_REQUIRED=1 cargo test -p daedalus-wgpu --test storage`:
  the dma-heap test has to run, and `Storage::new_host_cached` has to give a `wgpu.dmaheap`
  buffer, since V3D has no cached memory of its own.
- Time, as the median of 50: allocate, map and read back a 1 MiB and a 16 MiB dma-heap buffer,
  with `begin_cpu_access` and `end_cpu_access` around the read. `dev` measured 3.6 ms to read
  16 MiB from a dma-heap buffer against 13.1 ms from V3D's own host-visible memory. Record both.
- `export_fence` on a dma-buf that V3D has just written: record that the fence is a sync_file and
  how long it takes to signal.

## Result


Run on 2026-11-10 on the CM5 (raze2): OS image 2026.2.0-dev.993+e1097ec7, kernel 7.2.9-v8-16k, aarch64, 4 cores, 4 GB RAM. V3D 7.1.10.2 through the Broadcom ICD (Vulkan 1.3.354, driver 26.1.8), `/dev/dri/renderD128`. Tested commit: `next` at bdbfe947.

Method: the test binaries were built with `cargo test --release --no-run --target aarch64-unknown-linux-gnu -p <crate>` on NVMe, copied to `/tmp/daedalus-next/bin` on the board, and run as `DAEDALUS_GPU_REQUIRED=1 flock /run/lock/raze-gpu.lock ./<binary> --nocapture --test-threads=1`, with `DAEDALUS_DMA_HEAP_REQUIRED=1` where the variable is named below. Logs are on the board under `/tmp/daedalus-next/logs`.

- `dma-kernel` (`cargo test -p daedalus-dma-sys`): 4 of 4 pass: `a_heap_buffer_allocates_maps_and_syncs`, `a_pipe_is_not_a_fence_and_nothing_waits_on_it`, `an_idle_buffer_exports_a_fence_that_has_signaled`, `mmap_read_write_and_identity_on_a_plain_fd`. `dma-sys-lib`: 2 of 2 pass. No test printed `skipped`.
- `dmabuf-memory` (`cargo test -p daedalus-dmabuf`, with `DAEDALUS_DMA_HEAP_REQUIRED=1`): 17 of 17 pass, including `steady_state_reuse_allocates_nothing` and `the_pool_reuses_up_to_four_idle_blocks_and_drops_the_fifth`. `dmabuf-lib` has no tests. No test printed `skipped`.
- FAIL: `wgpu-storage` with `DAEDALUS_DMA_HEAP_REQUIRED=1`: `a_dma_heap_buffer_is_one_memory_for_the_host_and_the_device` at `storage.rs:243:23`, message `a dma-heap buffer: Vulkan: ERROR_INVALID_EXTERNAL_HANDLE` (see E2). The host-cached dma-heap buffer (`wgpu.dmaheap`) check was not reached.
- Not run: the median of 50 for allocating, mapping and reading back 1 MiB and 16 MiB dma-heap buffers with `begin_cpu_access` and `end_cpu_access` (dev 3.6 ms and 13.1 ms for 16 MiB), and the time for a sync_file fence exported from a dma-buf that V3D has just written. The test `an_idle_buffer_exports_a_fence_that_has_signaled` covers the idle case only. This branch has no harness for the timings; writing one is new code, so it was not written.

## Build

- A frame crosses the boundary as a repr(C) table of functions with a layout hash. The table has no allocation at the boundary. Each side releases what it retained exactly once.
- The accessor set of dev's v3 table is kept in shape: dimensions, fourcc, modifier, timestamp, sequence, residency, planes, colorimetry, and metadata as u64 and as bytes. Dev's v2 table, the v2 compat shim (compat.rs) and v1 are dropped: next has no older plugins to load.
- Layout hash: the mechanism (dev foreign.rs, FNV-1a over the whitespace-stripped signature, size and align) is not placed by the design. Use it from wherever A5 or G2 puts it, and do not copy it into interfaces/frame. The owner decides (see report).
- A frame handed back to the host is the host's own, with no copy. A frame dropped during a call is released once. A panic while a plugin holds a frame releases it (the boundary guards the panic).
- A held frame is released with its node. A reload carries or releases frames the old build held, per C10.
- A memfd frame crosses with its fd borrowed, not owned.
- Pin the v3 layout hash and table size in a test. Dev pins only v2 (tests_v3.rs:86-95), so v3 can change without a failure.

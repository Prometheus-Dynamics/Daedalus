## Build

- Dev has no merging. Each GPU node is one shader and one submit. This PR merges pixel chains, as the design's first GPU level requires.
- Pixel body: a node declared `backend = wgpu(pixel)` with one WGSL function `fn apply(c: T_in, cfg: Cfg) -> T_out`, and no other access to its input. wgpu-author (pixel.rs) renames every top-level name in the body with a prefix from the node id at expansion, so bodies concatenate without clashes. A body with neighbourhood reads, workgroup memory, barriers or atomics is not a pixel body and fails to expand.
- Merge rule (exact): a chain is n1..nk, k >= 2, in one region, with an edge from n(i-1) to n(i) that is an input of n(i). n(i) reads that input only at the same pixel. Every node in the chain is a pixel body. Output of n(i), for i < k, has exactly one consumer, which is n(i+1). A second consumer, inside or outside the region, ends the chain at n(i). The chain's type keys match: T_out of n(i) equals T_in of n(i+1). A conversion between them merges only when it is itself a pixel body.
- Side inputs: a node may take other inputs that it reads at the same pixel from their own buffers. Each one is a binding. Any other access makes the node not a pixel body.
- Bindings: the head's input is binding 0 and the tail's output is binding 1. Every node's config and its side inputs follow in chain order, with unique binding numbers. Each binding is counted against the limits below.
- Limits: a merged shader must fit the device's limits (E1: storage buffers and storage textures per stage, workgroup storage, invocations) and the portable floor WEBGPU_DEFAULTS. A chain that does not fit is split into the longest prefixes that fit, and each segment is its own shader. A single node that does not fit alone is refused, and the planner reassigns it.
- Generation at compile: compute form writes one `@compute` entry `main` with the head's workgroup size. It loads the input at the invocation's index, then applies each node in order (`let c1 = apply_1(c0, cfg_1);`), then stores the result. Intermediate values stay in registers. Nothing is written for intermediates.
- Fragment form for tile-based devices (profile flag from E1): one render pass per segment, with the same bodies and the pipeline builder from E7. Dev measured the fragment pass on V3D at 2.83 ms against 36.4 ms for storage-buffer compute (gpu-nodes.md, box 3x3 on 1280x800), so V3D takes the fragment form.
- Cache: key = stable hash (FNV-1a 64) over the ordered node ids, each body's source hash computed at expansion, the binding table, the workgroup size, the form, the output formats and the device key. Pipelines are cached per device with the dev limit of 128. Wgpu's pipeline cache file is written by the Host's schedule (C10), as dev does.
- Output: integer formats are bit-exact against the unmerged chain. Float formats match the unmerged chain within the tolerance dev's float kernel tests use.

## Proof

CI, lavapipe, both forms: a chain of 4 integer pixel nodes equals the unmerged chain bit-exact (new). A node that reads x+1 inside a chain splits it into two shaders (new). A node with a second consumer ends the chain (new). A 9-node chain where each node has one storage parameter splits into segments that each fit WEBGPU_DEFAULTS (new). Compiling the same chain twice creates one pipeline (counter). Golden key test for a fixed chain. Ported: every_target_format_renders_and_reads_back and pass_reads_inputs_at_its_own_pixel, now run on a merged fragment chain. A merged chain of two test per-pixel functions gives the same output as the two run separately.

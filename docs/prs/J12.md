## Build

- A producer that writes in a declared space (J6) and a consumer in the same region share the value: the consumer reads it in place and the plan lists no transfer, which is right. But the explanation said nothing, so a zero-copy read looked the same as a transfer that was missed. The explanation says where each edge's value is written and read, and whether it is read in place.
- When no transfer exists, the refusal named the consumer's input and the two spaces. It names the producer's output too.

## Proof

`examples/04_gpu/tests/dmabuf.rs`: for the value made in the dma-buf space, the edge to the CPU node beside its maker has no transfer, is written and read in `dmabuf`, and is marked read in place; the edge to the shader has its transfer, is read in `wgpu.buffer`, and is not. `testing/crates/planner/tests/b9_stitch.rs` and `backends/wgpu/tests/devices.rs`: the refusal carries `from_port`.

## Build

- crc32(bytes) and crc32_combine(crc_a, crc_b, len_b) (zlib's combine), the reflected IEEE polynomial 0xEDB88320. crc32 selects at run time (the CPU reports the feature): AArch64 CRC instructions, x86 PCLMULQDQ with SSE4.1, RVV Zvbc (detected through riscv_hwprobe), else slice-by-8.
- ARMv7: the default stays slice-by-8. The NEON vmull.p8 folding (Backend::Neon32 path) is conformance-tested under qemu only. Its default changes only after the board run below.
- crc32_combine stays for the GPU path (E12), which computes CRCs per chunk and joins them here.
- The host blob writer (D3) and the chip reader (D3, bitwise) must produce the same CRC. The bitwise CRC in core/plan (A10) is the reference.
- Dropped: nothing. The GPU crc32 shader stays in E.

## Proof

cargo test -p daedalus-kernels-sys --test crc: the scalar and each carried path agree on lengths 0, 1, 7, 31, 64, 129, 1000, 4099 and 65537; crc32_combine agrees with crc32 of the concatenation; folding_with_a_software_clmul_matches (crc.rs). Conformance evidence for each path is produced by D15's CI accel job.

## Board run

Written to `testing/board-runs/D16.md` and run later by a local session:

On the Luckfox Pico Pro (RV1106, Cortex-A7 with NEON): time the NEON32 vmull.p8 folding against slice-by-8 on a 64 KiB buffer, and change the crc32() ARMv7 default only if NEON is faster. Record in testing/board-runs/D16.md. Until then slice-by-8.

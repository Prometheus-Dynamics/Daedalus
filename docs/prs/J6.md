## Read on dev

- No dev file. Dev's dma-buf backend knew frames, and was removed in #194 with the image code. This is designed fresh: a location, and no type.

## Build

- A memory space named `dmabuf`, supplied by a backend that runs no nodes. Movers move opaque bytes plus a location: nothing here or below knows what the bytes mean, how they are laid out or who made them.
- A type's owner says its values are dma-bufs (`DmaBufBacked`: an fd and a length) and lists the type in the space. Listing gives the moves between the space and the host's memory for that type, as hand-overs with no copy.
- The wgpu backend imports from the space into a device buffer, with the import it already has from the host.
- A node puts a port in the space with `memory(port = "dmabuf")`.

## Proof

`backends/dmabuf/tests/space.rs`: the space and a type's two moves are listed once, a value is handed on as the same value, and a value with no dma-buf is refused on the way in. `examples/04_gpu/tests/dmabuf.rs`: a value a node makes in the space is imported by a shader from there, is handed to the host and uploaded on a device planned without dma-buf import, and a port in a space nobody supplies fails to plan.

## Status

Done.

- `daedalus-dmabuf` has `SPACE` (`"dmabuf"`), `DmaBufBacked` (moved here from the wgpu backend, which re-exports it) and `DmaBufMemory`, the backend. `DmaBufMemory::new().with::<T>()` lists `dmabuf.to_host:<key>` and `dmabuf.from_host:<key>`, both `Handoff`: the step moves the input cell's reference to the same `Arc` into the output cell. A value made in the space can have a reader inside its maker's region as well; the runner marks the cell of such a slot as lent, so taking from it gives another reference and leaves the slot's for the other reader. The way in faults on a value with no dma-buf.
- `WgpuBackend::with_dmabuf::<T>()` lists the import twice, from the host and from `dmabuf` (`wgpu.import.dmabuf:<key>`), offered only while the open device imports dma-bufs.
- **The planner now honours `memory(port = "space")`.** A9 settled the attribute and the registry carried it, but nothing read it: an output was always placed in its backend's own space. The router now places a port where its body says, for outputs and inputs, and refuses a space no backend supplies with `StitchError::UnknownSpace`. A space that a transfer only names doesn't count as supplied.
- Not built: a move from a device buffer back into the space. It needs a way to make a `T` from a dma-buf, which the type's owner would have to supply, and nothing asks for it yet. A device output the host reads is already placed in dma-heap memory and read in place.

## Build

- testing/capability-audit.md is a checklist: every capability dev has, grouped by area, one row each, with the PR that replaces it (a PR ID, or 'dropped: reason'). Every crate directory on dev is named at least once. The rows below are the content.
- Planning and graph model (crates/core, crates/registry, crates/planner, crates/macros): graph model and JSON -> A6; type keys and ids -> A4; registry and joining bodies -> A8; node groups and defaults -> B1; const inputs and config -> B3; conversions -> B4; rewrite hook (dev lowerings) -> B5; rates and ordering -> B6; plan hashing and schema drift guard -> B12; planner API -> B13; lint and explain -> B11; #[node] macro -> A9; macro UI tests -> A9.
- Solver and assignment: device assignment (crates/daedalus/tests/device_assignment.rs) -> B7; a region that is refused and reassigned -> B8.
- Runtime executor (crates/runtime): serial runner -> C1; fences and pending steps -> C2; host IO -> C3; rates, joins, backpressure, edge policies -> C4; parallel lanes -> C6; cancellation and progress -> C7; output reuse -> C8; state slots and config cache -> C9.
- Failure handling (crates/daedalus/tests/dylib_retry.rs, retry_by_value.rs, input_dropped.rs): failure rule -> C5; fault reports and manual unmerged mode -> C12; device loss -> E11.
- Engine and host (crates/engine, crates/host-wrapper, crates/daedalus/tests/it/host_*.rs): load, start, reload with state carried -> C10; the facade -> C14; host listener -> H3.
- Metrics and telemetry (runtime metrics feature, crates/bench-counters): telemetry -> C11; bench-counters -> I2 (board only, see its report).
- Values and recycling (crates/data, tests recycled_by_value.rs, recycled_identity.rs): values, slots, recycle pool -> A5.
- Transport and wire (crates/transport): values across the wire -> A5 and G1; the transport crate itself -> dropped (replaced by A5 and G1).
- Surface and host-wrapper shared mode (crates/surface, crates/host-wrapper) -> G10, G11.
- Frames (crates/daedalus/tests/dylib_frames.rs, frame-bench, plugin frames.rs): dropped, Daedalus has no frame type. A type's owner defines it. Moving large values -> A5, A14, E17; values owned across a plugin boundary -> G3; dma-buf into the GPU -> E14, E15; large-value overhead -> I3. Colorimetry and pixel conversions: dropped, they belong to whoever owns the type.
- Stable ABI and dylib plugins (crates/ffi, examples/plugins/stable_*, tests dylib_stable*.rs, dylib_export_macro.rs, dylib_external_types.rs): step ABI and handshake -> A3; loader -> G2; stable plugin path and codecs -> G3; reload race (dylib_reload_race.rs) -> G2; stable allocations -> I2.
- Node groups in plugins (crates/nodes, examples/plugins/node_groups*): node groups -> B1; plugin node groups -> G2. crates/nodes bundle starter and demo are dropped (examples replace them).
- Process workers and languages: dev has no process backend; Python, Node, Java, C/C++ and Rust SDKs -> G4 to G9.
- GPU (crates/gpu, tests gpu_*.rs): wgpu context and device choice -> E1; buffers, textures, pools -> E2; transfers -> E3; whole-shader nodes and WGSL inference -> E4; shared submit -> E5; per-pixel merge -> E6; recording code -> E7; fences and bounded waits -> E8; dma-buf -> E9; multi-device -> E10; the GPU fallback test (gpu_fallback.rs) -> E11 and E12; the Khronos validation layer -> E12; pi board tests -> board_run of E9.
- Kernels and accelerators (crates/accel, crates/accelerator, crates/kernels, crates/wgsl-infer): acceleration inventory and backend matrix -> D8; WGSL inference -> E4; the accelerator interface -> dropped (the Backend trait, A7, covers it; the NPU case is I1).
- CPU and chips (crates/mcu, examples/mcu_*): CPU backend -> D1; CPU merging -> D2; blob form -> D3; source form -> D4; chips and firmware API -> D5; scalars and wire on a chip -> D6; chip examples -> D7; no_std core -> C1 and A3 to A6.
- CUDA: dev's gpu-cuda feature and device_cuda.rs test have no successor. Dropped: there is no CUDA backend in the design.
- Lean preset (the lean-preset job): dropped (no presets; telemetry is one feature, tested by C11).
- Daemon (crates/daemon): daemon -> H4; control client -> H5; wire protocol -> H1; client -> H2; packaging -> H6.
- Examples and docs: examples/00 to 03 and 09 -> I4; examples/04_gpu (from 07_gpu) -> I8; examples/08_ffi -> G10 and G11; examples/plugins -> G2 and G3; examples/wasm_* -> D9; examples/surface_image -> dropped; docs/* -> I5.
- Gate and CI (scripts/*.sh, .github/workflows/*.yml): each ci.sh step and each CI job is mapped to its PR in the gate table.
- Benchmarks: bench.yml -> I2; frame-bench -> I2 and I3.

## Proof

scripts/check-capability-audit.sh fails when a row has neither a PR ID nor a 'dropped: reason', or names an ID with no brief in docs/prs/. A planted row with no PR fails the check. The check also fails when a crate directory on dev is named nowhere in the file (the list of crate directories is read from origin/dev at the audit's commit).

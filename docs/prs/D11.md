## Build

- The inventory types: Backend, Ext, Status (Implemented, Gap, Impossible, NotDataParallel, Deferred, each with a reason), Op, CallSite, Kernel, Exempt and Registry. Kept as on dev, with these removals: the Backend::FixedFunction variant, the fixed_function column, Op::only_on, and any reason text that names Lemnos or RGA.
- conform(op, backend, || kernel == scalar) and conform_with (std). With ACCEL_RESULTS_DIR set, each check appends one JSON line: op, backend, variant, adapter, target (ACCEL_TARGET), runner (ACCEL_RUNNER), RVV vlen (read from vlenb), rev (the commit, from ACCEL_REV, which CI sets, or `unknown`) and result. A backend the process cannot run is skipped (ARMv7 NEON and RVV count only when compiled in).
- dump writes the registry as JSON for the renderer (D14).
- Cargo.toml declares features std (off by default) and generator (off by default). lib.rs declares pub mod matrix behind generator; D14 adds the matrix files and sets the bin's required-features to generator.
- The crate has no dependencies of its own. It is a testing crate: nothing in core/ or backends/ depends on it except as a dev-dependency.
- The crate's path is testing/crates/accel, under the design's testing/crates folder.

## Proof

cargo test -p daedalus-accel builds with and without std. A unit test checks that every Status variant has a reason, and that conform records a JSON line with ACCEL_RESULTS_DIR set and skips an unavailable backend. cargo check -p daedalus-accel --no-default-features.

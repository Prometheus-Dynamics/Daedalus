## Build

- The type key is `daedalus:frame` (dev FRAME_INTERFACE_KEY). The first version in next is 3, so there are no v1 or v2 layouts.
- Core never imports this crate. The core stores the type key and a memory space and nothing else (design: the core matches type keys and memory-space ids).
- Residency (dev FrameResidency): cpu, external (dma-buf), gpu. Raw values decode conservatively: an unknown value is Unknown, never a guess (dev raw_values_decode_conservatively).
- Format kind (dev FrameFormatKind): pixel, bayer, compressed, unknown. The kind is explicit in the layout. Dev's surface heuristic (fourcc 0 means unknown, surface dma.rs:95-101) is dropped.
- Plane mapping modes (dev PlaneMapping): cached, uncached, write-combined, unmapped.
- DRM constants as data: the fourcc codes, linear and invalid modifiers, and the MIPI CSI-2 packed modifier, with a fourcc helper (dev foreign_frame.rs:36-45).
- Layout: width, height, fourcc, modifier, planes (dma-buf fd index or CPU slice, offset, stride, length), sequence number and timestamp. Field names follow dev's FrameSource getters.
- Frame as a trait: producers implement a FrameSource-style trait, so frames from different sources share one reader. Dev has no concrete frame struct; keep it that way.
- CPU access is explicit: plane bytes sit behind a guard whose drop ends access (dev PlaneBytes). A metadata read never maps a plane.
- Plane limit: set it here and say what it is. Dev takes its limit from lemnos-abi, which next does not have.
- Dropped: FRAME_INTERFACE_V1 (identity only, usize length, u32 offsets) and every v1 path. Also the gpu crate's ExternalFrameDescriptor, which the layout replaces.

## Build

- Crate daedalus-lang-rust. serve(nodes) runs the worker loop on stdin and stdout. The nodes are ordinary functions declared with #[node] (A9). The hello is built from the registry records.
- Context: cancelled(), progress(fraction, message) and log(level, text). No thread-local event buffer; dev's events.rs is dropped.
- Each node runs under catch_unwind. A panic is a fault with code node_panic, and the loop keeps serving.
- Stateful nodes keep state in the worker and answer G1 state export and import.
- Stdout carries packets only. Output from node bodies goes to stderr through the log message.
- Fixture bodies: the 13 G fixtures in fixtures/nodes.rs. The shader CPU forms are dropped with their fixtures.
- Dropped: Worker::from_plugin, with_worker_id, the schema filter that hides builtin plugins, rust_worker_package and the BackendConfig builders (the spec is the caller's), and the shader CPU forms.

## Status

Partly done. `languages/rust` (daedalus-lang-rust) is the Rust worker SDK: `serve(nodes)` runs the worker loop, builds the hello from the registry records, runs each node under a panic guard, and sends events and outputs in order. A reader thread lets a cancel reach a running node. `#[node(backend = daedalus_lang_rust)]` works for functions whose ports are scalars, `String` or `Vec<u8>` bytes, through the body macro in `src/lib.rs`. The Rust worker serves three canonical fixtures, and they pass in two rounds through the process backend: `scalar_add`, `multi_output` and `raw_io`.

Not done, and why:

- **Ten of the thirteen canonical fixtures are not served.** `struct_record`, `enum_choice`, `optional_value`, `list_reverse`, `tuple_pair` and `map_pairs` have compound port types. `Typed` (core/types) has no const form for `Vec<T>`, `Option<T>`, tuples or maps, so `#[node]` cannot declare those ports. `custom_type_key` is opaque. `failure_diagnostic` needs a body that returns an error, and the `fn` body arm does not carry one. `bytes_echo` and `stateful_counter` need the `in` keyword as a port name, and state (`stateful_counter`) has no type on the `#[node]` path. Closing these needs a typed-port path in A9, not a change in this PR.
- **The Rust test set in the brief** (`serve.rs`: a panicking node, a malformed line, clean end of input, event order, cancel polled) is not written beyond the conformance test. The panic, the malformed-packet path, and cancel are in the code, but no test drives them.
- **Stateful nodes:** `Context::state` and `set_state` exist, but nothing declares a state type to the hello. `StateExport` and `StateImport` are answered as no-ops.
- **Dropped:** `Worker::from_plugin`, `with_worker_id`, the schema filter for builtin plugins, the package and backend-config builders, and the shader CPU forms, as the brief says.

Tests: `languages/rust/tests/conformance.rs` runs the three served fixtures through `daedalus_worker_conformance::run_fixtures` against the `daedalus-rust-fixture-worker` binary.

Shared-crate additions: `worker-conformance` gains `run_fixtures(spec, names)` (`run_all` calls it with no names). Additive.

### Added after: ports made of other types (`port-types`)

The reason six fixtures couldn't be declared is gone: `Vec<T>`, `Option<T>`, tuples and `BTreeMap<K, V>` are `Typed` now, compared by what they are made of, and `#[node]` declares such a port by its expression. This holds for every `#[node]`, on any backend. Serving the six fixtures in the Rust worker is the wire encoding for those types, which follows.

### Added after: all thirteen fixtures, state, the serve tests (`G9-finish`)

- **All thirteen canonical fixtures are served** by `fixtures/nodes.rs`, in two rounds each, through `tests/conformance.rs`. Ten are declared with `#[node]`: `scalar_add`, `multi_output`, `raw_io`, `bytes_echo` (its port is `in`, named as a string: `inputs("in")`, with a parameter `r#in`; the SDK's input lookup strips the `r#`), `struct_record`, `enum_choice`, `optional_value`, `list_reverse`, `tuple_pair`, `map_pairs` and `custom_type_key`. The port types come from `Typed` (`port_type`), which the port-types work (PR 145) added.
- **Structs and enums are structural.** `Record` and `Choice` implement `Typed` by hand with `STRUCTURAL = true`, because `#[derive(Type)]` makes a named type that is compared by key, and the fixtures compare the structure. Their `Wire` encode and decode are written beside them.
- **`optional_value` names its port type** (`ty = Option<i64>`). A bare `Option` parameter is an optional port of its inner type, which is a different port.
- **`failure_diagnostic` and `stateful_counter` are declared with `#[node]`** (see `worker-node-params` below).
- **State.** A `#[node]` with `state(T)` declares the state's wire type in the hello, so `T` implements `Typed` and `Wire`. A state export answers with a state value, and a state import is stored for the next run. A node with no state answers an export with a `bad_input` fault.
- **Opaque types have codecs in the worker.** The worker's schema registers the opaque keys its nodes use, so an opaque value decodes. Without this, an opaque input hung the run (the worker answered with a fault, and the host waited for outputs).
- **Cancel ordering.** The reader thread now records the run and resets the cancel flag when it reads a run packet, and sets the flag when it reads a cancel for the run going on. Before, the main thread did this, so a cancel right after its run could be lost.
- **Serve tests.** `tests/serve.rs` runs `serve-worker`: a panicking node is `node_panic` and the worker keeps serving; a malformed line is a malformed-packet fault and the next run still runs; closing stdin is a clean exit; progress and log events arrive in emission order before the outputs; a node that polls the context sees a cancel and ends `cancelled`.
- **State through the protocol.** `tests/rust_worker.rs` runs the fixture worker: a run gives 5, its export gives 5, an import of 100 is the start of the next run, which gives 105, and its export gives 105.
- **Fixed by `worker-node-params`:** `#[node]` takes a state parameter, a `&Ctx`, and a `Result` return, and `stateful_counter` and `failure_diagnostic` are declared with `#[node]`. The `examples/08_ffi/rust_worker` end-to-end test is in its own PR, `rust-worker-e2e`.

### Added after: `#[node]` takes state, context and fallible returns (`worker-node-params`)

- **The spelling is the in-process one.** A state is `state(T)` on the attribute and `state: &mut T` on the parameter. The context is a `&Ctx` parameter. A fallible body returns `Result<T, Fault>`. A parameter `in` is written `r#in`, and the port is named by the string in `inputs("in")`.
- **Where the worker differs, and why.** `Ctx` is an alias for the worker's `Context`, and `Fault` is an alias for `NodeError`, which has the same field names (`code`, `reason`). The code is the worker's `FaultCode` and the reason a `String`, because the worker's fault is a wire message, not a step's `u32` code and `&'static str` reason. A state type must also implement `Typed`, because the worker declares its wire type in the hello, which the in-process macro does not need. `Context` reports progress and log through `&self`, so a body reports through `&Ctx`.
- **The macro** reads the `bind` roles that `#[node]` writes (`take`, `read`, `modify`, `opt_take`, `opt_read`, `state`, `ctx`) in a tail-recursive walk (`__worker_call`), so a parameter role the worker does not yet honour (`fanin`, config) is a compile error rather than a silent wrong call.

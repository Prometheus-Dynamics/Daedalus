## Build

- Input: a region (B8) on the CPU backend. Output: Compiled::Steps where a run of nodes that merge becomes one Step. The Step's wrapper calls each node body in order, and values pass between the bodies as locals, not through slots.
- Merge rule, restated for regions. An edge merges when all hold: the source port has one consumer; the target port has one producer; the consumer is the next node in the region order; the consumer fires on any input (not fire = all); the edge is not a queued edge (its policy or the graph backpressure strategy does not force a queue); both ends are in the same region; and neither end sets node metadata daedalus.node.fusion to false, 'never', or 'off'. A conversion node (B4) is an ordinary node and merges like one.
- Covers: the merged Step still reports every node it covers (A3 StepEnd / plan covers list). A fault in a middle node stops the merged Step and sets StepCx.at to that node. The region fails as a whole (failure rule, C5). Nothing unmerges by itself.
- Manual unmerged mode: a compile option (C12 uses it for finding a faulty node) gives one Step per node and no merged calls. It must behave the same as the merged form except for speed.
- Errors and skips match Steps: a failed producer publishes nothing, so the consumer sees no value. A consumer that is not ready drops what it collected.
- Dropped from dev: the Carry SmallVec and fused_carry buffer, the fused-handoff telemetry (C11 may count merged edges per region), frame_probe.record_fused, the DAEDALUS_NODE_FUSION environment switch (C14 config), and the executor opt-out methods. Their replacement is the region option above.

## Proof

cargo test -p daedalus-cpu --features merge. fusion_equivalence: port dev's 60-random-DAG generator (chains, fan-out, fan-in, conditional and doubled outputs, optional and required inputs, fire = all, latest-only edges, state, failing nodes, opted-out nodes). Merged and unmerged runs must give the same node calls in the same order, the same inputs, the same outputs and the same faults for six ticks. chain_runs_as_one_fused_unit: a 16-node chain compiles to one Step. held_slot_payloads_survive_fusion ported as a test that a slot already holding a value is delivered first. Steady-state ticks make zero heap allocations (counting allocator).

## Build

- Recording body: an author gives `fn record(cx: &mut RecordCx, bindings: &Bindings)`. The region (E5) calls it in order with the region's encoder, and the author can open passes. The author never submits. Dev's rule holds that the encoder is the author's to control.
- FragmentPass, FragmentBinding and FragmentRects (dev fragment.rs): a WGSL fragment with `@location` targets, the rect vertex stage supplied by the backend. Bindings: input textures first, then storage parameter buffers, all in group 0. Every declared binding must be used (dev rule). Bind once and encode the bound pass; FragmentRects draws part of a target in one instanced draw.
- The fragment pipeline builder is one function, `fragment_pipeline(device, wgsl, targets)`, used here and by E6's fragment form.
- Raw submission (dev raw_vulkan.rs, RawSubmitter): a ring of reused command buffers, each with a fence, `submit` returns a ticket (try_complete, wait). Raw submits take the same submit lock as every other submit. Commands are recorded through E13's safe wrapper. Raw commands do not see queue.write_buffer data, so the region flushes uploads first (E3).
- Plugins do not get raw Vulkan handles. Dev's `GpuContextHandle::raw_vulkan()` is dropped as a public API. Raw access stays inside the backend crates.
- Check `storage_buffer_8bit` before any raw pipeline reads 8-bit storage (dev RawVulkan::storage_buffer_8bit).
- The widen_u8.comp source and its committed .spv stay as the fixture for raw tests, with dev's glslang command in the file's header.

## Status

Done, and run here on hardware and on lavapipe. The V3D timings are written in `testing/board-runs/E7.md` and haven't been taken.

Differences from the brief:

- A recording body is a const of type `RecordBody` on `#[node(backend = daedalus_wgpu_author(record, src: T, dst: T))]`, holding a function `fn(&mut RecordCx) -> Result<(), String>`. `RecordCx` gives the device, the region's encoder, and the node's buffers by port index. There is no separate `Bindings` argument. An output is as large as the first input unless the body says otherwise with `sized`. The body's error faults the region's step at that node, and nothing is submitted.
- A recording body sees wgpu itself: the device, the encoder and `Storage::wgpu`. That is what this level is for. Raw Vulkan handles don't leave the backend crates: `Storage::raw_buffer` is for a recording through `backends/vk-sys`.
- `backends/wgpu` forbids `unsafe`, and a function that takes a raw recording has to be `unsafe`, so the raw submitter stays `daedalus_vk_sys::submit::Submitter`. This PR adds the safe part: `WgpuBackend::raw_submitter` makes it on the backend's device with the device's own submit lock, and `storage_buffer_8bit` answers before a pipeline is built. The raw tests are in `backends/vk-sys`, where they can record: ordering against wgpu's own submits, a ticket whose slot was reused, a one-slot ring, a drop that waits, no allocation per submit, and the 8-bit kernel from dev's fixture.
- Raw submits don't go through a region yet. A region that flushes uploads and then submits raw commands is for whoever writes the first node that needs it.
- `FragmentPass` takes its layout from the shader, as on dev, so every declared binding has to be used and bound. `fragment_pipeline` is the one builder, ready for E6. A pass is drawn into an encoder (`encode_bound`, `encode_rects`), and `run_bound` and `submit` are for running one by hand. A fragment pass as a node of its own in a region is a recording body that calls it.
- `Texture` gains render-target usage, which every one of the seven formats supports.
- The validation layer isn't installed here or in the GPU lane, so "no message outside a known list" isn't checked. wgpu's own validation is on in every test, through error scopes and the uncaptured-error handler.
- `integer_formats_round_trip_exactly` is E3's test of the same name, and isn't repeated.

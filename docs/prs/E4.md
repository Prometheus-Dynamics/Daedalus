## Build

- A shader body is a `const NAME: &str` (or include_str!) on `#[node(backend = wgpu, ...)]`. The authoring macro in backends/wgpu-author is a proc-macro crate. At expansion it reads the WGSL with naga and emits a static record: entry point, workgroup size, and a binding table (index, kind, access, texture format, sample type, view dimension, sampler kind). There is no WGSL parse at run time.
- Replace dev's string scan (crates/wgsl-infer: find '@binding', then parse the next line). Naga reads only real declarations, not text in comments. It also resolves a `@workgroup_size` built from a const, which dev cannot (dev returns None and fails at run time with 'failed to infer workgroup size'). A missing workgroup size is a macro error on the node. The wgsl-infer crate is dropped; it has no tests.
- Port types: a function node types its ports from its Rust signature (A9). A shader node types its ports from its GpuBindings fields, using the classification rules in dev's shader_bindings classify.rs and map.rs (storage read, storage write, storage read-write, uniform, sampled texture, storage texture, sampler). The derive emits the A8 record instead of dev's runtime spec.
- Binding limits are checked at expansion against GpuComputeCaps::WEBGPU_DEFAULTS (8 storage buffers and 4 storage textures per stage, 16 KiB workgroup storage, 256 invocations). A body over those limits fails to expand, and the error names the count. The device's own limits are checked at compile (E1).
- Shader pipelines are cached per device key. The key is a stable 64-bit hash (FNV-1a) over name, entry, source bytes and the binding table. Dev's DefaultHasher key is not used: its output is not stable across Rust releases, and the key must survive into the on-disk pipeline cache.
- `compile` builds the bind group layout and the compute pipeline once per (device, key). The Step only sets the pipeline and a bind group. Bind groups are cached per (pipeline, buffer identities), with the dev limit of 256 per device.
- Dispatch shape: a whole-shader node is one compute pass. The workgroup count comes from the node's declared invocation shape (dev's invocation_stride, workgroups.rs) or from explicit counts. Output buffers are sized at load.
- Uniform data is passed as Pod bytes (dev bindings.rs Uniform<T>).
- Dropped: ShaderContext and ShaderInstance with name lookup (dispatch_by_name), `dispatch_auto` and the blocking `dispatch` helpers, the `Compute<DynamicImage>` input helpers in types.rs, and the GpuBindings runtime plumbing. A node reaches the GPU only through its region (E5).
- The authoring part is written into backends/wgpu-author/README.md: how to write a shader node, the three levels, the binding table. I5 turns it into docs/gpu-nodes.md. Remove the Styx and Eidos names from what is carried.

## Proof

CI: a compile-pass case with a shader whose comment contains `@binding(3)` gets no binding 3; a trybuild compile-fail case with 9 storage buffers fails with the count in the message; a missing @workgroup_size fails at the node; a const-sized @workgroup_size is read. Golden test: the pipeline key of a fixed shader equals a pinned value. On lavapipe: a copy shader matches the CPU result; cached_spec-style test (ported from spec_cache_tests.rs: cache keyed by content, not address); a_kernel_dispatch_allocates_no_more_than_raw_wgpu (ported from gpu_allocations.rs) passes.

## Status

Done, and run here on hardware. lavapipe runs it in the GPU lane of CI.

Differences from the brief:

- `#[node]` passed a const body's name to the body macro and nothing else, so no macro could read the WGSL at expansion. #88 added a trailing `init = (..)` with the const's initializer tokens. That was a change to a shared interface (`core/macros`) and went in as its own PR.
- A port's type comes from the backend's arguments, `backend = daedalus_wgpu_author(src: Samples, dst: Samples)`, and a port is fed by the binding of the same name. There is no `GpuBindings` struct or derive: the binding table is read from the WGSL, so a struct would only repeat it.
- The authoring crate is a proc-macro crate, so it can't re-export anything. The code it generates names `::daedalus_wgpu`, `::daedalus_registry` and `::daedalus_types`, and a crate with shader nodes depends on all three until the facade covers it.
- `include_str!` is resolved against the file the const is in, through `Span::local_file`.
- A shader with no `@workgroup_size` is refused by naga's own parser, and the node shows naga's message.
- Textures are two-dimensional and not arrays, and a storage texture is one of the backend's five storage formats. Anything else is a macro error that says so.
- `Shader::load` and `Shader::run` are the way to run a shader until E5 gives regions steps. `run` submits by itself, one pass per submit. The backend's `compile` still refuses.
- The bind group limit of 256 is per device, as on dev, and the oldest goes first.
- The allocation test compares the cheapest of 16 runs on each side, because wgpu's own count varies as its tables grow.
- A uniform is passed as bytes the length of the WGSL struct. A typed wrapper is left to the node's config port in E5.

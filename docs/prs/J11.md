## Build

- `Registry::register_owned` made a body of text and nothing else: right for a declaration that arrives as data from a worker, and no use to a host that makes a node while it runs and has the code for it in its own process. `#[node]` was the only way to give a node code.
- The general form: a run-time declaration can carry the payload of whichever backend it names, as a compiled-in record does. This is not a CPU special case. The CPU backend then takes one more kind of payload, a closure.

## Proof

`backends/cpu/tests/owned_code.rs`: three nodes are declared at run time with closures that hold values only known then (a word, a count, a place to keep the result). The graph plans on the CPU backend, its steps run in the plan's order, and the last node has kept the word repeated the count's times. A run-time declaration with no code, naming the CPU backend, is still refused, with the backend's reason.

## Status

Done.

- `OwnedBody` has `code: Option<Arc<dyn Any + Send + Sync>>`, with `OwnedBody::text(..)` and `OwnedBody::code(..)` to make one. The promoted record's `code` is that payload, kept for the life of the process. Two declarations that differ only in their code are different declarations: the payload is told apart by where it is.
- `daedalus_cpu::steps::CpuStepBody::new(closure)` is the CPU backend's run-time payload: the closure is given the node's `Setup` and returns its `Step`. The backend takes a `CpuBody` (a `#[node]` function) or a `CpuStepBody`.
- A closure body runs as a step in this process only. The blob and source forms, and a `#[transfer]`, still need a `CpuBody`, and refuse anything else as they did.
- Not built: typed helpers for writing such a step. The closure builds a `Step` by hand, reading and writing its cells with the runner's own calls (`typed_view`, `put_typed`), where `#[node]` generates that from a function's signature.

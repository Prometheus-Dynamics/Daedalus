## Build

- The lavapipe lane: the wgpu backend's conformance cases, the A12 suite cases for the backend, and the ported tests from E1-E8 and E16 run with VK_ICD_FILENAMES pointing at lavapipe. The lane fails if it runs zero GPU tests. Dev's rule that unit tests skip without an adapter stays, but a lane that skips everything is a failure.
- Validation layer on lavapipe: any validation message outside a short known list fails the lane. Dev's list (ci.sh around line 496) pins RADV, and CI has no RADV, so the list is redone for lavapipe.
- Budgets counted in CI, not timed: queue submits per region, pipelines created per merged chain, passes per region, allocations per Step after warm-up, transfers per boundary. Each is a constant in the budget crate, and a regression fails the test.
- Timed budgets run on the CM5 (board_run). The table from design.md is recorded per PR. A PR that makes a number worse says so in its description.
- gpu_bench moves into testing/crates/gpu-budgets as the measurement tool (sections batching, allocation, dispatch-floor, readback, limits). It runs on boards, not in the gate.
- Ownership of ci.sh: the lane is one function in scripts/ci.sh, which A2 owns. This PR adds scripts/gpu-lavapipe.sh and asks A2 to call it from the gate. It does not edit ci.sh.

## Proof

CI: the lavapipe lane runs with a non-zero count of executed GPU tests. A planted region that submits twice fails the submit budget test. A planted validation error fails the validation lane. Budget constants match the values the tests measure on lavapipe for submits, passes, pipelines and transfers.

## Build

- A backend that runs no nodes: `can_take` returns nothing. `memory` declares the `dmabuf` space. `transfers` declares dmabuf to CPU (map, cost `import`) and CPU to dmabuf (copy).
- Holds blocks of memory with an fd and a length. It knows nothing about width, format or planes, and has no image or frame type.
- Allocate from `/dev/dma_heap/<name>` through `dma-sys`, or from a memfd. Strides are the caller's business.
- Pool: keeps up to 4 idle blocks per size (dev KEPT = 4) and reuses them. A block returns to the pool when its last holder drops it. Dropping the pool releases what it holds. Reuse allocates nothing.
- CPU access is explicit: mapped bytes sit behind a guard whose drop ends access. Begin and end access use the dma-buf sync calls in `dma-sys`.

## Proof

CI: memfd blocks round-trip bytes and identity; the pool reuses up to 4 idle blocks and drops the 5th, counted; a block is released exactly once; steady-state reuse allocates nothing. The dma-heap test skips with a reason where `/dev/dma_heap` is absent. It passes the conformance suite (A12) as a memory-only backend.

## Status

Done. Every test ran here, the dma-heap one included. The CM5 run is written in `testing/board-runs/E17.md` and hasn't happened.

Differences from the brief:

- A value in the `dmabuf` space is an `Arc<Block>`. The pool keeps a reference to each block it lends, and a block is idle again when the pool's is the only reference left, which the pool finds out the next time it is asked for anything. So no drop hook is needed, a block can sit in a runner slot as an ordinary typed payload, and reuse allocates nothing.
- `dmabuf.map` hands the block itself to the CPU side: it is mapped when it is made, and the reader takes a guard. `dmabuf.copy` copies a CPU value's bytes into a block, and passes a value that is already a block straight through.
- A transfer's step is made by a plain function that can't see its backend, so each `dmabuf.copy` step owns a pool of its own, and where its blocks come from is the choice of the latest `DmabufBackend::new` in the process.
- memfd creation is a kernel call, so it went into `backends/dma-sys` as `DmaBuf::memfd`.
- The crate is Linux only, and empty elsewhere.

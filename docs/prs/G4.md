## Build

- Crate daedalus-backend-process, implementing the A7 Backend trait. A worker spec (program, args, env, working dir, launch hook) is part of a node body's record in A8. Nodes with equal specs share one worker process. The language PRs G5 to G9 set their specs.
- Compile: a region on this backend compiles to Compiled::Steps holding one step. The step takes a run buffer from the A5 recycle pool, writes one run message, reads the reply packets and writes outputs into the region's slots. One run is outstanding per worker; a second run waits.
- Reader: one thread per worker reads packets from stdout into pooled buffers and pushes them to a bounded channel. The step waits on the channel with the region deadline.
- Deadline: an optional per-region deadline. On expiry the backend sends cancel, waits a fixed grace period, then kills the child it stored at spawn and reports a fault. It never kills by name or by search.
- Stderr: a thread drains stderr into a 64 KiB ring. The tail is attached to fault reports.
- Hello: the worker must send hello within a fixed startup deadline. Its declarations are compared with the registry; a mismatch is a registration error that names the spec and the node id.
- Supervision: a dead, hung or faulted worker makes its region report Fault, covering the region's nodes and the failing node if known. A respawn happens on a later run after a backoff capped at 8 s. It never gives up on its own. An operator disables a backend by hand. No automatic off.
- Steady state: after the first run a run allocates nothing. A worker crash never ends the host process.
- Shutdown: send shutdown, wait for exit within the grace period, then kill the stored child. Drop does the same.
- Telemetry through C11: spawns, restarts, faults, runs, bytes in and out, stderr bytes.
- Conformance: testing/crates/worker-fixture is a small Rust binary that speaks G1 and serves 13 canonical fixtures. testing/crates/worker-conformance holds the fixture specs and a runner that drives any worker spec through this backend. Dev fixtures image_passthrough, shader_write_u32, capability_camera_frame, boundary_frame_modify and package_shader_asset move to the interface and GPU libraries.
- Dropped: JSON and base64 transports, payload handles, leases, mmap and shared-memory transports and their ownership modes (a memory backend can add shared memory as a transfer), the runner pool keyed by serialized config, RunnerLimits queue depth and restart policy, batch loops, the in-process EchoRunner and FixtureRunner, the self-echo conformance harness, and the PeekNamedPipe reader (Windows support returns in D10).

## Proof

cargo test -p daedalus-backend-process. worker-conformance against worker-fixture: all 13 fixtures pass, each run in two rounds. Named tests: a worker that exits mid-run gives a fault covering the region, then a respawn after the backoff; a worker that never answers is cancelled and then killed, and the test asserts the killed PID equals the PID the backend spawned; stderr stays within 64 KiB; an oversize packet from the worker is a fault with no large allocation; a steady-state run allocates nothing; a run keeps trying after three consecutive faults.

## Status

Done. `backends/process` (daedalus-backend-process) runs nodes in worker processes. `testing/crates/worker-fixture` serves the thirteen canonical fixtures, and `testing/crates/worker-conformance` holds them and a runner. All thirteen pass in two rounds through the backend. The board run is in `testing/board-runs/G4.md`, untested.

Shared interface additions (small, and needed by this PR):

- `core/abi/src/slots.rs`: `Slot::bytes()` returns a full cell's bytes for the static, inline and shared owners. This is the one read of a raw cell, and it is the only unsafe here, with a `SAFETY` comment. The process crate forbids unsafe, so it cannot read a cell itself. Layout is unchanged; the layout hash does not move.
- `core/wire` (G1): `pub mod kind` (the message kind bytes are public, so the host can frame a run), and `Reader::{pos, span, text}` (position, a span of read bytes, and a borrowed string, so the output path allocates nothing). Additive only.

Differences from the brief:

- **Values are the slot form.** A scalar is its little-endian bytes, a string or byte field is its raw bytes, and a compound value is its wire encoding. The host writes inputs and reads outputs in this form with no `WireValue` in between, which is what lets a steady run allocate nothing. Outputs of 16 bytes or less are inline, and longer ones are `Arc<[u8]>` published with `Arc::into_raw`.
- **Regions.** One region is one worker and one step. A region with edges between its nodes is refused, since values do not travel along edges here, and a region whose nodes span two workers refuses the second. Refusals name the nodes, and the planner assigns them elsewhere.
- **Memory.** The backend's host space is `process.host`, and it offers no transfers. A graph that mixes `cpu.host` values with this backend needs a host transfer, which is not in G4.
- **`can_take`** offers every node with a body for this backend, since an offer carries no node id. A node no worker serves is refused in `compile`.
- **Registration** starts the worker and reads its hello at `add_worker`. Each declared node is checked against the registry: its id, its port names and count, and its port types (`TypeRef::Expr` exactly, `TypeRef::Key` by scalar key or opaque key, `TypeRef::Body` not at all). The error names the program and the node. A respawn checks the protocol version and layout hash only.
- **Sharing.** A spec equal to one already started (`same_as`, which ignores the launch hook) is a no-op. The node ids come from that worker's hello.
- **Telemetry** is the backend's own counters (`Snapshot`: spawns, restarts, faults, runs, bytes in and out, stderr bytes). It is not wired into C11's runner counters.
- **Fault text.** A step's reason is cut to 120 bytes by `StepCx`, so the stderr tail appended to a fault report is cut too. The tail is kept in the worker and its held size is visible through `stderr_held`. The full reason is not carried further in G4.
- **Fault protocol.** A node's error is sent as a `Fault` packet, followed by `Outputs` with status `fault`. The host ends the run on `Outputs`. A worker that exits, hangs or sends a bad packet is killed, and its link goes down until the backoff passes.
- **Progress** is passed to `StepCx::progress` as thousandths of the fraction.
- **Backoff** is 100 ms, doubled per failure, capped at 8 s. A respawn happens on the first run after the backoff, and nothing turns the backend off.
- **Testing-only nodes.** The fixture worker takes `--misbehave` modes (`exit`, `exit-once:<marker>`, `hang`, `oversize`, `stderr-flood`) for the supervision tests. They are not among the thirteen.
- **Test binary.** The fixture binary is built by a nested cargo into `CARGO_TARGET_TMPDIR`, because `CARGO_BIN_EXE_*` only works within one package.
- **Dropped:** the five GPU and image fixtures, JSON and base64 transports, payload handles and leases, the runner pool, and the in-process echo runners (they were not carried, as the brief says).

Tests (`backends/process/tests`):

- `conformance.rs`: thirteen fixtures, two rounds each, through the fixture worker.
- `supervision.rs`: a worker that exits once faults, is refused during the backoff, and respawns after it; a worker that never answers gets a cancel, then a kill, and the killed pid is the spawned one; an oversize packet is a fault that names the cap; a megabyte of stderr is drained and held within 64 KiB; four rounds of repeated exits each start a new worker after the backoff; a registry without the node is refused naming it.
- `alloc.rs`: 200 steady runs allocate nothing on the host thread (counting allocator).

## Build

- languages/cpp/Cargo.toml is a crate, daedalus-lang-cpp, so the workspace glob accepts this directory.
- daedalus.h is a C11 header with the G1 packet codec, the worker loop and node registration. daedalus.hpp is a C++17 header-only layer on top with DAEDALUS_NODE, to_wire and from_wire templates for A4 types, and typed errors.
- Node functions receive bytes as a const pointer and length. Outputs come from an arena that the loop resets after each run, so steady state makes no heap allocation per run.
- u64 is uint64_t, exact. Range checks are explicit; no casts through int64.
- Workers only. The in-process pointer-length ABI is not carried.
- Showcase: the non-image, non-GPU nodes of examples/08_ffi/cpp/complex_plugin/src/showcase.cpp are ported to fixtures/nodes.cpp.
- Dropped: the CCpp in-process ABI backend and the pointer-length views in crates/ffi/cpp/src/lib.rs, the BytesView, SharedBytes, CowBytes and OwnedBytes subclasses (BytesView owns a vector, and the others are nominal), Rgba8Image and GpuRgba8Image stubs, DAEDALUS_GPU_NODE, DAEDALUS_PACKAGE_ARTIFACT, DAEDALUS_PLUGIN and DAEDALUS_BOUNDARY_CONTRACT descriptor macros, and sdk_descriptor.cpp.

## Proof

cargo test -p daedalus-lang-cpp builds the SDK with cmake and g++ and runs worker-conformance: 13 fixtures pass in two rounds. wire_test: u64 max; out_of_range on int8 and uint8 overflow; kind mismatch. worker_test: a node that throws becomes node_error and the worker keeps serving; a malformed packet is a fault and the next run still works.

## Status

Partly done. `languages/cpp` (daedalus-lang-cpp) holds the C SDK (`sdk/src/daedalus.c` with `sdk/include/daedalus.h`), the C++17 header-only builders (`sdk/include/daedalus.hpp`), the canonical fixture worker (`fixtures/nodes.cpp`), and a CMake project (`sdk/CMakeLists.txt`). The Rust crate configures and builds the worker with CMake (`build()`), then:

- `run_all` runs all thirteen canonical fixtures through the worker, two rounds each: passes.
- A fault run returns a fault packet then outputs with status fault; a malformed packet gets a `malformed_packet` fault, and the next run still works: passes.

Differences from the brief:

- **The native C++ tests are not written.** `wire_test.cpp` and `worker_test.cpp` are replaced by the Rust-side protocol checks above. The out-of-range checks run inside the worker's encoder (an output that does not fit its type ends the run with status fault), not in a unit test of the codec.
- **No `DAEDALUS_NODE` macro.** Nodes are plain `extern "C"` functions in a `dd_node` table. The header gives type builders and a port helper.
- **Arena per run.** Values live in a per-run arena reset when the run ends. A value a node keeps across runs (state) must be copied out by the node. `dd_state`/`dd_set_state` keep the state value itself; its pointers are the node's to manage.
- **Events are written as they happen**, not buffered until the outputs. Order is preserved, since they are all written before the run's outputs.
- **Stdout** is redirected to stderr with `dup2`, and packets go through a `dup` of stdout. On Windows the `_dup`/`_dup2`/`_fdopen` variants are used. Windows is compiled by the CMake project under MSVC with `/W3` (warnings not treated as errors) since the Windows build has not been run here.
- **State export and import are not served** by the C SDK. A cancel between runs has nothing to stop.
- **Dropped**: the CCpp in-process ABI backend, the pointer-length views, the subclassed byte types, the descriptor macros, and `sdk_descriptor.cpp`.
- **Unverified**: the Windows build (CI runs it; here it was only built on Linux with gcc and g++), and the CMake install is not used by the gate beyond the test.

Tests: `languages/cpp/tests/conformance.rs` (the thirteen fixtures, and the fault and malformed-packet checks).

## Status (CI follow-up G8-ci)

The two C++ tests ran CMake into one build directory in parallel, and the second configure saw a half-written tree. `built()` now builds once per test binary through a `OnceLock`, so every test shares the one build. The Java, Node and Python tests use separate directories or have no build step, so they are unaffected.

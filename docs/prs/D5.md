## Build

- chip.rs declares queue, ring, clock and errors always, and scalar, param and wire behind feature chip-params (their files arrive with D6). Chip runtime in backends/cpu under feature chip (no_std, no alloc). It holds: a fixed-capacity typed Queue<T, N> that stores values in MaybeUninit slots with shared Ring index arithmetic; Overflow (drop oldest, drop newest, error); Ctx { tick: u32, now_micros: u64 } for nodes that take &Ctx; a Clock trait for tick_with and tick_at(now); ChipError (QueueFull { edge }, Node { node, code }, Port { port }), a Copy enum with no formatting and a defmt feature.
- The generated module from D4 calls only these items plus the node bodies. push_<port>, pop_<port>, tick, tick_with and tick_at, and new() as a const fn.
- Nodes: a chip node is a #[node] (A9) with the CPU body path. Its error is a code, as in D1. Its state is a state(T) slot, as in D1.
- User adapters (dev's #[adapt]) have no design home. This PR does not carry the attribute. A user conversion is a one-in, one-out #[node] registered as a conversion (A8, B4).
- Dropped: the alloc feature (String and Vec<u8> ports; the chip runs with no heap), the McuType trait and mcu_type! macro, the NodeDesc descriptor, and the mcu_macros crate's descriptor output. The design has one #[node] macro.
- Budgets (design, measured on dev): the five-node blink graph is 3 to 12 KiB of flash and 112 to 584 B of RAM across modes. The compiled firmware alone must match dev's measured values: 2988 B flash and 112 B RAM on thumbv7em, and 3316 B flash and 112 B RAM on thumbv6m. The compiled size is pinned exactly in scripts/ci.sh (dev's MCU_COMPILED_SIZE pattern, renamed to a chip constant), so any change must update the pin with a reason.
- scripts/ci.sh gets a 'chip' subcommand that replaces 'mcu': it builds examples/chip_blink (compiled) for thumbv7em-none-eabihf and thumbv6m-none-eabi with the chip profile, prints flash (.vector_table, .text, .rodata, .data) and static RAM (.data, .bss, .uninit) from readelf, and fails over budget or on a pin change. The chip profile is in the root Cargo.toml. The portability job's step that runs the mcu subcommand is edited to run chip.
- docs/chips.md replaces the chip sections of docs/mcu.md (Which Runtime, Workflow, Limitations, Measurements). I5 links it.

## Proof

scripts/ci.sh chip on thumbv7em-none-eabihf and thumbv6m-none-eabi: prints flash and RAM, fails above 12 KiB flash or 584 B RAM, and fails if the compiled size differs from the pinned value. cargo check -p daedalus-cpu --no-default-features --features chip for both targets. chip_queue (native): FIFO order, latest_only, drop_oldest, drop_newest, error_on_full returning QueueFull. chip_alloc: a counting allocator shows zero allocations across push, tick and pop. chip_string_port (trybuild): a chip node with a String port fails to compile.

## Status

Merged. Differences from this brief:

- Firmware sizes: 2120 B flash and 112 B RAM on thumbv7em, 2652 B and 112 B on thumbv6m. RAM matches dev and flash is smaller, so the pins in `scripts/ci.d/chip.sh` are these figures, not dev's.
- The typed queue and the `Ring` arithmetic are in `core/runner` (`fixed_queue.rs`), because `backends/cpu` forbids `unsafe`. `chip` re-exports them, so there's no `chip/queue.rs` or `chip/ring.rs`. The blob runner uses the same `Ring`.
- `Ctx` is D1's `StepCx` with `now_ns`, not a new `{ tick, now_micros }` struct. `tick_at` takes nanoseconds and `Clock` returns them.
- A node crate for firmware depends on `daedalus-cpu-author` with `default-features = false`. Whether `#[node]` needs an allocator is decided inside `daedalus-cpu`, by `__if_alloc!` and `__cpu_body!`, so feature unification can't get them out of step.
- The generator is `examples/chip_blink/nodes/examples/generate.rs`, in the nodes crate, so it still runs when the old module doesn't compile. D7 builds on it there. This PR also adds `tests/generated.rs`.
- A non-`Copy` port is refused while planning, naming the type. `fail_chip_string_port` shows the queue itself also refuses, since one `#[node]` can't be told it's for a chip.
- The size check is `scripts/ci.d/chip.sh`, which the gate picks up by itself. There's no portability job to edit yet.

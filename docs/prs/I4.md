## Build

- Each directory under examples/ is a crate, as the design requires. examples/Cargo.toml on dev is not carried; the workspace globs pick these up.
- 00_quickstart: one node, one graph, feed, step, take. Uses only the facade (C14).
- 01_basics: typed ports, const inputs and config, one fan-in and one fan-out. Uses only the planner forms and the CPU backend.
- 02_host: a Host that is fed, stepped and drained in a loop, with a reload in the middle that keeps the state of one node and reports the change of another. This replaces dev's 09_hosts.
- 03_metrics: the metrics that C11 reports, read from a Host. Replaces dev's 06_metrics_debugging.
- Dropped on dev: 02_engine_config (the engine config is replaced by the planner forms and Host options), 03_transport (the transport crate is replaced by the value and wire layers). Dropped: 08_ffi and plugins (owned by G-series PRs), surface_image, mcu_* (owned by D7), wasm_* (owned by D9), nostd_smoke (owned by C1).
- Examples name no hardware. They use CPU nodes only, so they run on GitHub-hosted runners.
- smoke.sh is the scripts/ci.sh fragment that builds and runs each example binary listed above and fails on a non-zero exit.

## Proof

scripts/ci.sh smoke runs the four examples and checks their output against a golden line in each example's test. Tests named quickstart_output_matches, basics_fan_in_out, host_reload_keeps_state_and_reports_change and metrics_read_from_host, in each example crate's tests/. A planted failing example (a wrong golden line) fails the smoke step.

## Status

Done. `examples/00_quickstart`, `01_basics`, `02_host` and `03_metrics` are crates, each a library with `run()`, a binary that prints it, and a test with the golden lines. `scripts/ci.sh smoke` runs each binary and each test.

As built:

- **00_quickstart:** one `#[node]` function between a host input and a host output: register, plan, load, feed, step, take.
- **01_basics:** two constants set by the graph, a `#[derive(NodeConfig, Type)]` config struct with one field set by the graph and one left at its default, one input fanned out to two nodes and both fanned in to a `FanIn` node. It also prints what the planner says about a graph whose config does not fit.
- **02_host:** a host fed, stepped and drained in a loop. In the middle the graph is reloaded with the first stage replaced: the running total goes on from where it was, and the report names the replaced node as fresh.
- **03_metrics:** `Telemetry` at the trace level around each tick with a counter for a clock, then the counters, the per-step row, the per-tick events and the fault reports, read back and printed.

Differences from the brief:

- **"Uses only the facade" holds for `use` lines, not for `Cargo.toml`.** The core names no backend, so an example names the CPU backend itself (`daedalus_cpu::CpuBackend`), and `#[node]` expands to paths in `daedalus_cpu_author` and `daedalus_registry`, so an example's manifest lists those three beside `daedalus`. The facade test's rule now allows `use daedalus_cpu::` and `use daedalus_cpu_author::` in examples, and says why.
- **The facade grew.** `daedalus::prelude` now has `node`, `NodeConfig`, `Type`, `Registry`, `NodeRecord`, `GraphDoc`, `GraphBody`, `Telemetry`, `Level` and `ExecutionReport`, and `daedalus::layers::registry` exists. Without them no example could be written against the facade.
- **02_host keeps `total` in a step of its own** (`daedalus.node.fusion` false). A reload keeps the steps that did not change, and the CPU backend would otherwise merge the two nodes into one step that changes as a whole.
- **The smoke step runs each example's test as well as its binary**, since the golden lines are in the test.

Bug found and fixed first, in its own PR (`C10-fix`, #126): a reload listed a CPU node's state as carried and then dropped it. Without that fix 02_host printed `[-1, -3, -6]` after its reload, under a report that said the total was kept.

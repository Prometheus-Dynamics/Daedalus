## Build

- Load already had the `Recovery` type and the runner applied it (C5). Load set `Recovery::Fail` on every step. Now each step's recovery comes from its nodes' metadata at load.
- Keys, on the node's metadata: `daedalus.node.recovery` set to `"fail"`, `"skip"` or `"restart"`, and `daedalus.node.retries` set to an integer from 1, which gives `Recovery::Retry { max }`. Both together, a non-integer, zero or an unknown name are refused at load with `LoadError::Recovery`, which names the node.
- A step that covers several nodes (merged) takes the one recovery the nodes that set one agree on. Two different explicit values refuse the load, and the message points at `daedalus.node.fusion`.
- The graph-wide default is not read. `GraphBody` has no metadata field, and adding one touches every graph literal in the workspace. Set the key on each node. This is a stated gap, not a silent one.
- Manual off already exists (`set_node_on`). It is now covered by a test with a failing node.
- Failure rule: no automatic off from these keys, backoff stays at the C5 cap of 8 s, retries don't sleep.
- `Host::set_failure_policy` is added so a host can turn fail-fast on, which the tests need.

## Proof

`cargo test -p daedalus-planner-tests --test j1_recovery`: a fault fails the run by default; skip keeps the run going under fail-fast; restart is accepted; retries run the body again (step calls and retry count are checked); a retried fault still stops a fail-fast run; both keys, an unknown name, a non-text recovery, zero, negative and text retries are refused; a failing node is never switched off by default across 20 ticks; manual off stops a failing node and on brings it back.

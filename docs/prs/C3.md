## Build

- Crate daedalus-host at core/host. alloc is allowed (not on the no-heap list). lib.rs: each host PR adds only its own mod line.
- Host::from_loaded(plan) (C10 supplies the loaded plan). feed(port, value) -> FeedOutcome; step() -> Result<TickReport, HostError>; take::<T>(port) -> Option<T>; drain::<T>(port) -> Vec<T> (allocates, host side only).
- Ports come from the plan: each host input and output has a slot index and a type key (A4). Lookup is a binary search over a sorted table, not a hash map. An unknown port error names the port.
- feed converts the value to a payload (A5), checks its type key against the port, pushes it into the input slot, and sets the dirty bits of the consumers, the same as a body write. feed never runs a tick.
- feed_all (dev batch.rs): several pushes under one dirty update, applied in order.
- step() runs one C1 tick and returns the TickReport from C11. An idle step is the C1 idle path and nothing more.
- take pops one value from a host output slot with a typed check. drain pops all. Both use the C15 policy later; until C15 lands, FIFO with the plan capacity.
- Handles: PortId and typed port handles carry over (handles.rs). The dev HostBridgeManager, its alias registry and the default input and output policy setters do not carry: one Host per graph, and sharing across graphs is C21.
- Errors name the port and both type keys on a type mismatch. No Strings in the tick path.

## Proof

core/host/tests/host_io.rs: feed three values, step, take three in order; a wrong-typed feed fails and names the port and both keys; an idle step makes zero step calls (C1 counter); a steady feed, step, take loop with pooled payloads allocates nothing after warm-up (counting allocator).

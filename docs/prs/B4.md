## Build

- For each edge whose producer output type differs from the consumer input type, find a conversion path in the registry's conversion table (A8). The cheapest path wins. Ties go to fewer steps, then to the lower conversion id. The path is inserted as conversion nodes that are ordinary registry nodes, so later stages see only ordinary nodes.
- A conversion is available only when its features are active (config active_features, B13).
- No path: ConverterMissing, naming the edge and both types. For a numeric pair, add the note that the conversion may lose data and is never implicit.
- Exclusive access: when the consumer takes its input by move or by modify, and the producer port is fanned out or held, insert one copy per consumer so each gets its own value (dev target_exclusive rule).
- Host input policy (held, shared) is a typed field on the host bridge (A6), read here. A held input that feeds a by-value consumer is planned as a fan-out. Dev host_inputs.rs keeps its round-trip through the graph document (B13 and A6 carry the document form).
- Dropped: device residency targets (target_residency_for_node, consumer_device_key, is_device_of). Memory spaces are chosen at stitch (B9), after backends are assigned, so they cannot be chosen here.
- Dropped: the edge-explanation metadata strings. B11 produces a typed explanation instead.
- Adapter tables are not planner state. Lookups go through the A8 registry view.

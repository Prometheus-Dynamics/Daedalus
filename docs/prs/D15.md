## Build

- Rows for the CPU ops on the kernels that come across: daedalus.float.f32_from_le, f16_to_f32, f32_to_unorm8; daedalus.copy.bytes; daedalus.codec.hex_lower, base64_encode, base64_decode and crc32. Each row points at a file under backends/kernels-sys or backends/cpu, and at its test in backends/kernels-sys/tests/conformance.rs.
- The registry test checks that every CPU row names an existing file and an existing test function (the path check is the same as the brief's read check).
- Not carried: the GPU rows (daedalus.gpu.storage_to_texture and the kernels.wgsl compute rows: E12), the fixed-function rows (RGA, VGLite, and the rgba_red Y-only row), the GPU image rows (removed on dev), and the rgba_red and pixel fixed_function cells.
- Evidence: the CM5 neon64 and scalar rows from docs/accel-evidence/raze-cm5-v3d-2026-11-02.jsonl (12 neon64 lines) move to testing/board-runs/accel/raze-cm5-neon64.jsonl, re-recorded on the new paths when D2's board run is done. The v3d and fixed_function lines are not carried (E12 and Lemnos).
- docs/backend-matrix.md and .csv are generated by accel-matrix render (D14) and checked in. The baseline is regenerated for the carried rows only. Dev's CPU pass cells for these ops must still pass.
- Dropped: the ACCEL registry (dev crates/kernels/src/registry.rs) and its fixed.rs and gpu_image.rs modules.

## Proof

cargo test -p daedalus-inventory: registry_rows_point_at_existing_files_and_tests, and the CI accel job (scripts/ci.sh accel) runs the conformance tests on each CPU backend (x86 SSE2 and AVX2, aarch64 NEON, armv7 NEON under qemu, riscv64 RVV at VLEN 128, 256 and 512) and fails if a pass cell is lost against docs/backend-matrix.csv.

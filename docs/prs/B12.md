## Build

- Plan hash: FNV-1a 64 (core stable_id) over the canonical bytes of: the solved graph in the A10 Blob encoding; backend ids and versions; the transfer tables; the config fields in a fixed order; the rewrite ids and versions. No serde_json output goes into the hash, and no hash-map order is used anywhere.
- Plan key: the hash of the input graph and the hash of config plus backend offers. Each cache entry also stores the full key bytes, so a 64-bit collision cannot return a wrong plan.
- Cache: bounded entries with least-recently-used eviction. A hit returns the solved plan. The engine owns the cache instance (C10). This PR provides the type and its keying.
- Diagnostics do not change the key.
- Schema drift: the test compares the graph schema from A6's generator with docs/schema/daedalus.graph.v1.schema.json. Dev's test is the model. The generator and the file belong to A6; this PR only adds the test.
- Dropped: PlannerConfig::stable_hash's serde-based fingerprint. It is replaced by the canonical bytes above.

## Proof

cargo test -p daedalus-planner-tests --test b12_hash_cache --test b12_schema_drift. hash_golden: a fixed three-node graph hashes to a fixed value. Reordering config lists leaves the key unchanged. Changing one const changes the key. Changing a rewrite version changes the key. forced_collision: two inputs stored under one hash with different bytes do not hit. Hit and miss counts are checked. schema_drift: an unlisted field in a fixture schema makes the test fail.

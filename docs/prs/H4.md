## Build

- Crate daedalusd in service/daedalusd. It contains no unsafe code; plugin loading goes through core/loader.
- Config file (TOML): listen addresses (default a unix socket in the runtime directory), plugin directory, max runs, log level. --check-config validates and exits.
- Start: loads every plugin in the plugin directory through G2. A failed plugin is retried on the 8 s capped backoff and never stops the daemon.
- Serves one Host through H3.
- Signals: SIGTERM and SIGINT stop the listeners, cancel and drain runs (C7), then stop plugins once their generations are retired. Exit code 0 on a clean drain.
- Dev's default TCP port 4100 and its CLI-only serve subcommand are dropped in favour of the config.

## Proof

cargo test -p daedalusd --test daemon: start the daemon on a unix socket in a temp directory, load dylib-fixtures, put a graph, start, feed, step, take, reload, stop, then SIGTERM exits 0. --check-config accepts a good file and rejects a bad one with a message.

## Status

Done. `service/daedalusd` is the daemon binary. `cargo test -p daedalusd --test daemon` passes: five tests, three of them unix only.

As built:

- **Arguments:** `--config FILE`, `--check-config`, `--stdio`. With no `--config`, `/etc/daedalusd/daedalusd.toml` is read if it exists, and otherwise every default applies.
- **Config (TOML), every key optional:** `listen` (a list of `unix:<absolute path>` and `tcp:<loopback address>:<port>`), `plugin_dir`, `max_runs`, `connections`, `log_level` (`error`, `warn`, `info`, `debug`). An unknown key is an error. The default listener is a unix socket at `$RUNTIME_DIRECTORY/daedalusd.sock`, else `$XDG_RUNTIME_DIR/daedalusd/daedalusd.sock`, else `/run/daedalusd/daedalusd.sock`. `--check-config` prints what the file resolves to and exits 0, or prints `daedalusd: config: <file>: <reason>` and exits 1. Nothing is bound or opened by the check.
- **Plugins.** Every file in the plugin directory with the platform's library suffix is loaded before any listener opens. One that fails is retried by a background thread on the loader's backoff (250 ms doubling to 8 s), for as long as its file exists: removing the file is how an operator stops the retries. A failure never stops the daemon. `load_plugin` from a client goes through the same loader.
- **Plugin backends.** `plugins.rs` wraps each loader backend as a `Backend` for the planner. It names every port of every node in the region (the boundary, and both ends of each inner edge), since a plugin's steps are one a node, and maps the loader's region-local node numbers back to the graph's. All plugin backends share the memory space `plugin.host`. Loading a name again registers nothing new for nodes the earlier generation declared, and replaces the backend of the same id.
- **Signals.** SIGTERM and SIGINT set a flag (`signal-hook`). The main thread then shuts the host down (listeners stop, runs are cancelled and dropped, watches get `ended {shutdown}`, sessions close after what they are owed is written), waits up to 10 s for the sessions to end, drops the host, and waits up to 10 s for every plugin generation to be released. It exits 0 when both happened and 1 otherwise.
- **Socket activation.** Sockets passed in through `LISTEN_FDS` (`listenfd`) are served in place of the configured listeners, and their files are left for the activator to remove.
- **`--stdio`** serves one session on stdin and stdout, opens no listener, and stops the daemon when stdin closes.
- **Logging** is one line per event on stderr, `daedalusd: <level>: <message>`.

Differences from the brief:

- **Three workspace dependencies are new:** `toml` (the config), `signal-hook` (signals without `unsafe` here) and `listenfd` (passed sockets without `unsafe` here). The crate itself forbids `unsafe`.
- **The daemon's reload test** reloads onto the same graph and then onto a second generation of the plugin. State carry itself is C10's, tested there.
- **On Windows** there are no unix sockets, so a config must name a `tcp:` address, and the three socket tests do not run. The config check and the stdio session do. Windows was only checked by `cargo clippy --target x86_64-pc-windows-gnu`, not run.
- **The socket activation test** runs only where `systemd-socket-activate` is installed, and returns at once where it is not. It starts no unit: the tool passes one socket to the daemon it starts.

Bug fixed in merged code:

- **A loaded graph never released its steps.** `owned_run::RunBuffers` (C1, used by C10's `LoadedHost`) freed the step table without calling each step's `release`, so every stopped or reloaded graph leaked its step data, and a plugin's library could never be closed. `RunBuffers` now releases its steps when it is dropped. `core/host/tests/listen.rs` has the test (`a_run_that_is_reloaded_or_stopped_releases_its_steps`), and the daemon's exit code depends on it.

- `core/runner/src/owned_run.rs`: the fix above.

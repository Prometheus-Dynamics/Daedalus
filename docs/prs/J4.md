## Build

- `core/planner/src/solve/expand.rs` builds each stage of a group with `NodeDoc::new(id)` and copies only the constants. Metadata is lost, so `daedalus.node.fusion` (and `daedalus.node.recovery`, from J1) set on a group instance do not reach the nodes inside it.
- Each stage now inherits the metadata of the group instance it belongs to, and a nested group passes its own metadata down to its stages, so the setting reaches the whole subgraph. A stage that sets its own key keeps it.
- Stage definitions carry no metadata of their own in `GroupDoc`, so inheritance from the instance is the only source. Adding per-stage metadata to `GroupDoc` would change a shared interface and is not part of this PR.
- Leaf nodes already keep their metadata; nothing changes for them.
- The J1 docs get a bullet that a group instance's keys reach its stages.

## Proof

`testing/crates/planner/tests/j4_group_metadata.rs`: a group instance with `daedalus.node.fusion` false and a `daedalus.node.recovery` value expands to stages that carry both keys; a nested group's stages carry them too; a stage's own key wins over the instance's; and a merge that the fusion key forbids is not made (the stages stay in separate steps).

## Status

Done.

- A stage inherits the metadata of the group's own node, through nested groups, as the brief says.
- Stages also have metadata of their own, which the brief left out: `GroupDoc::metadata` (stage name to keys, in graph JSON and its schema) and `GroupDef::metadata` (stage, key, value) for a group on a declaration. The ask was that settings on the nodes inside a group survive expansion, and inheritance alone can't set one stage apart from its neighbours. A stage's own key wins over the inherited one. The plan hash covers the field.
- The sim backend now honours a node's `merges` flag when it merges: a node that opted out is a step alone. It ignored the flag before, so the last proof case could not have been observed on it.
- Proof: `testing/crates/planner/tests/j4_group_metadata.rs`, five cases: inherited keys, nested groups, a stage's own key winning, a declared group's stage metadata, and the forbidden merge not made (one step of three nodes without the key, three steps with it).

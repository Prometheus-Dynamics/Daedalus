## Build

- Backend impl (core/backend trait, A7) with id 'cpu'. memory(): one host memory space. transfers(): none (the host space needs no transfer to itself). can_take(offer): every node that has a CPU body. It never refuses a node it can run.
- The #[node] macro (A9) names the default body path daedalus_cpu_author. That crate exports the body expansion. The macro knows nothing about CPU types beyond that path.
- Per node the body expansion emits one body function and one 'unsafe extern C' wrapper with the Step signature from core/abi (A3): run(data, slots, cx) -> StepEnd. The wrapper reads inputs from its frame by position (D0: inputs in declared order, then outputs; A5), calls the body, writes outputs, and returns Done, Skipped or Fault. The unsafe blocks carry SAFETY comments; cpu-author itself uses no unsafe beyond these wrappers.
- Input rules: an Option<T> input is None when its slot is empty. A required input whose slot is empty makes the wrapper return Skipped. A conditional output (Option<T> return) writes nothing when None.
- Return types: unit, one value, a tuple, or Result<_, E>. E must implement the fixed error trait from A3 (a code and at most 64 bytes of reason). A String or any other allocating error type is a compile error on this path. An Err becomes StepEnd::Fault, with StepCx.at set to the node index and the reason written into StepCx. Nothing is formatted and nothing is allocated.
- State: a node with state(T) gets &mut T from the state slot that C9 owns; the wrapper receives its pointer through the Step data field. Config and const inputs are fixed in the Step data at compile time.
- compile(region) returns Compiled::Steps with one Step per node in region order. UnitInfo lists every declared port of the node, in declared order (D0). Step data points at a static per-node record only for a node with no consts, config or state; any other node gets one per-instance allocation at plan time. Running a Steps form allocates nothing.
- Ctx: a node parameter of type &Ctx is filled by the runner's tick context (its fields are defined by C1, not here). Only nodes that ask for it get it. Chips use their own Ctx type from D5, which has the same shape for the same purpose.
- Dropped from dev and not carried: the NodeHandler trait object, DirectPayloadFn, HandlerRegistry (closures keyed by id), NodeIo input vectors, Payload (Arc<dyn Any>) dispatch, the node_handler low-level attribute (node_handler_impl.rs) and its handler types. The design replaces them with the Steps form.
- Cargo.toml declares every feature the CPU crate will ever use, so later PRs only add files: std (default), alloc, merge, blob, receive, source, tunable, chip, chip-params, f64, defmt. lib.rs declares every module behind its feature: steps and backend always; merge (D2), blob (D3), source (D4), chip (D5) behind their features. A later PR fills in its file without editing lib.rs. source.rs and chip.rs declare their own submodules in the same way (see D4, D5).

## Proof

cargo test -p daedalus-cpu -p daedalus-cpu-author. Nodes with 0, 1 and 3 inputs and outputs run through Steps and give reference values. A steady-state run of 1000 ticks makes zero heap allocations (a counting allocator in the test). The ported cases in backends/cpu-author/tests/ui/ (ok_node, ok_three_ref_params, ok_id_expressions compile; fail_missing_id, fail_id_not_string, fail_unknown_argument, fail_port_ty_and_type_key, fail_fire_mode match the dev .stderr snapshots, changed only for the new paths). A chip-style node with a String error type fails to compile. A node returning Err gives StepEnd::Fault with at set and the reason text. cargo check -p daedalus-cpu --no-default-features passes on the host.

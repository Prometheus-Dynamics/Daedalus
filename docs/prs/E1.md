## Build

- The backend is `#![forbid(unsafe_code)]`. Its unsafe calls live in backends/dma-sys (E9) and backends/vk-sys (E13).
- Instance and device creation happen only under the process-wide driver lock (dev driver.rs:34-97). Make the instance type constructible only while a guard is borrowed, and make `open_device` the only device constructor. Reason, from dev: the Vulkan loader crashed when instance or device creation raced an NVIDIA ICD beside Mesa (3 of 3 segfaults without the lock, 6 of 6 passes with it, commit 5a1404c).
- Wgpu debug labels stay off by default (dev driver.rs:101-106). Labels make every submit call the loader's object-naming path, which races creation. `WGPU_DEBUG=1` turns them on for RenderDoc.
- Adapter choice (dev adapter_select.rs:28-93): score by backend (Vulkan over Metal over DX12 over GL), device type, storage and copy usage. Software adapters (llvmpipe, lavapipe, softpipe, swiftshader) lose to any hardware adapter but stay usable when nothing else exists. The Host reads `WGPU_BACKEND` and passes the choice in as an option; the backend does not read the environment.
- Vendor selection (dev select_wgpu_on_vendor) stays as an explicit option. The blocking `select_backend` and the separate async selector are replaced by one path: a request that opens the device on first use. Dev's rule holds: no context exists before a plan runs on the GPU (commits df05a6f, 26d45bd).
- One device per process by default: the Host shares it, as dev's shared_context does (commit 3eb2f74). A second device opens only when a caller names an adapter.
- Planning opens no device (dev rule, engine/src/engine.rs:632: caps come from a cache, planning opens nothing). `can_take` answers from a caps record keyed by adapter: the device profile and the compute limits, written the first time a device opens. With no record, `can_take` accepts a node whose needs fit GpuComputeCaps::WEBGPU_DEFAULTS, and `compile` decides. A refusal then reassigns the node once, as the design's refusal round says.
- Device profile (dev device_profile.rs:85-115, table at 191-318): vendor ids, tile-based flag (fragment passes win on V3D, see E6), warp width (V3D 16, NVIDIA 32, AMD 64, Bifrost 4 or 8). Rows for Mali, PowerVR, Adreno and Apple stay as data and carry dev's flag that they are unmeasured (device_profile.rs:4-7).
- Compute limits and enabled features are reported from the device (dev compute_caps.rs, wgpu_reports_compute_limits_and_enabled_features). Only the caps record crosses into planning, not the device.
- Backend trait implementation in backend.rs: `id`, `can_take` as above, `compile` returns a Refusal until E5, and `memory` and `transfers` are empty until E2 and E3.
- Not carried: the GpuBackend trait object with its 30 methods, `as_any` downcasts, and the wgpu escape hatches (wgpu_device_queue and friends). Nothing outside backends/wgpu gets the wgpu device.
- scripts/check-gpu-driver-lock.sh is rewritten for backends/. It fails on `Instance::new(`, `.request_device(`, `create_device_from_hal`, `Entry::load`, `Entry::linked`, `create_instance(` anywhere except backends/wgpu/src/driver.rs and backends/vk-sys/src/device.rs. It scans backends, interfaces, languages, service, core, examples and testing, not only crates/gpu (dev's script missed surface).
- Settled: two ways to start. `WgpuBackend::open(options)` finds and opens its own device. `WgpuBackend::adopt(handle)` is given a device someone else set up, and whoever passes the handle owns the rule against racing device creation.
- Settled: the Host only ever receives a finished backend, and the core never sees a device. Opening stays lazy: no device exists until a plan runs on it.
- Settled: `.github/workflows/ci-gpu.yml` installs the lavapipe Vulkan driver and runs the tests of the `backends/wgpu*` crates. Every GPU proof that says "CI, lavapipe" runs there.

## Proof

CI, lavapipe: contexts_open_and_close_on_several_threads (ported from driver_stress.rs; 200 contexts on 4 threads, skips only when no adapter exists, and the lane fails if it skipped everything); the lock-exclusivity test (dev driver.rs driver_lock_is_exclusive_and_send); shared_context_opens_one_device_per_process (ported); a pure table test that a software adapter ranks below a hardware one; a test that planning (can_take on a plan with GPU nodes) creates zero devices (counter), ported from dispatch_and_state_without_a_context_create_no_device; check-gpu-driver-lock.sh with a planted `request_device(` in a fixture file must fail.

## Build

- Scalar kinds: bool, i8, i16, i32, i64, u8, u16, u32, u64, f32 and, behind feature f64, f64. The wire tags are fixed: bool 0, i8 1, i16 2, i32 3, i64 4, u8 5, u16 6, u32 7, u64 8, f32 9, f64 10.
- Conversions follow the planner's ValueType::check_value rules exactly. An integer converts to any integer type it fits, and to a float only when the float represents it exactly. Floats convert to floats. bool converts to bool only. NaN fails the range check. The widening table is tested against the runtime's adapters.
- Tunable (chip/param.rs): set_param(id, Scalar) -> Result<(), ParamError>, param(id) -> Option<Scalar>, and apply_update(&[u8]). ParamError is Type, Range or Id. A new value is used from the next tick (setters take &mut self, so they never run inside a tick). The ParamSpec table (type and range per id) is emitted by source/tunable.rs in the D4 emitter.
- Parameter marking: a graph's node metadata marks tunable constants. The key is renamed from dev's daedalus.mcu.params to daedalus.chip.params. A marked input must be a scalar constant inside its range. Ids are numbered in schedule order, then input order.
- freeze_params (a B13 plan option) turns markers into literals. A graph with no markers yields the same compiled firmware as before: D5's pinned sizes do not move.
- Update messages: postcard (id: u16 as a varint, ScalarKind tag, value) at 3 to 14 bytes. chip/wire.rs is the one hand-written codec for both sides: the device decodes and the host encodes with the same file. No serde on the device.
- Host side (param_host.rs, std): encode an update by parameter name from the plan manifest, with the device's checks applied. This replaces dev's daedalus-mcu param command, which has no binary here.
- f64 feature off: no f64 soft-float is linked. An f64 update to an f32 parameter still converts, in integer arithmetic.
- Dropped: the alloc-only String and Vec<u8> conversions and the separate daedalus-mcu binary.

## Proof

cargo test -p daedalus-cpu --features chip,source. Every scalar kind round-trips through the wire codec. The golden bytes from docs/mcu.md hold: threshold.on = 2.5 (id 1) encodes to 01 09 00 00 20 40. Range and type errors for each kind, and NaN rejected. Converting an integer that does not fit fails. Host and device share one encode and decode (the test calls both). cargo check -p daedalus-cpu --target thumbv6m-none-eabi --no-default-features --features chip,f64 and without f64. The D5 chip size pins do not change.

## Status

Merged. Differences from this brief:

- The scalar kinds are in `backends/cpu/src/scalar_kind.rs`, shared with the blob form, whose numbers were already these.
- `Interpreter` also implements `Tunable`, and `BlobBackend` turns the same markers into `ParamDesc`s, so stored plans have parameters too.
- The host encoder takes the generated module's `PARAM_NAMES` and `PARAMS` as its manifest. There's no separate manifest file.
- `tunable` is on whenever `source` is, so a module with markers always gets its parameters.
- `f64` values convert and compare with integer arithmetic whether or not the feature is on, so there's one code path to test. It's checked against the hardware's result over 400,000 values.
- There's no widening table: this codebase has no numeric adapters to test it against, and a conversion is a registered node.
- `NodeBody` gained `label` and `metadata`, and `Config` and `CompileCx` gained `freeze_params`.

## Build

- `add_worker` starts a worker, reads its hello and checks every node in it against the registry, and a node the registry lacks is refused. So a host had to know a worker's nodes before it had met the worker, and write the declarations out by hand, though the hello already says all of it.
- A second way in registers what the worker declares. The check stays for a node the registry already has.

## Proof

`backends/process/tests/supervision.rs`: a worker started against an empty registry registers every node it declares, with the ports and types a registry written by hand has, and then runs one of them; the same spec again registers nothing; a worker that disagrees with a node already registered is refused by name, as before.

## Status

Done.

- `ProcessBackend::add_worker_declaring(spec, &mut Registry)` returns the ids it registered. Each is an owned declaration whose one body is the process backend's.
- `daedalus_backend_process::type_expr(&WireType)` and `owned_decl(source, &Declaration)` are public: the translation from a hello to a registry declaration. The worker conformance crate had its own copy of the first, which is gone.
- A hello's `config` and `state` aren't carried into the declaration: `OwnedDecl` has no place for them, and `add_worker` doesn't check them either. A worker's config ports arrive as ordinary inputs.
- An opaque type whose key isn't a valid type key is refused, naming the node and the port.

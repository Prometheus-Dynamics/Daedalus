## Build

- Order: Kahn topological sort. Ready nodes are taken lowest index first. Dev pops from a stack, so its order is not stable under reordering of ready nodes; this changes that on purpose. A cycle is ScheduleConflict naming every node left on it, sorted by id.
- Rate: each node has a pair (in, out) of positive rationals, default (1/1, 1/1). A node may declare a ratio p/q (a typed field, A6): out = in times p/q. A node with no inputs has in = 1/1 unless the host bridge declares a rate.
- An edge carries the producer's out-rate. All inputs of a node must carry the same rate. A mismatch is RateMismatch naming the node and both rates.
- Sync groups (core SyncGroup) require all their ports to carry one rate, with the same check. The alignment policy (AllReady, Latest, ZipByTag) is recorded on the solved node for the runner (C4). Nothing aligns data here.
- Output: the solved graph has an order, a rate pair per node and a rate per edge. B8 reads them.
- Dropped: schedule_priority (GPU-first sorting). Placement order is the Host's backend order (B7). Dropped also: the topo_order and schedule_order metadata copies. The order is a typed field.

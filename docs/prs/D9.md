## Build

- wasm32-unknown-unknown: examples/wasm_smoke is a cdylib with no imports. smoke() runs the fan-out graph (x + 1 and x * 2, summed) for 32 ticks in each mode the design has, and returns 0 on success or the 1-based index of the first wrong mode. Expected sum: 3 * 32 * 31 / 2 + 32 = 1520.
- wasm32-wasip1: daedalus-wasi-smoke runs the same smoke on the platform clock under Node's WASI.
- examples/wasm_bindgen_host exports a Pipeline class with push, tick and take over the Host (C10). The clock is injected from performance.now() through wasm-bindgen. tick returns the tick duration on that clock.
- Build with the embedded preset of the facade (C14) without threads, so the wasm build pulls in no thread-only API. A clock is injected; without one, durations are zero.
- Adaptive mode is not in the design. The smoke covers serial and the parallel lanes (C6), which degrade to serial without threads.
- scripts/ci.sh wasm (the function already in dev) is kept with the new package names. The wasm-bindgen CLI version check against Cargo.lock stays. The portability job already calls the wasm subcommand.
- Dropped: the engine-level names (daedalus::engine, RuntimeMode::Adaptive, HostGraph) that the design replaces.

## Proof

scripts/ci.sh wasm: builds for wasm32-unknown-unknown and wasm32-wasip1. node scripts/wasm-smoke.mjs and node scripts/wasi-smoke.mjs each print a result of 1520. The wasm-bindgen host builds and runs under node scripts/wasm-bindgen-host.mjs. The runtime's compile_error for threads on wasm32-unknown-unknown (dev crates/runtime/src/lib.rs) is kept and tested by a compile-fail build.

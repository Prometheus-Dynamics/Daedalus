## Build

- A binary, daedalus-plugin-worker, in backends/process/src/bin/. It takes a plugin path, loads it with G2, and serves the plugin's nodes over G1 the same way a language worker does. Its hello declares the plugin's node records.
- Isolation is per node. A node that a graph isolates gets a worker spec that runs this binary with the plugin path. A node with no spec runs in process as before.
- A plugin crash (abort or segfault) kills only this worker. G4 supervision reports the fault and respawns after the backoff.
- Panics inside nodes are faults, as in G2.

## Proof

cargo test -p daedalus-backend-process --test plugin_worker, with dylib-fixtures built. The dylib-fixtures plugin, run through this worker, gives the same canonical outputs as an in-process load. A fixture node that aborts gives a fault that covers the node; the next run after the backoff succeeds in the same host process.

## Status

Done. `backends/process/src/bin/daedalus-plugin-worker.rs` loads a plugin with the G2 loader, compiles each node once, and serves the nodes over the G1 wire protocol. The host's process backend (G4) supervises it unchanged.

Differences from the brief:

- **Isolation is by spec.** A graph isolates a node by giving it a `WorkerSpec` that runs this binary with the plugin path. Nothing selects that automatically, and a node with no spec still runs in process.
- **Scope of served nodes.** Every node the plugin declares is served, and each is compiled as a one-node region. Plugin nodes with state, config or conversions are not served: the entry does not carry them (see G2 and G3 Status).
- **Port types** come from the plugin's registered type keys. A scalar key maps to its wire scalar, and any other key is opaque. A port with no key is declared opaque with an empty key, which the host registry check then rejects.
- **Crash handling** is G4's: the worker dies with the plugin, the fault covers the region, and the respawn happens after the backoff.
- **`run_step`** is a small addition to `core/loader`. It runs a compiled step, which the worker needs, and keeps the unsafe call in the crate allowed to make it, so the binary can forbid unsafe.
- **Fixture.** `testing/fixtures/dylib` gains an `abort` node, which calls `std::process::abort()`. The loader's node-list test now expects three nodes.

Tests (`backends/process/tests/plugin_worker.rs`):

- The `pass` node through the worker gives the same output bytes as the in-process load of the same library.
- The `abort` node faults its region with "exited mid-run"; after the backoff, the `pass` node runs in the same host and succeeds, with a restart counted.

## Build

- Crate daedalus-capi, built as cdylib and rlib. Unsafe is allowed here, each block with a SAFETY comment.
- The header include/daedalus.h is hand-written. tests/header.rs checks each exported symbol and signature against it, and the header compiles as C11 with -Wall -Werror.
- Handles: opaque u64 with index and generation. Stale and null handles return a status.
- Version: one call returns the ABI major and minor and the layout hash. It replaces dev's version and features data symbols.
- Calls: host_create, host_release (busy while graphs live), host_install (plugin path through G2), host_schemas, graph_compile, graph_release, graph_ports, graph_explain and graph_telemetry. explain and schemas return JSON into a caller buffer, with a size query first.
- IO: push and take by name and by index for i64, f64, bool and bytes; tick; push_batch, checked whole before any push.
- Status codes: one fixed numeric table, with a text name for each.
- Every entry point is wrapped in a catch_unwind guard that turns a panic into a status.
- Dropped: frame push, take and release and dma-buf handling, the daedalus_surface_allocations symbol and the alloc-count feature (counting moves to I2), the in-image export_surface! load-time constructor, and the stable_abi min and max data symbols (folded into version).

## Proof

cargo test -p daedalus-capi. header.rs (exports match the header; C11 compile with -Wall -Werror). c_host: a C program compiles a graph, pushes, ticks and takes. Stale and null handles return statuses. host_release with live graphs returns busy. push_batch with one bad entry pushes nothing. A panicking push returns a status, and a counting allocator shows no leak over 1000 calls.

## Status

Done. `core/capi` (daedalus-capi) builds as a shared library and an rlib, with `include/daedalus.h` written by hand. A C program compiled with `-std=c11 -Wall -Wextra -Werror -pedantic` and linked to the library loads the plugin fixture, compiles a graph, pushes, ticks and takes. Run here on Linux. The C tests are skipped off Unix, and the export check off Linux.

As built:

- **A host made here has no nodes of its own.** `core/` can't depend on a backend, so the nodes and the backends that run them come from plugins: `daedalus_host_install(path)` joins a plugin's nodes and wraps its backends (`daedalus_loader::PluginBackend`, moved out of the daemon in #134).
- **33 functions**, each returning a status, each run under a guard that turns a panic into `DAEDALUS_PANIC`. 18 statuses in one table, numbered from 0 in order, with `daedalus_status_name`. `daedalus_last_error` gives the reason for the last failed call on the calling thread, as text.
- Handles are 64-bit: 8 bits of kind, 24 of generation, 32 of place. A released handle is `STALE_HANDLE` for as long as the process lives, and a made-up one, a null one, or a host's handle where a graph's is wanted is `BAD_HANDLE`.
- Text goes both ways as UTF-8 with a length and no NUL. A call that returns text takes a buffer and writes the length: a null or short buffer gets `BUFFER_TOO_SMALL` and the size.

Differences from the brief:

- **A number goes into any port it fits, not only `i64` and `f64` ports.** `push_i64` writes an integer into a port of any integer type, in that type's width, and refuses one that doesn't fit with `OUT_OF_RANGE`. `take_i64` reads any integer type. The same for `push_f64` and `take_f64` with `f32` and `f64`. Without this the fixture's `u32` node couldn't be reached from C at all.
- **`graph_ports` is three calls**, `graph_port_count`, `graph_port(index)` and `graph_port_index(name)`, not one that returns JSON. A port's index is its place in the ports sorted by name.
- **`graph_telemetry` is a struct of six counters** (ticks, idle ticks, step calls, faults, pushes, takes), counted by the surface. The host's own telemetry levels and events aren't reachable from C.
- `host_schemas` is the registry's nodes as JSON: id, input and output ports with their type keys, and the backends that have a body.
- **A bytes take that doesn't fit keeps the value.** The size is written, the status is `BUFFER_TOO_SMALL`, and the next take of that port gets the same value. So does a take of the wrong kind.
- `push_batch` checks every entry first: port, direction, kind, range. One that fails makes the whole batch `BAD_BATCH` with the entry's position, and nothing is pushed. After the check an entry can still be refused by the graph itself, and then the ones before it stay pushed: that can't be known ahead.
- **"A panicking push" is `daedalus_selftest_panic`**, an exported call that panics on purpose under the same guard as every other call. No push can be made to panic from outside. A node that panics is a different thing and is tested too: the tick reports a fault, and the graph and host stay good.
- "No leak over 1000 calls" is three checks: 1000 warm push, tick and take calls allocate nothing at all, 1000 graphs compiled and released leave no handle live and reuse one place, and the failed compiles leave nothing.
- **The header check is a table, not a parse of the sources.** Each function is assigned to its Rust type, the header must hold its C prototype exactly and declare nothing else, the built library's dynamic symbols must be exactly the table's names, and the structs' sizes are asserted in C against Rust's.
- **Only `u32` values run end to end**, since that is the fixture's node. The float, bool and bytes paths are tested for what they refuse and for their encoding, not through a graph.
- Reloading a plugin on a live host follows the loader: a graph compiled before keeps its library. It isn't tested through the surface.
- There is no example under `examples/` for it yet. `tests/c/host.c` is the worked C program.

## Build

- A region's Step returns StepEnd::Pending(Fence) carrying the wgpu submission index. The Runner (C2) polls it with a non-blocking poll on each tick. A tick never waits.
- In-flight limit: dev allowed 2 submissions per device, and blocked on the oldest when a third arrived. Here the Step returns Pending on the oldest instead. The limit of 2 stays, as a hidden setting.
- Bounded waits: any wait the backend itself needs (setup, shutdown, tests) uses a bound. The default is 5 s (dev wait.rs; `DAEDALUS_GPU_WAIT_TIMEOUT_MS` moves to Host settings). A timeout returns a Fault and marks the device lost (E11).
- Uncaptured errors: the device's error callback stores messages (cap 16, joined). The next region Step that dispatched work returns a Fault, so a node never uses output the driver flagged as suspect (dev wait.rs:45-76, commit 5100c74).
- Dropped: poll_driver.rs, the thread pool with 2 shared workers and 2 overflow threads. No thread polls the device. A bounded wait runs on the caller's thread during setup or shutdown only.
- Dropped: GpuInFlight and its latest-wins drop_oldest policy. That is a node-level policy and belongs to C4 backpressure. The ticket type becomes the Pending fence.
- Timers (dev gpu_timer.rs): timestamp queries where the device has them, otherwise submit-to-done. GpuTimeSource says which one was used. The duration reaches telemetry (C11).
- scripts/check-gpu-async-blocking.sh is rewritten for the new design: it fails on any `PollType::Wait` or `pollster::block_on` in backends/wgpu/src outside wait.rs and setup modules.

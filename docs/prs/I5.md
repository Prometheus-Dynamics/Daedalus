## Build

- Write the docs fresh for the design's terms: Backend, Offer, Region, Compiled, plan forms (Steps, Blob, Source), Host feed/step/take, the failure rule, control regions. Use the names the code uses, and do not cite dev paths as the way to do things.
- docs/migration-from-dev.md is one page: a table from each dev crate to the next crate or PR ID that replaces it. It is for the owner and for anyone reading dev, not a user guide.
- Dropped docs: api-review.md (review notes for dev's API), accelerator-interface.md (replaced by the Backend trait; the NPU case is I1), host-bridge-lock-granularity.md (the host lock design is replaced by C3), benchmarks-log.md (history stays on dev), migration-4.0.md (dev-to-4.0 notes; no 4.0 release is planned here), shared-library.md (folded into docs/plugins.md and the C surface doc from G10).
- docs/backend-matrix.md and docs/accel-evidence are generated by D8 and are not written here.
- scripts/ci.d/doc.sh runs cargo doc --workspace --no-deps with RUSTDOCFLAGS set to -D warnings, and a link check over docs/ that fails on a relative link that does not resolve.
- No product names beyond what is needed to point at dev. No marketing.

## Build

- Scope: a control node with one of three operators. Nothing else. Dev has no control flow, so nothing is ported. Its embedded-graph expansion is a reference for body handling only.
- A control node holds named body graphs. A body is closed: it reaches the outside only through its declared ports.
- if: inputs cond (bool) and any number of value inputs. Bodies then and else take the same value inputs. The node's outputs are the outputs of the branch taken. Both bodies must declare the same output names and types (TypeMismatch otherwise).
- for_each: input list (a list of T). The body takes item (T) and produces out (U). The output out is a list of U in input order. Runs one body per element, in order. An empty list gives an empty list and runs no body.
- until: input init (S). The body takes state (S) and produces state (S) and done (bool). The body repeats until done is true. The output state is the last state. A required integer max (1 to 65535) bounds the loop. Reaching max is a Fault, reported with covers. The loop never stops silently.
- Lowering: each body is planned as its own graph (B1 to B9, recursively) and compiles to a nested step list. The control node is a single-node region on a built-in control backend. Its unit is a Steps unit whose step runs the nested lists: if runs the taken list, for_each runs one list per element, until runs the list until done or max.
- The control backend is built in. It has the host memory space only, and it takes control nodes only. It has no hardware or media meaning.
- A body edge that reaches outside the body is a planning error naming the body and the port.
- The control node follows the ordinary region rules (R1 to R5).

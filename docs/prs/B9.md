## Build

- Memory per value. A region output lives in its producer backend's home space: the first entry of that backend's memory() list. A consumer region reads from the first space its backend lists as readable. If the producer's space is readable by the consumer, the value does not move. This is dev's rule that a producer stays on its device.
- Transfers. When no shared space exists, find a path through the transfer table (A7) from the producer's space to a consumer space. Minimise total cost, then hops, then the lexicographic order of space ids. One transfer per (value, destination space): consumers in the same space share it. No path is NoTransfer, naming the port, the producer space and the consumer space.
- Slots: each live (value, space) pair gets a numbered slot. A slot is freed after its last reader step. A new value takes the lowest free index. The slot count equals the peak number of live values.
- Fences: a unit that may return Pending gets a Wait item before its first reader in another region. The wait names the producing unit's index. Readers in the same region need no wait.
- Layout: the flat list is written in region order, and each region's units in their order. A transfer sits just before its first reader. A wait sits just before its reader. Items: Run {region, unit, covers}, Move {from_slot, to_slot, transfer}, Wait {unit}. Every node of every region appears in some Run's covers.
- Output format: the A10 step list and slot table. This PR fills them.
- Dropped: gpu_buffers and EdgeBufferInfo (buffer ids for GPU chains). Slots replace them. The GPU chain rule is not a planner concept.
- Settled: same memory space means producer and consumer share one slot, and no step is inserted.
- Settled: the planner computes each value's consumer count. One consumer: ownership moves and no reference count is touched. Several consumers: the extra retains happen once, at the producer's output.
- Settled: the handler for a move is looked up by (type key, from, to), then an any-type transfer. Choose the path with the lowest cost class (`Handoff`, then `Import`, then `Copy`), then fewest steps, then id. No path: planning fails, naming both ports and both spaces.

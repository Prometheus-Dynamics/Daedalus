## Build

- Module core/host/src/listen, behind the feature listen. C10 should declare it in core/host/src/lib.rs. If C10 did not, this PR adds that one line and nothing else to lib.rs.
- Transports: unix socket, TCP on loopback, and stdio (one session on stdin and stdout, dev's default mode). A remote, non-loopback address is not offered.
- One Host per listener, shared by every session. Dispatch maps each H1 op to the C10 and C3 API. Each dispatch is panic-guarded and a panic becomes an error response.
- Ownership: graphs and runs belong to the Host, not to a connection. A closed connection does not stop its runs; its watches end.
- A session has a bounded outbound queue. A client that stops reading is disconnected; a Host step never waits on a client.
- Concurrent sessions. Dev's one-client-at-a-time TCP loop is dropped.
- Accept errors back off with the 8 s cap. The default connection limit is 64.

## Proof

cargo test -p daedalus-host --features listen --test listen. Two clients on one Host: client A's run is visible to client B. A disconnect leaves the run running. A client that stops reading is disconnected without stalling step. Stdio session round-trips a graph. Accept backoff stays within the cap.

## Status

Done. `daedalus_host::listen` (feature `listen`) serves one host to many clients over a unix socket, loopback TCP and stdio. `cargo test -p daedalus-host --features listen --test listen --test listen_wire` passes: fourteen tests, against a backend written in the test on `OwnedStep` (a core crate can't use a real one).

As built:

- **`ServiceHost` is the host.** On `next` a `LoadedHost` is one loaded graph, so the thing every session shares is a `ServiceHost`: the registry, the backends, the stored graphs (by session name, then graph name), the runs (each a `LoadedHost`), the plan cache, the watches and the trace. `ServiceHost::builder(registry).backend(..).plugins(..).codecs(..).options(..).build()` makes one, and any number of listeners can be opened on it.
- **Runs are stepped by `step` requests.** A run is not ticked by a thread of its own: C10's `start()` stream is not used. "A run outlives its connection" means the run, its queued values and its state stay in the host, and any client can step, feed, take, inspect and stop it.
- **Dispatch.** `load_plugin` goes to a `PluginLoader` the embedder supplies (H4 supplies one over the loader). A host without one answers `unsupported` and leaves the op out of its hello. `put_graph` stores any document that parses and returns what solving and linting it found. `patch_graph` also reports each selector that matched nothing. `plan` caches the summary by plan key, and `cached` says a summary came from there; a plan asked for with `inspect` is always planned, since the explanation is made from the plan. `start` and `reload` plan in the steps form each time, because a plan's steps can only be taken once.
- **Cancel** is per run and permanent: the run takes no more feeds or steps, and still answers take, inspect and stop. A tick in progress on another connection stops through the run's cancel word (C7), so a body that checks `cancelled()` stops inside the tick.
- **Stop.** `drain` ticks until a tick finds nothing to do, at most `drain_ticks` (10,000) times, then removes the run. `immediate` removes it at once. Both report how many values were left in the run's ports.
- **Events.** A `fault` event is sent for each step that failed in a tick, and one `telemetry` event per `step` request with that batch's totals. `ended` is sent when a run is stopped or cancelled, when a watch is unwatched, and at shutdown.
- **A client that stops reading** is disconnected when 256 answers wait for it (`outbound_queue`), or when a write to it has blocked for 10 s (`write_timeout`, a socket option on unix and TCP connections). Watch events never count toward the queue: each watch holds 64 and reports `lagged`. Nothing that runs a graph writes to a client.
- **The connection limit** (64) is enforced after the hello: the client is sent a `busy` error response in place of the server's hello and the connection is closed. A hello with another version or layout gets `unsupported` the same way.
- **Values.** `WireCodecs` maps a type key to a wire type and both directions. Every scalar is built in. A port whose type key has no codec is refused with `unsupported` on feed and on take, and a take is refused before the value leaves the port.

Differences from the brief:

- **Two files more than listed** in `src/listen`: `runs.rs` (a run and its tick) and `values.rs` (the wire codecs). The tests are `tests/listen.rs`, `tests/listen_wire.rs` and `tests/listen_support/mod.rs`, to stay under the file size limit.
- **A panic in a dispatch is answered with `invalid_request`** and a message that says the op panicked. The closed code set has no code for a fault of the host's own.
- **`unmerged`** is a start setting: the run is planned with merging off, and reloads keep it. There is no op to switch a running run.
- **Telemetry over the wire** is the run's totals and, at the detailed level and above, one row per step with the nodes it covers. Tick timings and the trace-level event log are not sent.
- **`plan` in the blob and source forms** returns the summary. The bytes and the generated text are not sent: no reply carries them.
- **The accept loop** takes its wait as a function, so the test runs twelve failed accepts without waiting: 50 ms doubling to 8 s, then 8 s each.
- **Not run here:** the 10 s write timeout on a real socket. The test drives the same path with a writer that returns `TimedOut`.

Changes outside `core/host/src/listen`:

- `core/runner/src/owned_run.rs`: `CancelHandle` and `RunBuffers::cancel_handle`. The cancel word is now held in an `Arc`, so a handle to it can be kept by another thread. `LoadedHost::cancel_handle` returns it.
- `core/client`: `Client::close`, which drops the connection for every handle.
- `core/host/Cargo.toml`: the `listen` feature, the optional `daedalus-wire` dependency, and `daedalus-client` as a dev-dependency.

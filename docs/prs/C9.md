## Build

- Node state is owned by the step's data (the backend sets it up). It is typed and dropped with the step. The runner never reads it.
- The host StateStore (alloc) maps a node id (A4) to typed state slots: native get and set by type, plus a serde JSON access behind a std feature. The store is read and written between ticks only.
- Managed resources (dev with_node_resource and its restore on reload) carry over. A resource is dropped exactly once.
- Config: const inputs are decoded once at load. They are decoded again only on a const patch (C23). A dynamic config input (fed over an edge) keeps its last decoded value and the input version it came from, and decodes again only when that version changes. Equal values are not decoded again (dev test re_emitted_equal_config_value_is_not_decoded_again).
- Snapshot: JSON of the store, std only, with a round trip.
- Do not carry: state access in the tick path, serde in any core crate, and the custom-metric drain (it moves to C11).

## Proof

core/host/tests/state.rs ports state_tests.rs, the const_cache tests (config is decoded again only when an input changes; an equal re-emitted value is not decoded again), snapshot_round_trip, and the stateful isolation cases (same-id stateful instances count independently). A counting Drop type shows a resource dropped exactly once.

# D0: Per-step cells: a step sees its own inputs, then its outputs

**Group:** D. CPU backend and chips

**Wave:** 14

**Needs:** B9, B10, C1

**Runs:** cloud

Read `AGENTS.md` and `docs/design.md` first.

## Why

Stitching comes after compiling, so a compiled step can't know plan-wide slot numbers. D1's wrappers
need a fixed place to find each port.

## Build

- A step's `Slots` holds the cells for `UnitInfo.reads` in order, then `UnitInfo.writes` in order.
  Index 0 is the first input. The step holds no slot numbers.
- `NO_SLOT` (`core/abi`) in a plan's slot list marks a port with no edge. An input reads as empty.
  An output is thrown away and released once.
- `cells` is scratch memory sized to the step with the most ports, one per worker.
- The runner stamps each output at publish from `Runner::set_stamps`, since a step can't know plan
  type and space numbers.
- A unit must name every boundary port of its region and may name ports inside it. A named port on
  an edge inside the region gets a slot in the region's memory.
- Control nodes use the same contract. The step that bound slot numbers after stitching is gone.

## Proof

`core/runner/tests/positions.rs`: order, an input with no edge, an output with no edge released
once, stamps. `testing/crates/planner/tests/d0_positions.rs`: per-node steps in one region share
slots, unwired ports are `NO_SLOT`, and an edge inside a region moves nothing. Merged-unit layout
goldens are unchanged.

## Build

- Crate daedalus-registry (core, not heap-free: the registry itself is built at host start). The const records it reads are heap-free, so they can live in statics on any target.
- Shared declaration, one per id: pub struct NodeDecl { pub id: &'static str, pub at: SourceAt, pub summary: &'static str, pub inputs: &'static [PortDecl], pub outputs: &'static [PortDecl], pub config: &'static [ConfigDecl], pub fanin: &'static [FanInDecl], pub fire: Fire, pub reusable: bool }. Fire is Any or All (dev's NodeFire); C4 runs it. SourceAt(pub &'static str) is "file:line", written by the macro with file!() and line!().
- pub struct PortDecl { pub name: &'static str, pub ty: TypeRef, pub access: Access, pub optional: bool, pub conditional: bool, pub default: Option<Literal>, pub label: &'static str, pub unit: &'static str, pub group: &'static str, pub advanced: bool }. TypeRef is Key(TypeKey), Expr(TypeExpr), or Body: the type is not in the attribute and the body supplies it (shader ports, B-group checks). Access is daedalus_value::Access. conditional is set for Option outputs; optional for Option inputs (dev's PortDecl::optional).
- ConfigDecl { pub name: &'static str, pub ty: TypeRef, pub fields: &'static [PortDecl] } for config types (A13 fills fields). FanInDecl { pub prefix: &'static str, pub start: u32, pub ty: TypeRef } for indexed fan-in ports (dev's FanInDecl).
- Per body: pub struct BodyRecord { pub backend: &'static str, pub at: SourceAt, pub needs: &'static [&'static str], pub state: Option<StateDecl>, pub ports: &'static [(&'static str, TypeRef)], pub code: &'static (dyn core::any::Any + Sync), pub text: &'static str }. needs lists the backend's own requirements as text; the backend reads them in can_take. StateDecl { pub size: usize, pub align: usize, pub name: &'static str }. code is the backend's own payload (a fn pointer, a generated stub); text is source for text bodies such as WGSL.
- The record: pub struct NodeRecord { pub decl: &'static NodeDecl, pub body: BodyRecord }. A #[node] emits one of these as a const (A9). Records are only ever read.
- Join, as the design table says. A new id creates the entry. A known id with an equal declaration and a new backend adds a body. A known id with a different declaration is RegError::DeclConflict naming both SourceAt values and the first differing port. A known id and backend already present is RegError::DuplicateBody naming both places. Equality of declarations ignores at. A body whose TypeRef is Body fills the port type on first join; later bodies must agree, or it is a conflict.
- Registry API: pub struct Registry (BTreeMap by id) with new(), register(&mut self, &'static NodeRecord) -> Result<(), RegError>, register_all(&mut self, &[&'static NodeRecord]) -> Result<(), Vec<RegError>> (collects every error), entry(&str) -> Option<&Entry>, entries() sorted by id, and offer(backend: &str) -> Offer-building helper for A7. Entry { pub decl, pub bodies: Vec<&'static BodyRecord> } with bodies sorted by backend name. Registration order does not change the result: the test permutes the input and compares snapshots.
- Conversions: pub struct ConversionRecord { pub id: &'static str, pub from: TypeKey, pub to: TypeKey, pub cost: u32, pub lossy: bool, pub body: BodyRecord } and a Conversions table joined the same way. The path search (B4) reads this table. Dev's ConverterGraph and resolve are not carried here; B4 writes the search.
- Types: pub struct TypeRecord { pub key: TypeKey, pub expr: TypeExpr, pub at: SourceAt } and TypeTable with a conflict error when one key has two different expressions (dev's TypeConflict). Named types with HostExportPolicy (dev named_types.rs) are not here: host export is C10.
- Errors: RegError with variants DeclConflict, DuplicateBody, UnknownBackend, TypeConflict, InvalidId. Each names the id and both places. No Display text is built on the heap-free path.
- Dropped here: feature flags on nodes, types and conversions (dev's snapshot_filtered), dev's overloads metadata (daedalus.overloads: the planner reads it but nothing on dev writes it), and capability strings on nodes (replaced by body needs).
- Settled: the registry also accepts owned declarations a worker sends at start (G1), not only compiled-in records.
- Settled: the declaration has `shareable`, and group bodies held as typed graphs. A conversion record is a one-in, one-out node marked as a conversion. There is no NoOp execution kind.
- Settled: memory space belongs to the body, not the declaration. The type on a port is shared by every body; where it lives depends on which body runs. The default is the backend's own space.

## Proof

Tests in core/registry/tests: the join table (new id, same decl and new backend, conflicting decl naming both locations and the port, duplicate backend), order independence (permuted inputs give equal snapshots), a body with TypeRef::Body fills the type and a later disagreeing body conflicts, conversion table joins, TypeConflict. Each test builds its NodeRecord values as const items, as A9 will.

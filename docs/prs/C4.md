## Build

- Each step carries its fire mode and its required input slots (from the plan). Two modes, as on dev: All (fire = all) and Any (the default).
- All: the step is called only when every required input slot has an unconsumed value. Otherwise the step is not called and its inputs stay queued across ticks. This is the cross-tick join.
- Any: when a required input is missing, the step is not called and the values that did arrive on the other inputs are dropped (consumed), as on dev (test any_drops_what_arrived_when_skipped). Keep that behaviour; do not change it to waiting.
- Optional, fan-in and undeclared inputs never block a step.
- Held (sticky) host inputs: a HELD slot keeps its value until a feed replaces it or the host clears it. A held slot counts as present. A feed to a held port replaces the value and does not wake consumers by itself, because held values are context and not work.
- Fan-in: ports named prefix plus index (ins0, ins1, ...) are ordered by numeric suffix. The order is computed at load and stored in the plan; no sorting in the tick.
- The join check is one test per required input and is skipped when a step has none.

## Proof

core/runner/tests/join.rs with plain-function steps: All joins producers at different rates across ticks; Any drops the arrivals of a skipped tick; FIFO pairs values in arrival order; a held value reaches every tick until replaced or cleared; an unconnected optional input runs with none; fan-in order follows the numeric suffix. The dev test files above are the spec and are ported to the new runner when D1 lands.

# A15: #[transfer]: a memory handler in one function

**Group:** A. Foundation

**Wave:** 7

**Needs:** A7, A9

**Runs:** cloud

Read `AGENTS.md` and `docs/design.md` first.

## Creates

- `core/macros/src/transfer.rs`
- `core/macros/tests/transfer.rs`
- `core/macros/tests/ui/transfer/`

## Read on dev

Nothing to port.

## Build

- `#[transfer(from = <space>, to = <space>, cost = handoff | import | copy)]` on a function from `&T` (or `T`) to the output type. It emits one constant transfer record, listed by hand beside `NODES`, so it works with no heap.
- The function may take the destination backend's context as a second argument, through the authoring-crate contract from A9. The macro names no backend.
- `T`'s type key comes from the Rust type, as for a port.

## Proof

Compile-pass and compile-fail tests with trybuild: a missing `from`, an unknown cost, and a function with no output. A record built this way joins the registry beside a hand-written one, and generated code builds `no_std`.

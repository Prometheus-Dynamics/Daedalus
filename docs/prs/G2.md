## Build

- Entry: each plugin exports one symbol, daedalus_plugin_entry, which returns a repr(C) PluginEntry: the core/abi layout hash, node records, backend tables and conversion records. The loader reads the layout hash first and refuses a mismatch that names both hashes, before reading anything else. There are no version symbols, no handshake symbol and no version branches.
- Backend table: a repr(C) BackendTable with id, can_take, compile and release. compile gets a RegionView (node ids, port types, boundary slots) and returns Compiled::Steps. release drops plugin-owned step data. core/abi/src/backend.rs is a new module in A3's crate; this PR adds it and its layout entries.
- Steps: a plugin's steps are A3 Step values (run and data). The export macro wraps every generated run in a panic guard. A panic returns StepEnd::Fault with the node set through StepCx. No panic crosses the extern C boundary.
- Loader: opens with libloading, resolves the entry, copies every string into host-owned storage at load, and places the library in a generation. Unsafe code is allowed only in this crate, each block with a SAFETY comment.
- Records join the registry through A8. A record with an existing id must have the same declaration; a plugin that brings a new body for a known id joins it.
- Failure rule: an open or check failure is a typed error. Retry is a backoff capped at 8 s that never stops on its own; an operator can stop retries by hand. No automatic off.
- Reload: loading a new library for the same plugin name creates a new generation. The old generation is retired when its last step data is released. The state carry rule belongs to C10.
- What goes away: the Rust-ABI install path (InstallPath::RustAbi, check_rust_abi, install_into_as), fingerprint.rs, crate_builds.rs, boundary.rs, the boundary and foreign-interface descriptor fields, the four-function StableHandlers table (version, create, invoke, release, unload), StableExtension v4 to v7 and their version gates, LIVE_OBJECTS, the daedalus_plugin_stable_version data symbol, the optional daedalus_plugin_stable_abi handshake, the frame v2 adapter, the hand-written SHAPES list in stable/layout.rs (layout hashes come from the repr(C) types), and the lemnos-abi dependency (its layout_hash, AbiVersion, Status and Handle are replaced by core/abi). Per node there is no vtable: one Step and its data.
- testing/fixtures/dylib is a cdylib with the plugin nodes the tests use, built from its own Cargo.toml and not by the root workspace.
- Settled: step data is released through `Step.release` (A3). `BackendTable` has no `release`.
- Settled: this PR is the one exception to "shared interfaces change only through A-series PRs". It adds `core/abi/src/backend.rs`, adds its shapes to `SHAPES` and re-pins `LAYOUT_HASH` in `core/abi/tests/abi.rs`.
- Settled: nothing that isn't `repr(C)` crosses, so `Compiled` doesn't. `RegionView` is `repr(C)`: node indexes and their ids as pointer-and-length, and `BoundaryPort { node: u32, port: u16, reserved: u16, type_index: u32, slot: u32 }` arrays for inputs and outputs. `compile` and `can_take` write into buffers the host owns, with the capacity and written-length pattern of `write_out` (A3). A plugin never hands the host memory to free, and steps are freed by `Step.release`. A plugin's backend produces steps only. Blob and Source forms need an in-process backend.
- Settled: the fixture lives at `testing/fixtures/dylib`, outside the workspace globs, and its `Cargo.toml` has an empty `[workspace]` table so it builds on its own.

## Status

Done for the host side. `core/loader` (daedalus-loader) opens plugins, checks them, joins their nodes into a registry, compiles and runs their steps, and retries loads. Its tests pass, and the fixture is built and loaded by them. The board run is written to `testing/board-runs/G2.md` and has not been run.

Shared interfaces changed, as the brief allows for this PR:

- `core/abi/src/backend.rs` is new. It holds `Text`, `PortC`, `NodeC`, `BoundaryPort`, `RegionView`, `UnitOut`, `BackendTable`, `PluginEntry`, the `CanTakeFn` and `CompileFn` and `EntryFn` types, and `ENTRY_SYMBOL`. Each shape is added to `SHAPES`, and `LAYOUT_HASH` is re-pinned in `core/abi/tests/abi.rs` to `14163395766266215545`.

Differences from the brief:

- **The layout check.** The entry is `daedalus_plugin_entry(host_layout, out) -> Status`. The loader passes its own hash. A plugin with another layout writes only its own hash into the first field of `out`, which is at offset zero in both builds, and returns `VERSION_MISMATCH`. The host reads that one field and refuses, naming both hashes. The host reads nothing else from a struct it cannot trust. The brief said only "before reading anything else", and this is how that is done without a second symbol.
- **Units are per node.** A backend's `compile` returns one `UnitOut` per taken node: a step and the index of the node it runs. The loader fills each unit's `reads` and `writes` from the boundary ports that name that node. The brief's "merged" or multi-node units are not carried. Merging belongs to a backend that can merge, and this plugin contract does not yet offer it.
- **Not carried: conversions, config ports and state.** `PluginEntry` has no conversion records, and `NodeC` has no config or state. `OwnedDecl` (A8) has no field for them, so a plugin node joins with its ports only. Config and state on plugin nodes come with the state carry rule (C10) and the typed ports of G3.
- **The compile-time port check is not here.** The brief's trybuild test ("a node with an unsupported port type fails to compile") belongs to the `#[node]` macro (A9). A plugin's port types are type-key strings here, so an invalid key is a typed `LoadError::BadText` at load, and nothing is checked at compile time.
- **The fixture** has one backend, `fixture.cpu`, with two nodes: `fixture.pass` forwards its input cell, and `fixture.boom` panics. It is built by `testing/fixtures/dylib` on its own, outside the workspace. The loader tests build it with a nested cargo into `CARGO_TARGET_TMPDIR`. Up to eight backends per plugin are supported, but only one is exercised.
- **Re-joining the same body is a duplicate.** A8 rejects a second body with the same backend for one id (`DuplicateBody`), and the test asserts that error. A new body on another backend joins the same id, under A8's rule. That second case is not tested here.
- **Retry takes a stop flag and a sleep.** `load_with_retry` checks an `AtomicBool` before each attempt and calls a caller-supplied `sleep` with each delay. It does not sleep itself. The backoff starts at 250 ms, doubles, and never exceeds 8 s. Nothing turns a retry off except the flag.
- **Leaks.** A8's `register_owned` promotes each declaration with `Box::leak`, and the entry leaks its node and backend tables once per load. Each reload leaks its declarations. That is A8's design, and a host that reloads often will grow. Recorded for the reload work.
- **Generations.** A generation is an `Arc<Generation>` held by the plugin and by every step it compiled, through a `Pinned` wrapper that forwards to the plugin's step and releases it on drop. The library closes when the last of them goes. The test `a_reload_is_a_new_generation_...` checks that the probe stops upgrading once the steps are released.
- **Unsafe.** `core/abi/src/backend.rs` has one unsafe fn (`Text::as_str`) and two unsafe impls, each with a `SAFETY` comment. `core/loader` has all its unsafe blocks in `open.rs`, `records.rs`, `entry.rs` and `export.rs`, each with a comment, and the plugin macro writes `unsafe` in the plugin's own crate, as the brief allows.

Tests (`core/loader/tests`): the declaration and registry join, a node run through its compiled step, a panicking node as a fault with the host still serving, the layout refusal before any record is read (called directly with the wrong hash), a missing plugin retried with growing delays until it appears, a failed reload that leaves the old library serving, stopping by hand and resuming, a reload as a new generation retired with its last step, a non-library file as a typed error naming the path, the backoff cap, and the allocation count on a warm tick (`alloc.rs`, counting allocator: zero).

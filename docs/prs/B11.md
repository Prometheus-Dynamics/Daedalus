## Build

- Diagnostic: one code enum (non_exhaustive) and one struct. Codes cover every error from B1 to B10. Each stage's error type converts with From. Keep dev's codes where they still fit (NodeMissing, PortMissing, PortExtra, PortDuplicate, ConverterMissing, TypeMismatch, ScheduleConflict, AccessViolation, LintWarning). Dev's bundle() for editors (MissingNode, MissingPort, MissingGroup, TypeMismatch lists) stays.
- Severity is error or warning. Only errors stop planning. Warnings come back with the plan.
- Lints, off unless config enables them: unconnected required input; unused output; exclusive access on a fanned-out source; fire-all node whose input may not produce (dev lint_fire_modes). Each is LintWarning with the rule name in a field.
- Explain: a typed record. Per node: backend and reason (forced, only candidate, or chosen with crossings and rank). Per edge: conversion path and transfer path. Per region: nodes, rate pair, boundary ports. Per unit: covers. explain_plan returns it. No metadata strings are parsed.
- JSON: the explain record and the plan serialise to JSON. plan_dump reads a graph file and prints the explain record. debug::from_json reads a plan back, for tests.
- Dropped: the metadata-string round trip in explain.rs (its parse functions) and the metadata keys PLAN_APPLIED_LOWERINGS, PLAN_EDGE_EXPLANATIONS and PLAN_OVERLOAD_RESOLUTIONS.

## Proof

cargo test -p daedalus-planner-tests --test b11_lint_explain. One fixture per lint rule: a planted violation gives exactly one LintWarning with that rule name. With lints off, the same graphs give none. The explain record for the three-backend fixture of B7 equals testing/crates/planner/fixtures/explain_three_backends.json byte for byte. A plan with only warnings returns Ok.

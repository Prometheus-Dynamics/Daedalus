# J9: A panic's message is the fault's reason

**Group:** J. After the plan

**Wave:** 22

**Needs:** A3, G2, G9

**Runs:** local

Read `AGENTS.md` and `docs/design.md` first.

## Creates

- Nothing new. Changes `core/abi/src/guard.rs`, `step.rs` and `step_cx.rs`, and each place a panic is caught.

## Read on dev

- No dev file.

## Build

- A node that panicked gave a fault that said nothing of why: no reason at all for a node in the host's own process, and the fixed text "node panicked" for a node in a plugin or a Rust worker. Whoever reads the fault needs what the panic said.
- One helper reads a caught panic's message, and every place that catches one uses it.

## Proof

`core/abi/tests/abi.rs`: a panicking step's reason is `panicked: ` and its message, for a plain and a formatted message; a panic that carries no text says so; a long message is cut to the reason's room on a char boundary; a node the body named before it panicked stays named. `core/loader/tests/loader.rs`: a plugin node's panic reaches the host with its message and its node. `languages/rust/tests/serve.rs`: a worker node's panic is sent as `node_panic` with its message.

## Status

Done.

- `daedalus_abi::panic_message(payload)` gives the text of a caught panic. `guard_step(cx, body)` runs a step's body and turns a panic into a fault with that text, through `StepCx::fault_panic`, which writes `panicked: <message>` into the reason with no allocation.
- Used by every step (`Step::of` and `Step::boxed`), the plugin side's node guard, the stream worker (`the tick panicked: ...`), the service dispatcher and the C surface. The last two had their own copies of the same lines, which are gone.
- The Rust worker SDK doesn't depend on `daedalus-abi`, so it reads the message itself and sends `node panicked: <message>`.
- Targets without `std` build with `panic = abort`, and are unchanged.

## Build

- 1 Offers. Take the backends in Host priority order (rank 0 is highest). Give each backend an Offer holding the nodes that have a body for it (A8 bodies). Call can_take. Candidate(n) is the list of backends that take n, in rank order.
- Host bridge nodes are not offered. They are fixed on a pseudo-backend named host. Their edges count as crossings like any other.
- 2 Forced placement. A node with a forced backend (an A6 field) has Candidate(n) intersected with that backend. A forced backend that has no body for the node is ForcedUnknown. A forced backend that has a body but does not take the node is ForcedUnavailable, listing every body and whether it took the node.
- 3 Empty candidates: NodeUnplaceable, listing every body and its status.
- 4 Crossings. For each output port P of producer u, count the pairs (P, b) where b is not a(u) and some consumer of P is on b. The total is the sum over all ports. Pairs are counted, not edges: a value is sent to a backend once, however many consumers read it there.
- 5 Objective: minimise (crossings, rank_sum), where rank_sum is the sum over all nodes of the rank of a(n). Among assignments equal on both, take the one whose rank vector is lexicographically smallest in node index order.
- 6 Components. Free nodes have two or more candidates. Two free nodes are coupled when an edge joins them, or when both read the same output port. Fixed nodes are constants. Each coupled component is independent: solve it alone and add the results.
- 7 Search. Depth-first over a component's nodes in index order, trying candidates in rank order. Keep the best (crossings, rank_sum) found so far. Prune a branch when its committed pair is at least the best pair. Both committed values only grow as nodes are assigned, and DFS visits assignments in lexicographic order, so the first leaf that reaches the minimum is the lexicographically smallest optimum.
- 8 Incremental cost. When x is assigned and produces port P, add the number of backends b other than a(x) on which an already-assigned consumer of P sits. When x consumes P from producer u, increment the consumer count for (P, a(x)). If u is assigned, a(x) differs from a(u), and that count was zero, add 1. Undo on backtrack.
- 9 Budget: ASSIGN_BUDGET = 1,000,000 expansions per component, a constant, overridable in config for tests. Exceeding it is AssignmentBudget, naming the component's nodes and asking for forced placements. No approximate answer is returned.
- 10 Output: a backend for every node, and a reason: forced, only candidate, or chosen (with its crossings and rank).
- 11 Determinism: same graph, offers and host order give the same result. The search uses no hash maps.
- Dropped: ComputeAffinity and its three values (the design has no soft preference), GpuPlanCaps, GpuCaps and enable_gpu (a backend's can_take answers for itself), the gpu pass, gpu_segments.rs, Graph::gpu_buffers, the PLAN_GPU_* metadata, use_cpu_fallbacks (no swap by node id: a CPU body is offered to the cpu backend), and device_from (the host sets a forced backend before planning, see B13).

## Proof

b7_assign.rs, named worked cases. (a) two_backends_fewest_crossings_beats_priority: backends cpu(0), gpu(1). s forced gpu, feeding x with candidates cpu and gpu, feeding t forced gpu. x=gpu costs 0 and x=cpu costs 2; expect gpu. (b) tie_goes_to_priority: s forced cpu, feeds x with candidates cpu and gpu, feeds y forced gpu. x=cpu and x=gpu both cost 1; expect cpu. (c) three_backends_exact: cpu(0), gpu(1), npu(2). s forced cpu, feeds x in {cpu,gpu,npu}, feeds y in {gpu,npu}, feeds t forced npu. Costs of (x,y): (cpu,gpu)=2, (cpu,npu)=1 rank 2, (gpu,gpu)=2, (gpu,npu)=2, (npu,gpu)=3, (npu,npu)=1 rank 4. Expect (cpu,npu). (d) fanout_counts_pairs_not_edges: s forced cpu feeds p in {cpu,gpu}; p.out feeds c1 and c2, both forced gpu. p=cpu costs 1 (one pair), p=gpu costs 1 (the s to p pair). Tie, expect cpu. Per-edge counting would pick gpu. (e) fanout_to_two_other_backends_costs_two: s forced cpu, out feeds c1 forced gpu and c2 forced npu; cost 2 under any choice, no free node. (f) no_candidates_lists_bodies; (g) forced_unavailable_names_forced_backend; (h) host_bridge_edges_count_as_crossings. b7_assign_props.rs: a deterministic xorshift generator with a fixed seed; 2,000 random graphs with up to 8 nodes, up to 4 backends, random candidate sets and forced nodes, DAG edges and up to 2 output ports per node. For each, the search result must equal enumerating every candidate product and taking the minimum (crossings, rank_sum, then rank vector in index order). chain_of_200_free_nodes_uses_at_most_4n_plus_8_expansions (a deterministic count, not a timing). dense_component_over_budget_is_assignment_budget (budget overridden to 10 on a 12-node dense component).

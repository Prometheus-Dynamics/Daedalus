# J8: A worker's backoff is not a second fault, and its environment can be cut down

- No dev file.

## Build

- A run for a worker that is backing off was a fault, "worker … is backing off". That made one failure two or more, and stopped a host that stops on faults while it was only waiting. The failure rule is that a failed part is tried again after a capped wait, with nothing sleeping on the tick: so the run during the wait is skipped, with the reason, and is no fault.
- A worker the host killed itself, at a deadline or after a cancel it didn't answer, was counted as a failure of the worker and backed off. Nothing says its next start would fail. It is started again by the next run.
- `WorkerSpec` could add to a worker's environment and nothing else. It can now clear it, remove one variable, and set the directory the worker starts in.

## Proof

`backends/process/tests/supervision.rs`: after a worker exits mid-run, the next run is `Skipped` with "backing off" and the fault count hasn't moved, and the run after the wait succeeds. A worker that hangs is killed at its deadline, and the run straight after starts a new worker, which is killed in its turn: two different pids. A shell started as a worker writes its environment: inherited by default, empty but for the spec's own variables after `env_clear`, missing one variable after `env_remove`, and a variable both removed and set is set.

## Status

Done.

- `ensure_up` says why a link is not up: `NotUp::BackingOff` (skipped) or `NotUp::Start` (the worker was started and didn't come up, which is a fault).
- A fault's effect on the link is one of three: nobody's (the link stays), the worker's (killed, backoff), the host's (killed, next start at once and the failure count untouched).
- `WorkerSpec` has `env_clear()`, `env_remove(key)` and `cwd(path)`. What the spec sets is applied after what it takes away. `same_as` compares the new fields.

## Build

- Crate daedalus-client in core/client. Connects over a unix socket (default) or TCP loopback. Runs the H1 hello.
- Typed methods, one per H1 op. Pipelined requests are matched by id.
- Watch returns a stream of events; the stream ends on ended or on disconnect.
- Reconnect: a capped backoff of 8 s that never stops on its own while the client is asked to keep trying. Watches are resubscribed after reconnect.
- Delivery rule: while disconnected, calls fail with disconnected. A request whose delivery is unknown is never resent, unless it is idempotent (ping, inspect, trace, cache inspect). Others return unknown_delivery.
- Dev's CLI sent one request over TCP per command; that becomes a thin use of this client in H5.

## Proof

cargo test -p daedalus-client against an in-test server that speaks H1 framing. Reconnect after the server is killed uses the 8 s cap (fake clock). A non-idempotent request in flight during a disconnect returns unknown_delivery and is not resent.

## Status

Done. `core/client` (daedalus-client) connects over a unix socket or loopback TCP, runs the H1 hello, has one typed method per op, pipelines requests, gives a watch as a stream, and reconnects. `cargo test -p daedalus-client` passes: ten tests against a server written in the test that speaks the H1 framing.

Differences from the brief:

- **Threads, not async.** The client is blocking and uses one reader thread per connection. `Client::send` returns a `Pending` to wait on, so one thread can pipeline, and a `Client` is `Clone`, so several threads can call at once. Nothing in the workspace needs an async runtime for this.
- **Reconnecting is an option, off by default** (`Options::reconnecting()`). A command line tool wants the error and a long-lived client wants the retries. `Client::set_reconnect` turns it on or off by hand at any time.
- **A watch's stream ends on `ended`, or on a disconnect when the client is not reconnecting.** A reconnecting client subscribes each watch again and the same stream goes on. Events carry the watch's client-side number as `sub`, which does not change across reconnects. A watch whose run the server no longer has ends when the resubscription is refused.
- **Idempotent requests in flight at a disconnect** (ping, inspect, trace: `OpKind::idempotent`) are resent under their old id by a reconnecting client, and fail with `disconnected` otherwise. "Cache inspect" is `inspect {cache}` in H1, so it is covered. Every other request in flight returns `unknown_delivery` and is never resent. A request whose write fails is treated the same way.
- **The clock is a trait** (`Clock::sleep`), so the reconnect test runs on a fake one: it records the delays (250 ms doubling to 8 s, then 8 s each) and brings the server back during the ninth wait.
- **A server that refuses the connection** can answer the hello with an error response (H3 does this at its connection limit), which `connect` returns as `ClientError::Service`.
- **Loopback only.** `Endpoint::tcp` refuses an address that is not loopback. `Endpoint::Unix` exists on unix only.
- **The test server** uses TCP on a loopback port so the same tests run on Windows. One more test covers the unix socket endpoint, on unix.

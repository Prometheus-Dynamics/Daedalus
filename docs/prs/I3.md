## Build

- One benchmark that compares three ways of passing a frame along a chain: SharedFrame (F2), SharedBytes, and a plain Vec<u8>. dev's commit 36d2af6 has these three paths; the same shape carries over.
- The frame type comes from interfaces/frame (F1), not from core. The benchmark is a consumer of the frame interface, so it lives in testing/ and not in core/.
- Each path runs the same chain of N stages (N set by the benchmark). The chain is built once; the measured part is the steady-state tick.
- Counts per frame: instructions (through the I2 harness), and allocations. SharedFrame and SharedBytes must allocate zero per frame in steady state. Vec<u8> is expected to allocate, and the count is recorded as the contrast.
- Criterion timings are kept for board runs only. The criterion harness is not a CI gate.
- Drop the frame_access and shared_preprocessing tests as separate files; their assertions (view access, shared preprocessing output equal to the CPU path) go into the benchmark's own test file.

## Proof

scripts/ci.sh budgets (the I2 fragment) includes the frame-path rows: instructions per frame for SharedFrame, and zero steady-state allocations for SharedFrame and SharedBytes. Tests named shared_frame_steady_state_allocates_nothing, shared_bytes_steady_state_allocates_nothing, vec_path_allocates_per_frame (asserts the contrast is real), and shared_preprocessing_matches_cpu_path.

## Build

- The data-parallel ops of the kernels library, on GPU-resident storage: RGB, RGBA and gray layouts, LE f32, binary16 to f32, f32 to unorm8, byte copies, hex and base64 encode and decode (decode reports the decoded length and invalid input), and chunked CRC32. D8 holds the CPU reference.
- Per-pixel ops (rgb_to_rgba, rgba_to_rgb, gray_to_rgba, f32_to_unorm8 and the like) are declared as pixel bodies (`wgpu(pixel)`), so E6 can merge them. The others are whole-shader bodies.
- The kernels are library functions, not nodes (design: kernels are not nodes). A node calls them in its body or region.
- Copy engine: `copy_with_engine` stays as an op, with the copy command, not as a special path.
- Bit-exact against D8's reference for every op, as dev's kernels tests check.
- Dropped: dev's FRAGMENT_WIDTH constant path. Per-pixel ops reach the fragment form through E6, so this PR keeps one path per op.

## Proof

CI, lavapipe: pixel_kernels_match_the_references, float_kernels_match_the_references, copy_and_codec_kernels_match_the_references, gpu_base64_decode_reports_length_and_errors, copy_engine_copies_gpu_resident_bytes, gpu_crc32_matches_the_reference (all ported). New: a chain of rgb_to_rgba then f32_to_unorm8 merges into one shader (E6's counter reads 1).

Written to `testing/board-runs/E16.md` and run later by a local session:

CM5 (V3D): each op at 4 MiB against the CPU reference. Dev's backend matrix records the RTX numbers (0.005-0.2 ms on GPU against 0.2-10 ms on CPU); measure the CM5 figures fresh and record them.

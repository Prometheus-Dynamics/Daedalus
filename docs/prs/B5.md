## Build

- One rewrite hook. A rewrite has an id, a version, and apply(graph, cx) returning the list of applied rewrites or an error. Rewrites are held in config as an ordered list of shared trait objects.
- Position: after defaults and before hydrate, using the slot B1 left. Rewrites run in the order the config gives. Hydrate runs after them, so a rewrite that adds an unknown node id fails hydrate.
- No global registry, no register function, no scoped registry type. Dev's after-convert lowering phase is dropped: the design has one rewrite point, and conversions (B4) are inserted by the solver itself.
- Applied rewrites record the rewrite id, a summary, and whether the graph changed. B11 explains them.
- The rewrite id and version feed the plan hash (B12).

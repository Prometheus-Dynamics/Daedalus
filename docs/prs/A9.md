## Build

- Crate daedalus-macros (proc-macro). It names no backend. The only backend name it knows is the default body path ::daedalus::cpu, a path it writes and never looks inside. Derives are not here (A13).
- Grammar of #[node(...)] on a fn or a const: id = "..." (a literal or a const expression); summary = "..."; description = "..."; inputs(...) and outputs(...) with bare names or port(name = .., ty = .., type_key = .., source = .., default = .., label = .., unit = .., group = .., advanced = .., description = ..); inputs(config = Ty); fire = "any" | "all"; reusable; state(T); generics(T, instance(Ty, "suffix"), ...); backend = P or backend = P(args). Anything else is an error with a span: unsupported #[node] argument.
- Feature map, and where each dev feature lands. Lands in this PR: id, summary, description, inputs and outputs with port metadata, optional inputs (Option parameters), conditional outputs (Option returns), FanIn<T> inputs, config types, fire (stored; C4 runs it), reusable (stored; C8 runs it), state(T) (stored as StateDecl; C9 allocates), generics (instances, below), the backend slot. Replaced: fallback (a node's second body under the same id, A8). Dropped: capability (a body's needs), device_from (backend args, E1/E4), shareable (open question), same_payload (B9's identity step), sync_groups (descriptive on dev), the low-level NodeIo handler form (typed functions only), node_handler (one macro only), NodeExecutionKind host_bridge, external and no_op. Retry and auto-off are not attributes: failure policy is host policy (C5), capped at 8 s.
- Emitted items for fn NAME with backend P(args) (default P = ::daedalus::cpu): (a) the fn itself, unchanged; (b) pub const NAME_DECL: NodeDecl = NodeDecl { id, at: SourceAt(concat!(file!(), ":", line!())), ... } built from the attribute, with each parameter's TypeRef::Key(<T as Typed>::KEY); a shader port has TypeRef::Body; (c) pub const NAME_NODE: NodeRecord = NodeRecord { decl: &NAME_DECL, body: P::__daedalus_body!( ... ) }. The body call is an expression macro that the backend's authoring crate exports. The core macro never parses args: it passes them through as tokens.
- The body macro contract: P::__daedalus_body! receives a fixed header (kind = fn | const, name = NAME, args = ( .. ), params = ( name: Type, .. ), ret = Type, plus the generated decl path) and must expand to an expression of type BodyRecord that is const-evaluable. It may open a block with items inside, for example a generated adapter fn, and return BodyRecord { backend: "cpu", ... } at the end. The authoring crate for CPU (D1) and for wgpu (E4) each provide one. A const body (a shader source) gets no params; its ports come from the body (TypeRef::Body in the decl, A8 fills them).
- Records and collection on a heap-free target: no inventory, linkme or ctor. Each record is a const in the module that declares the node. A list is a const slice of references, written by hand: pub const NODES: &[&NodeRecord] = &[&track::TRACK_NODE, &blur::BLUR_NODE];. The host passes NODES to Registry::register_all (A8). Firmware generation (D5) reads the same slice at build time. A proc-macro crate can export only proc macros, so no list macro lives here; the facade (C14) may add one later. The reason for explicit lists: linker-section collection needs ctors or linker support that MCU and wasm targets lack, and it hides what a build links. An explicit list is deterministic and visible.
- backend = P(args) expansion, in one line: the attribute copies P and args into the body call unchanged, so P(args) resolves in the caller's scope. A backend therefore needs no change in this macro, and a new backend needs no change here. Errors if P does not resolve show the path as written.
- Generics: generics(T, instance(u32, "u32"), instance(Frame, "frame")) emits one NAME_<SUFFIX>_DECL and NAME_<SUFFIX>_NODE per instance, with id "<id>.<suffix>" and T substituted in the signature. A generic fn with no instance list is an error. The instance ids are the registry ids, so they are visible in graphs.
- Const checks, all compile errors with spans: id charset (A4's const check), duplicate port names, a state type that is not Default + Send + 'static (checked with a const fn bound), reusable together with state or with a non-pure body (dev's rule), a Result error type that is not Display (faults print through StepCx), and a bad fire value.
- Config and const ports: the attribute declares a config type as inputs(config = Ty). A13's NodeConfig derive provides Ty's FIELDS. The macro only records the reference: field validation and const resolution are B3.
- Fixture authoring crate testing/crates/author-fixture: a tiny backend body macro (no runtime) used by the tests, so A9 can be tested without D1.
- Settled: `#[node(conversion)]` declares a user type conversion, replacing dev's `#[adapt]`. `#[node(shareable)]` is kept.

## Proof

trybuild compile-pass tests for: a plain fn node, a const body through the fixture backend, generics with instances, fire and reusable, state(T), NODES with two nodes. trybuild compile-fail tests for: an invalid id (const panic message), duplicate port, state type without Default, reusable with state, a Result error type without Display, an unknown argument, a missing backend path. A fixture expands with #[node] and builds for thumbv7em-none-eabihf with --no-default-features, proving the expansion needs no alloc.

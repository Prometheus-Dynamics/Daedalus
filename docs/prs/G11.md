## Build

- Two crates. daedalus-capi-sys loads the library with libloading and holds the typed function table. It is the only crate with unsafe. The gate must allow it.
- daedalus-capi-rust is safe Rust with #![forbid(unsafe_code)]. Surface::load checks the version and layout hash. Host and Graph own their handles and release them on drop. Ports by name or index; typed push and take; HostError maps every status code.
- Dropped: frame.rs (dma-buf frames), the in-image shared-mode test shared_in_image.rs, the static-versus-shared allocation comparison (tests/support/compare.rs, tests/frames.rs), the SURFACE_ABI pin (the wrapper pins 1.2 while the surface reports 1.3), and tests/support/cdylib.rs (replaced by a build step in CI).

## Proof

cargo test -p daedalus-capi-rust with daedalus-capi built first. wrapper_contract: load the cdylib, run a graph, typed errors, optional takes, drop releases the host, busy while graphs live. The safe crate's build proves forbid(unsafe_code).

## Status

Done. Two crates: `languages/rust-capi-sys` (daedalus-capi-sys) loads the surface's shared library with libloading and holds the typed table of its 33 functions, and `languages/rust-capi` (daedalus-capi-rust) is the safe host over it, with `#![forbid(unsafe_code)]`. Its contract test loads the real library, installs the plugin fixture and runs a graph. Run here on Linux.

As built:

- **The sys crate is where a call is made safe, not only where the table is.** A crate that forbids `unsafe` can't call a C function pointer at all, so `daedalus-capi-sys::Api` has one safe method a call: it passes the pointers and lengths the header asks for, makes the two calls a text or bytes result takes, and copies a port's strings out of the graph. Statuses pass through as their numbers.
- `Surface::load` refuses a library whose major version or layout hash isn't the one this crate was built against, which it takes from `daedalus-abi`. `load_expecting` checks against a version the caller gives. A file that isn't the surface is refused for the function it lacks.
- **A host goes when its last graph does.** Each `Graph` keeps a share of its host's handle, since the library won't release a host with graphs. Dropping a `Host` first is fine: the graphs keep working, and the host is released after the last of them. `Host::release` releases now and gives the host back with `HostError::Busy` while graphs live.
- `HostError` has a variant for each of the surface's statuses, with the library's reason on the ones that have one, plus `Library` and `Version` for loading. A status this crate doesn't know is `Unknown` with its number and the library's name for it.
- `graph.push(port, value)` and `graph.take::<T>(port)` take a port by name or by `PortIndex`, and any of `i8` to `u64`, `f32`, `f64`, `bool` and `Vec<u8>`. An integer goes through the surface's 64-bit integer, and a number that doesn't fit, either way, is `OutOfRange`. A take is `Option`.

Differences from the brief:

- The contract test builds nothing itself: the surface is a dev-dependency, so cargo builds its shared library beside the test, and the test loads that file. There is no separate CI build step.
- The linked copy of the surface (the dev-dependency) and the loaded one are two copies with their own tables. The test uses only the loaded one, and says so where it checks nothing is left behind.
- Only `u32` values run end to end, as in G10, since that is the fixture's node.
- Not run on Windows or macOS. Both crates lint clean for `x86_64-pc-windows-gnu`.

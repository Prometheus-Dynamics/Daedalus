## Build

- Runner counters are a fixed struct: steps called, skipped, faults, backoff skips, deferrals, pending fences, cancelled, and per-step call counts in arrays sized at load. Incrementing never allocates.
- Levels on the host: Off, Basic, Detailed, Trace (dev names). Dev Timing becomes Detailed. Dev Hardware is std, Linux only, and holds per-node perf counters (perf.rs). Dev Profile moves to C24. Trace holds lifecycle events, host side only.
- Per-step timing reads the clock the host passes in. The runner never reads a clock itself.
- Tracing: the tracing crate is used host side only, behind the tracing feature. The runner has no spans in the tick path.
- Report: TickReport (in the tick) and an ExecutionReport on the host with a table and a JSON form (alloc, host side).
- Event log (dev host_bridge/events.rs): bounded recent events with an on/off switch and a limit. It lives here, not in the runner.
- Edge metrics: occupancy and drops per edge, filled by C15.
- Size guard: a test that the runner's telemetry struct size stays fixed (dev telemetry_size.rs).

## Proof

Port telemetry_tests.rs and the parallel telemetry merge test (parallel_ticks_merge_to_the_serial_telemetry, with C6). The runner counters have a test: a fixed size, and the counts match the C1 tests. Zero allocations in the tick with Basic telemetry on.

## Build

- One crate, examples/04_gpu, with three binaries: fragment (a per-pixel function merged into one shader, E6), mixed (a CPU node, a GPU node and back, E3), and upload_download (the transfer round trip, E3).
- Each binary computes its result on the CPU too and checks the GPU output against it. Replaces dev's 07_gpu.
- The examples use the facade and the GPU backend only. No backend-specific API beyond the authoring macro (E4).
- Runs on lavapipe in GitHub CI. A missing adapter is an error, not a skip.

## Proof

scripts/ci.sh smoke (I4's fragment) runs the three binaries on lavapipe. Tests named fragment_matches_cpu, mixed_round_trip_matches_cpu and upload_download_round_trip; each fails when the GPU output differs from the CPU output, and a missing adapter fails the test.

## Status

Done. `examples/04_gpu` is one crate with the binaries `fragment`, `mixed` and `upload_download`, each a line of library code behind it and a test with its golden line. Run here on hardware (RADV) and on lavapipe.

As built:

- **fragment:** three per-pixel nodes, each a WGSL `fn apply`, in a line between a host input and a host output. The example reads the device's pass counter around the run and fails unless the three ran as one pass. The answer is checked against the same three functions on the CPU.
- **mixed:** a CPU node that makes the numbers, a shader node that scales them, a CPU node that sums them. Nothing in the nodes says where memory is: the planner puts the upload and the readback in.
- **upload_download:** the host feeds words, one shader node squares them, the host takes them back.
- The value all three pass around is the example's own `Words`, with `HostBytes` written for it: two functions.

Differences from the brief:

- **This PR found that no graph could reach a shader node from the host or from a CPU node**, and `E3-typed` (#130) fixed it first: see "Added after" in `docs/prs/E3.md`.
- **The examples name more than the facade and the authoring macro.** They call `WgpuBackend::open(..).with_bytes::<Words>()`, implement `daedalus_wgpu::HostBytes`, and `fragment` reads `shader_stats` to show the merge. The manifest lists the GPU backend, its authoring crate, the registry and the types crate, which the macro's output names. The facade test's rule now allows `use daedalus_wgpu::` in examples, as it does the CPU backend.
- **They run in the GPU lane, not in `scripts/ci.sh smoke`.** The gate's runner has no GPU. `scripts/gpu-lavapipe.sh` runs the three binaries and the crate's tests on lavapipe.
- **A missing adapter is an error for the binaries always, and for the tests where `DAEDALUS_GPU_REQUIRED` is set**, which the lane does. Elsewhere the tests skip, as every GPU test here does, so the workspace's tests pass on a machine with no GPU.
- **The host ticks until the answer arrives.** A tick ends when a step is waiting on the device, and the host has no call that waits for one, so `when_ready` steps, sleeps 200 µs and steps again, for at most 10 s.
- The "fragment" example is the compute form of a merged chain: the values are buffers. The fragment form runs when a chain is given a texture (E15), which a host port can't feed yet.
- Status (element-wise rename): the merged form is now called element-wise. Where this brief says `wgpu(pixel)` the macro form is `daedalus_wgpu_author(element, ..)`; `pixel.rs` is `backends/wgpu-author/src/element.rs`; `PixelSpec` is `ElementSpec`. The 04_gpu example's `fragment` binary is `element`.

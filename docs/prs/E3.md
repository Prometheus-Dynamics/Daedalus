## Build

- Transfer entries offered to the planner (A7 Transfer): host to device (upload), device to host (readback), and the host-cached and host-mapped spaces from E2. Each entry has a fixed cost class, so planning never measures a device.
- A transfer is a planned edge. Dev's rule that a transfer inside a handler is invisible to the plan (gpu-nodes.md, Transfers as plan edges) is gone: no node body copies data across a space.
- Upload: `write` takes CPU bytes into a storage or texture. Wgpu's queue writes flush with the next submit, so the region flushes uploads before it encodes. Raw submits (E7) see upload data only after the same flush.
- Readback: the producing region copies its outputs into a pooled staging buffer in the same encoder. The copy completes through a fence (E8). The Step never blocks to read. `read_into` (blocking) is for setup and tests only.
- TransferStats (dev buffer.rs) counts uploads and downloads in bytes and in count. Tests read these counters to prove where transfers happened, so the counters stay.
- Dropped: the row-by-row re-pitch upload (dev texture_transfer.rs, 21 ms at 640x480 on V3D) is not carried. E15 replaces it for camera frames with the fold path, and nothing else needs it.

## Proof

CI, lavapipe: integer_formats_round_trip_exactly (ported; each texture format round-trips bit-exact), gpu_storage_reads_back_into_caller_buffers, and a planner-level test on the sim backend (A11) with two spaces: a CPU producer feeding a GPU consumer gets exactly one upload entry, and a GPU producer feeding a CPU consumer gets exactly one readback entry. The test fails if either is zero or two. Mock rejects_unaligned_row_pitch stays.

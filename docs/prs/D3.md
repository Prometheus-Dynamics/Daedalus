## Build

- Writer (std, in blob.rs): a CPU region becomes Compiled::Blob bytes in the A10 encoding. The blob names each node by its body index in the firmware's library and gives each edge inside the region a slot index local to the blob (D0: boundary ports are named in UnitInfo, and the plan's slot table connects them). It holds constants, parameters and host ports (by name hash). It holds no code addresses. Output is deterministic: the same graph and library give the same bytes.
- Library (blob/library.rs): the firmware's body table, generated from the bodies it links (D1 macro output). Each entry has a type-erased Step wrapper, its state size and alignment, and its port type keys. The library hash covers interfaces only (ids, port names, type keys, optional inputs, fire mode), not code.
- Runner (blob/runner.rs, no_std, no allocator): Interpreter over a caller-given arena of fixed const size. load(blob) validates the whole blob first (magic, version, CRC, library hash, entries, input counts, types, edges, parameters, host ports, arena size), without touching the running plan. Only then is the new plan laid out in the arena. A load swaps at a tick boundary. On error the running plan keeps running. required(library, blob) gives the arena size a blob needs.
- LoadError: a small Copy enum with Version, Checksum, Library, Node, Input, Edge, Type, Param, Port, Arena { needed } and Malformed, as in dev. No formatting.
- CRC: a bitwise CRC-32 in core/plan (A10). The device uses no table, which keeps flash small. The host writer uses the same function, so its bytes match whatever a host CRC produces.
- Chunked receive (feature receive): BlobReceiver writes CRC-checked chunks in order into a BlobSink (a byte buffer or the application's flash partition, contiguous writes only). It returns Progress::Complete or Partial, and ReceiveError::Gap { resend_from } for a missing range. The packet layout (15 bytes of overhead) is kept.
- Limits: port values are Copy and node states have no drop glue (checked at compile time). At most 256 nodes, at most 8 ports per node. Constants and parameters are scalars.
- Dropped: the standalone daedalus-mcu binary (plan and param commands, replaced by the B13 plan API and the D6 host function), the McuPlan intermediate (B9 stitch output replaces it), the JSON manifests (A10 schema replaces them), and the blob version history (A10 owns the version byte).

## Proof

Ports of dev's tests: loaded/tests.rs (fan_in_takes_the_first_edge_with_a_value_and_drops_the_rest, rejects_blobs_the_fan_in_and_adapter_rules_forbid), receive_tests.rs (a_blob_received_in_chunks_loads_and_runs, a_flash_sink_gets_contiguous_writes_and_too_large_blobs_are_refused), build tests blobs_are_deterministic_and_name_their_library and rejects_invalid_parameters. Load and tick make zero heap allocations (counting allocator). cargo check -p daedalus-cpu --target thumbv6m-none-eabi --no-default-features --features blob,receive.

## Status

Merged. As built, where it differs from the brief:

- The writer is `blob/write.rs`. `BlobBackend { library }` is the CPU backend storing regions, and `Planned::blob()` returns a region's bytes when they are a whole plan of their own. A graph that splits into more than one region is refused, so a blob holds one connected graph.
- The A10 format gained an `extra` word section for the blob's own tables, and a plan ends in its CRC-32 after the sections.
- Steps live in `daedalus_runner::StepArena`, because `backends/cpu` has no `unsafe`. `#[node]` adds an `ArenaBody` to `CpuBody`, built on `Fresh`, and constants are written into a step's input cells.
- A body that can't live in the arena (a port that isn't a `Copy` value of at most 16 bytes, a state with something to drop, a config) has no `ArenaBody`. That is found while planning on the host and at load, not at compile time, because a record's payload is a `dyn Any` that a `const` can't read. D5 can add a compile-time check where a firmware names its library.
- No widening at an edge: the planner already adds a conversion node. A type mismatch is `LoadError::Type`.
- Parameters are in the format and checked at load. Marking them is D6.
- New planner and backend inputs: `NodeBody::id`, `CompileCx::{host_inputs, host_outputs, fifo_capacity}`, `InnerEdge::policy`, `Config::fifo_capacity` (default 4).
- `#[node]` still expands `__make`, which needs the heap. D5 makes that expansion conditional for firmware with no allocator. `daedalus-cpu` itself builds on `thumbv6m-none-eabi` with `blob,receive` and no default features.

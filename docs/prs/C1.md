## Build

- Crate daedalus-runner at core/runner: #![no_std], no extern crate alloc, no dependency on the planner, registry, host or any backend. It depends only on daedalus-abi (Step, StepEnd, StepCx), daedalus-value (Slots and its pool) and daedalus-plan (the step list). unsafe only around the Step.run call, each block with a SAFETY comment.
- Plan input (A10): steps as a slice of Step in topological order, plus a meta record per step: wake (range into a flat table of consumer step indices), inputs and outputs (ranges of slot indices), always (bool), may_pend (bool). Load fails if a wake target does not have a higher index than its producer, or if any slot index is out of range. Load may allocate; the tick may not.
- Runner state: plan, slots (&mut Slots from A5), dirty and carry (Bits: fixed u32 words, ceil(steps/32) long, sized at load), always (Bits, precomputed in the plan), tick (u32, wrapping). No field grows during a tick.
- Tick, exactly: (1) tick += 1. (2) dirty |= always, one OR per word. (3) If every dirty word is zero and no fence is registered (C2), return Idle. That is the whole idle path. (4) Poll registered fences (C2). (5) For each word w: loop { bits = dirty[w]; if bits == 0, break; i = 32*w + trailing_zeros(bits); clear bit i; step_once(i) }. dirty[w] is re-read after every step, so consumers woken by this tick run in this tick. (6) OR carry into dirty, clear carry, return Ran with the call and fault counts.
- step_once(i): an inactive step (C18) is skipped and wakes nothing. A step whose joins are not ready (C4) is not called and its inputs stay queued. A step whose blocking outputs are full (C16) is not called and goes to carry. A step that is disabled or backed off (C5) has its inputs committed and is not called. Otherwise call end = (step.run)(step.data, slots, cx).
- Outcome: Done commits the inputs and wakes every index in meta.wake. Skipped commits the inputs and wakes nothing. Pending(f) commits the inputs, registers (step, f) (C2) and wakes nothing. Fault goes to C5: retry in this tick with inputs kept, or commit and wake nothing.
- Slot handling: a slot is a ring of fixed capacity holding values with an unconsumed count (A5). A body reads an input by reference (peek) and writes an output with push, which returns Stored, Dropped or Full. Bodies never pop. The runner commits after the call: a FIFO slot pops one value, a LATEST slot clears its unconsumed flag and keeps the value, a HELD slot pops nothing (C4). The runner never copies a value.
- Pool: Slots owns the recycle pool (A5). The loader sizes it at load to the sum of slot capacities, plus host input capacity, plus one per step output. A body that cannot get a value returns Fault with PoolExhausted. A valid plan does not reach that.
- Errors: RunError is a plain enum with no strings (LoadError kinds, Fault{step}, Cancelled, Overflow). Text goes through StepCx (C12).
- Time: the runner never reads a clock. Backoff (C5) reads the clock the host passes in StepCx, and only for a backed-off step.
- Tests in core/runner/tests/tick.rs use plain Rust functions as step bodies, not a real backend (A11 is not needed). Cover: FIFO order over three ticks; LATEST keeps its last value; an idle tick calls zero steps; a 16-step chain fed once calls exactly 16 steps and drains; a Fault with Retry keeps its inputs; a back edge is rejected at load.
- core/runner/tests/no_alloc.rs installs a counting global allocator and runs 10,000 warm ticks with zero allocations.
- Cross build with cargo build -p daedalus-runner for thumbv7em-none-eabihf and riscv32imac-unknown-none-elf. cargo tree shows no alloc feature.
- Why the budget is beaten: dev does per node, every tick, an active check, a join check, an admit, a collect of pooled inputs, an Arc clone of consts, a NodeIo build, a reuse check, span guards, telemetry branches and a publish. The new loop does none of that for an idle step: an idle 16-step plan costs one OR per word and one zero test. An active step costs one indirect call, its pops and its wakes. A merged region (D2) turns a chain into one call.
- Lines kept out of the runner: no tracing spans, no per-node perf sampling, no thread CPU time (all in C11, host side or std). Do not carry NodeHandler, the handler registry or NodeIo.
- Settled: the runner does no reference counting of its own on a value with one consumer. The plan says who owns what.
- Settled: the crate is marked `heap_free = true`. A5 provides the slot ring (peek, push, pop) and A3 the raw `Slots`. Joins (C4), backpressure (C16), inactive (C18) and backoff (C5) add themselves to `step_once` in their own PRs: C1 runs every step whose inputs are ready, and handles `Done`, `Skipped`, `Pending` and `Fault`. C1 defines its own meta records (`wake`, `always`, `may_pend`) next to the runner, built from A10's step list.

## Proof

CI proof (counters, not instructions): on a 16-step plan an idle tick reports step_calls == 0 and word_reads <= ceil(steps/32) + 1. A fed chain reports step_calls == 16. Zero allocations over 10,000 warm ticks. The back-edge load error and the cross build pass. Instruction counts are not in CI (no perf counters); the x86 count belongs to I2.

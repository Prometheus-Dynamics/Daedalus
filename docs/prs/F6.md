## Build

- CPU conversions with the same definitions as the GPU kernels (E16) and D8's reference: RGB to RGBA and back, gray to RGBA, LE f32, binary16 to f32, f32 to unorm8, and a frame layout to packed RGBA8.
- Each conversion is either a transfer entry (A7) or a conversion node the planner can insert (B4). A conversion between two frame layouts is one or the other, not both.
- Bayer and compressed frames are refused by every conversion.
- YCbCr (NV12 and YU12) to RGB is not on dev, though dev's docs describe it. This PR does not build it. The owner decides whether it is wanted (see report). NV12 stays sample-only on the GPU (E14).
- Dropped: dynamic_to_rgba8 and the image-crate DynamicImage input. Core and the frame interface do not depend on the image crate. Dropped: the Compute<DynamicImage> wrappers.

## Proof

CI, pure: each conversion matches its scalar reference bit-exact (ported from kernels_tests.rs's pixel and float references). Bayer and compressed inputs are refused with a typed error (new). A planning test (B4 with the sim backend): a CPU producer of RGB feeding a consumer of RGBA gets exactly one conversion node.

## Build

- Binary daedalus-ctl, in service/daedalus-ctl. It uses the H2 client.
- Commands: ping; load-plugin; put-graph FILE; patch-graph; plan; start; feed; step; take; watch; reload; cancel; stop; inspect; trace; cache inspect and cache clear.
- Mapping from dev: inspect-state and inspect-latest become inspect; inspect-cache and clear-cache become cache; export-trace becomes trace; put-registry is dropped (plugins are loaded, not registered as JSON); build becomes plan with a form option; inspect-plan becomes plan with inspect.
- Output is text by default and --json for scripts. The JSON is for this CLI only; it is not the wire.
- Exit codes: 0 success, 1 daemon error, 2 usage error, 3 could not connect.

## Proof

cargo test -p daedalus-ctl --test ctl against a daedalusd started in the test with dylib-fixtures. Each command's exit code is tested. --json output has a fixed schema test.

## Status

Done. `service/daedalus-ctl` is the command line client. `cargo test -p daedalus-ctl --test ctl` passes: four tests, three of them against a `daedalusd` the test starts with the dylib fixture loaded.

As built:

- **Invocation:** `daedalus-ctl [--socket PATH | --tcp ADDRESS] [--session NAME] [--json] COMMAND ...`. With neither flag it uses the daemon's default socket: `$XDG_RUNTIME_DIR/daedalusd/daedalusd.sock` if that exists, else `/run/daedalusd/daedalusd.sock`.
- **Commands:** `ping`, `load-plugin PATH`, `put-graph NAME FILE`, `patch-graph GRAPH FILE`, `plan GRAPH [--form] [--inspect] [--priority]`, `start GRAPH [--fifo] [--fault-reports] [--telemetry] [--unmerged] [--priority]`, `feed RUN PORT TYPE:VALUE`, `step RUN [COUNT]`, `take RUN PORT`, `watch RUN|all [--kinds] [--count]`, `reload RUN GRAPH`, `cancel RUN`, `stop RUN [--immediate]`, `inspect run RUN | graph NAME | telemetry RUN | host`, `trace [LIMIT]`, `cache inspect | clear`.
- **Output.** Each command's result is one JSON object with a fixed set of keys. `--json` prints it in an envelope, `{"ok": true, "command": .., "result": ..}`, or `{"ok": false, "command": .., "error": {"kind": .., ..}}` on stdout for a failure. Without `--json` the same object is printed as indented `key: value` lines, keys in alphabetical order, and a failure is one `daedalus-ctl: <code>: <message>` line on stderr with a planner's diagnostics under it. `watch` prints one object a line in JSON and one paragraph an event in text.
- **Exit codes:** 0 success; 1 the daemon refused, or the connection failed after it was made; 2 usage error, which includes a file the command names that cannot be read; 3 could not connect.

Differences from the brief:

- **`feed` takes scalars only**, written `TYPE:VALUE` (`u32:5`, `f64:1.5`, `bool:true`, `string:hello`, `bytes:00ff`, `unit`). The daemon has codecs for scalars only, so nothing else could be fed.
- **`inspect host`** is the fifth inspect target H1 added, and is what dev's `inspect-state` became.
- **`plan --form blob` and `--form source`** are sent as asked. The daemon's backends are plugins, which produce steps only, so against `daedalusd` they answer `planning_failed`. The test asserts that for `source`.
- **A `u64` hash** is printed as hex text, since JSON numbers lose it past 2^53.
- **The daemon binary for the tests** is built by a nested `cargo build -p daedalusd` into a directory of this package's own under `CARGO_TARGET_TMPDIR`, because cargo gives a test only its own package's binaries. The fixture is built the same way. Each is built once per test binary, with no time limit on the build.
- **On Windows** only the usage and cannot-connect test runs: the others need the daemon on a unix socket. Windows was checked with clippy for the gnu target, not run.

## Build

- Today a parallel tick with `fail_fast` stops taking new steps when one fails, but a body already running goes on to its end, and nothing tells it to stop.
- When a step stops the tick with an error in `tick_parallel`, the runner raises the host's cancel word for the rest of that tick. Running bodies that check `cx.cancelled()` return early. The word is cleared again before the tick returns, if the tick raised it, so the host's next tick runs normally. A word the host had already raised is left as it was.
- Error choice in the lanes: a fault outranks the `Cancelled` it causes in other steps. Among errors of the same kind the lowest step still wins, as before.
- The serial runner is unchanged: nothing runs beside a step there.
- The `tick_parallel` doc comment changes: running steps may now stop early, and bodies that never check the flag still run to their end.

## Proof

`core/runner/tests/fail_fast.rs`, on two workers: a body waits until a second body has started, then faults with `fail_fast`. The second body spins until it sees the cancel, and the test checks that it did, that it returned before its deadline, that the tick returned `RunError::Fault` for the failing step, and that the host's cancel word is clear afterwards. A second case checks that a cancel the host raised before the tick is left set.

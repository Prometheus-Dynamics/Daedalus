## Build

- accel-matrix asm: disassembles every kernel symbol with rust-objdump and records whether it holds that ISA's vector instructions. Its ISA table keeps crc, pclmulqdq, zvbc and the others.
- accel-matrix render: writes docs/backend-matrix.md and .csv from the registry dump and the CI evidence, with the baseline gate. Cells are pass, fail, untested, gap, deferred or impossible, and totals count each.
- The gate fails on registry errors, failing cells, a source file with SIMD or GPU markers (core::arch, target_feature, asm!, multiversion!, WGSL, pipeline creation) that no kernel or exemption names, and on pass cells lost against the baseline. --release also fails on any gap, untested or deferred cell.
- The marker scan covers backends/kernels-sys and backends/cpu, not the old crates/ paths.
- Dropped: the fixed_function column and its RGA reasons; the GPU-impossible review switch stays as it is.
- scripts/accel.sh is kept, with the zigcc wrappers, and the accel subcommand in scripts/ci.sh calls it. The accel job in ci.yml is unchanged.

## Proof

cargo test -p daedalus-accel (testing/crates/accel) matrix tests: cells_need_evidence_and_rvv_needs_three_vector_lengths, wired_needs_every_call_site_to_call_the_kernel, marker_files_need_an_entry_or_an_exemption, vector_instructions_are_recognized_per_isa, core_tuned_variants_get_their_own_columns, extension_candidates_can_be_impossible_and_cells_deferred. A planted SIMD marker in a file that no kernel names makes the gate fail. A planted lost pass cell makes it fail. The render output is checked in CI by accel-matrix render --release on the CPU rows.
